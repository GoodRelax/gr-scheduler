## 3. シナリオ（操作の導線と思考の導線）

3 段に分ける。どの段で止めても「確かめた」と言える区切りにする。

### 段 1 —— 見る（10 分。Windows だけ）

| 手順 | 操作の導線 | 思考の導線（こう思ってほしい） |
|---|---|---|
| 1-1 | 05 の「サーバー連携トライアル」を読む。冒頭に 1 文:「GRS 本体はサーバーを持たない。これは、ファイルの置き場をサーバーに替えた**デモ版**」 | 「本体は単一 HTML のまま、置き場だけ替えられるのか」 |
| 1-2 | [zip をダウンロード] → 許可する → 展開 → `start-server.cmd` | 「インストール無しで立つのはいい」 |
| 1-3 | Windows の「証明書をインストールしますか?」に [はい] | 「localhost の自己署名か。本番では自分の証明書を使えばいい」 |
| 1-4 | 開く → Dummy Server → サンプルを選ぶ → 編集 → `Ctrl`＋`S` | 「**ローカルのファイルと同じ操作**でサーバーに保存された」 |
| 1-5 | 黒い窓のログに `GET /api/files/...`・`PUT /api/files/...` が流れる | 「**サーバーがやっているのはこの 3 つだけ**か」← ここが一番大事な気づき |

### 段 2 —— 自分のデータを置く（30 分。Windows だけ）

### 段 3 —— 自分のサーバーにつなぐ（半日。OS も言語も問わない）

| 手順 | 操作の導線 | 思考の導線 |
|---|---|---|
| 3-1 | 「サーバーの約束」1 枚（英語と日本語、言語に依らない）を読む: 3 つのエンドポイント、同じ起源、`GRS-Demo.html` を自分のサーバーから配る | 「CORS も設定も要らない。**ページと API を同じサーバーから出す**だけ」 |
| 3-2 | その 1 枚と自社の API を AI に渡し、「この約束どおりのサーバーを（自社の言語で）書いて」と頼む | 「PowerShell 版は**見本**で、うちは Node／Python／Java で書けばいい」 |

## 5. 決めてほしい方針

### D1 —— サーバー連携の「物語」をどちらにするか（最重要）

紹介頁 03 は「AI 向けと同じ API（Agent API）で連携」と言い、デモは「ファイルの置き場をサーバーに替える」で作った。受け取る人には 2 つの別の話に見える。

| 択 | 物語 | 合う相手 |
|---|---|---|
| **D1-A（推奨）2 段の物語にする** | 「① まずは**ファイル単位**（GET／PUT の 3 つだけ。このデモ）② 細かく同期したくなったら **Agent API**（変更を 1 件ずつ、AI と同じ道）」。03 の文はこの 2 段に直す | 段 3 のエンジニアは ① から入れる。② は将来の話として残る |
| D1-B ファイル単位だけを言う | 03 の「AI 向けと同じ API」を消す | 単純。ただし Agent API の強みを捨てる |
| D1-C Agent API で作り直す | デモを Agent API 経由に作り直す | 03 と揃うが、デモは大きく重くなる。「まずは動くもの」から遠い |

### D2 —— Windows 以外の人をどうするか

| 択 | 中身 |

| D2-B | 段 1 用に、Node.js 版の見本サーバーも zip に入れる（Node を入れている人向け） |
