## 2. 何が壊れていたか（**逐語**）

### #1 —— 規格は要素の間の空白を保存する。**`FR-021` は書き手が 2 人いる比較である**

`Canonical XML` の 2.1 節:

```
All whitespace within the root document element MUST be preserved
```

同 3.2 節の `Demonstrates`:

```
Retain all whitespace between consecutive start tags, clean or dirty
```

⛔ **`FR-021` が比べるのは「取り込んだ元のファイル」と「本ソフトウェアが書き出したファイル」である。**
**元の字下げは相手のもの、書き出す側の字下げは本ソフトウェアのものである。** ⭐ **規格は両方をそのまま保存する。**

### #2 —— 規格は接頭辞を書き換えない。**それは意図された設計である**

同 2.3 節:

```
The namespace prefix used in the QName MUST be the same one which appeared in the input document.
```

同 4.4 節の題:

```
No Namespace Prefix Rewriting
```

⚠️ **同節が挙げる理由は 1 つだけである** —— `an XPath expression in an attribute value or element content can reference a namespace prefix`。
⭐ **交換相手にはその型が 1 つも無い**（`mspdi_pj12.xsd` の実測）:

```
xsd:attribute の宣言                        0 件
xsd:anyAttribute                            0 件
xsd:QName / ID / IDREF / NOTATION / ENTITY  0 件
使われている単純型  boolean 77 / integer 59 / dateTime 50 / string 46 /
                    float 36 / duration 35 / decimal 26 / time 6
```

### #3 —— 揺れは 4 つではなく 5 つある

同 1.3 節が範囲外を明言している:

```
application-specific rules such as those governing unimportant whitespace and equivalent data
```

⛔ **文書は交換相手の値を型付きで持っている**（`docs/spec/_source/erd.json` の実測）:

```
列の出自   GRS 57 / Own 43 / Consume 19 / Carry 19
Own の型   文字列 12・日時 10・整数 9・真偽 6・日付 2・その他 4
```

⭐ **`Own` は「取り込んでそのまま書き戻す」ものだが、原形の文字列では持っていない。**
⛔ **書き出すときの綴りは本ソフトウェアが決めるので、`1` を `true` と書けば規格を当てても一致しない。**
⚠️ **原形のまま持ち回るのは `Carry` の 19 列だけである。**
