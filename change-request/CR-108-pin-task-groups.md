# CR-108 — タスクグループのピン止め表示

## 1. 変更概要

**行（`TaskGroup`）をピン止めし、縦にスクロールしても画面に出し続ける**要求を新設する（`FR-098`）。

ピン止めした行の **LOD の段階は他の行と揃える**（ピン止めを理由に描き続けない）。
件数の上限は**値**なので `_assets/tbl-settings.md` が持ち（`S-126`）、**要求は表の行を指すだけにする。**

**新設 1 件・表への追記 3 行。既存の要求は 1 つも書き換えない。**

## 2. 変更の背景・目的

**日程を拡大すると、確かめたい 2 つが同時に画面へ入らなくなる。**

> **利用者（2026-08-14）**: 日程を拡大してスクロールする際、**詳細を見たいタスクとマイルストーンや重要タスクとの連携**を確認しやすくするため。

`UC-007`（見たい範囲を出す）は拡張 `1a` で「修飾キーを押していない → 縦にスクロールする」と定めているが、
**スクロールしても見続けたい行を指定する手段が、ユースケースにも要求にも無い。**

**そして仕様書はこの概念をまだ 1 文字も持っていない** —— 「ピン」「固定表示」「追従表示」を
`01-04-requirements.md` / `05-07-design.md` / `08-10-test.md` / `A-appendix.md` /
`_assets/tbl-glossary.md` / `_assets/tbl-settings.md` の 6 ファイルで検索し、**全ファイル 0 件**であることを確かめた
（`grep -c` の結果が 6 ファイルとも `0`）。**既存の語と衝突しない。**

**目的** —— 「拡大したまま連携を読む」経路を作る。
⚠️ **ただし LOD を曲げて作らない。** ピン止めした行だけ深い段を描き続けると、
「手で畳んだときと自動で畳まれたときで絵が違ってはならない」という表 T-015 の `HR-1a` の規定が、
**ピン止めした行だけで破れる。** 本 CR は**その一貫性を守る側に倒す**（利用者判断）。

**利用者が本 CR で決めたこと（2026-08-14）** ——

| # | 決めたこと | 理由（利用者の言葉） |
|---|---|---|
| 1 | **最大 5 群までピン止めできる** | マイルストーン、こちらに依存する主要日程 2 群、こちらが依存する主要日程 2 群で最大 5 群 |
| 2 | **5 群で画面をはみ出す場合は縦スクロールで対応する** | —— |
| 3 | **LOD の段階が上がってピン止めからタスクグループが消えるのは許容する** | —— |
| 4 | **ピン止めの状態は `documentSettings` 側に保存する** | 版数を上げない。Fit で消えるため |

⚠️ **利用者原案の「表示階層」は仕様書の語ではない。** 正しくは **LOD の段階**であり、
拡大縮小で行が増減するのは **3 種のうちグループ LOD**（表 T-005a の `L-3`、駆動は縦の `zoomY`）である。
本 CR は全編でこの語に直してある。

### 5-1. 新規 `FR-098`（`FR-018` の Relations ブロックの直後に挿入する）

```markdown
#### ピン止めした行を画面に出し続ける

**Type**: FUNC_REQ
**UID**: FR-098

**STATEMENT**: 行（`TaskGroup`）がピン止めされている間、閲覧者が縦にスクロールしたとき、システムは、その行を画面に出し続けること。**ピン止めできる件数は `_assets/tbl-settings.md` の表 T-203 の `S-126` が持つ範囲に収めること（MUST）。**

**ORIGIN**: UC-007 手順 4 ／ 拡張 1a（縦にスクロールする経路は定めているのに、スクロールしても見続けたい行を指す手段がユースケースにも要求にも無かった）

**RATIONALE**: 日程を拡大して縦にスクロールすると、いま見ているタスクと、マイルストーンや主要な先行・後続とが同時に画面へ入らなくなる。**連携は両方が同時に見えていなければ確かめられない。**

⚠️ **ピン止めした行の LOD の段階を、他の行と変えてはならない（MUST NOT）** —— グループ LOD（表 T-005a の `L-3`）は縦の倍率だけで決まる。ピン止めを理由に深い段を描き続けると、**手で畳んだときと自動で畳まれたときで絵が違ってはならないという表 T-015 の `HR-1a` の規定が、ピン止めした行だけで破れる。**

**グループ LOD が上がって描かれなくなった行は、ピン止め表示からも消えること（MUST）。** 消えてもピン止めを解除しないこと（MUST NOT）—— 倍率を戻せばまた出る。**畳まれた `TaskGroup` の配下にある行も同じく描かないこと（MUST）** —— ピン止めを `HR-1a` の抜け道にしてはならない（MUST NOT）。

**ピン止めした行が画面に収まらないときは、ピン止め表示の中を縦にスクロールできること（MUST）。収まらないことを理由に間引いてはならない（MUST NOT）。**

**上限に達しているときに新たなピン止めを求められたら、受け付けず、その旨を示すこと（MUST）。黙って古いものを外してはならない（MUST NOT）。**

**全体表示（`FR-055`）を行ったとき、ピン止めをすべて解除すること（MUST）。** 状態は文書に保存するが（`S-126`）、**版数は上げない**（`FR-063`）—— 全体表示で元へ戻せるので見せ方に当たる。

**読み込んだピン止めに、存在しない `TaskGroup` を指す値が混ざっていたときは、その値を捨てること（MUST）。読み込みを失敗させてはならない（MUST NOT）。**

**Relations**:

- **Type**: `Parent`
  **ID**: `UC-007`
  **Role**: `Satisfies`
```
