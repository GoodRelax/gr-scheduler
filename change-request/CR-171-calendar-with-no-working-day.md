# CR-171 — 稼働する曜日を 1 つも持たない暦を禁じる

> **閉じるもの**: `CM-39`（`setCalendar`）を書こうとして当たった穴 ——
> **仕様書は、7 つの曜日をすべて外した暦を止めていない。**
> ⭐ **本仕様書は既に同じ裁定を 2 度下している**（`FR-085` と `FR-098`）。3 度目の適用であって、新しい原理ではない。

## 1. 出どころ

`src/use-case/edit-document/edit-calendar.ts:225-229` が自分でこう書いている ——
「稼働日を 1 つも持たない命令を受け付ける。**仕様書のどこもそれを禁じておらず、ここで拒むのはこのファイルが発明した規則になる。**」
その暦が `FR-054` の解く文書の暦になると、稼働日の数え上げが答えを持てない。

### ⭐ 在ったので本 CR が触らないもの

| | 仕様書のどこが持っているか |
|---|---|
| **文書の暦の解き方** | `FR-054`。`Project.calendarUid` → `isBaseCalendar` が真のうち `ordinal` 最小 → 表 T-209 の既定、の 3 段。`Task.calendarUid` / `Resource.calendarUid` を読むことも `baseCalendarUid` をたどることも MUST NOT で閉じている |
| **暦を編集する経路と件数の告知** | `FR-088`。稼働する曜日・例外日・週の始まり。取り消しの対象（`UN-13`）、1 回の書き込みで確定（表 T-067 の `WS-3`）、2 つの曜日の符号が別であること |
| **拒否を運ぶ仕組み** | ⭐ **1 つも足さなくてよい。** `EditResult` が値で運び、`WS-3` が 1 件で束ごと捨て、表 T-035 の `AG-9a` が拒否の中身を定め、`FR-076` の `NT-1` が人への見せ方を定める |

### ⛔ 本当に無いもの

| | 無いもの | 測った事実 |
|---|---|---|
| (a) | **稼働する曜日を 1 つも持たない暦を禁じる規則** | `FR-054` にも `FR-088` にも 1 文も無い。`FR-088` の本文は 3 段落しかなく、どれもこの条件に触れない |
| (b) | **投げた例外の受け手** | ⛔ **`src/` に `catch` が 1 つも無い**（`grep -rn "catch" src/` の 4 件はすべて散文の中の語である）。`editDocument` は `EditResult`、`planDocumentChange` は `ChangePlan` という**値の直和**を返す。**`FR-028` の MUST NOT に届いている** |
| (c) | **投げるまでの代価** | `ACCEPTED_DAY_SPAN` は 84,364 日（1970-01-01 〜 2200-12-31）で、弁は `walked++ > ACCEPTED_DAY_SPAN`。⚠️ **`Task` 1 つにつき 1 フレームに 1 回そこへ届く**（`schedule.ts:517` が自分でそう書いている）。500 件なら 1 フレームで 4 千万回超を歩いてから、初めて誰かが何かを知る |
| (d) | **取り込みの経路** | 公式 XSD の `WeekDays` は `minOccurs="0"` である。`FR-054` は継承を解くことを取り込みの仕事とし（`FR-023`）、`ValidateImportedDocument`（`PI-13`）はまだ空の単位である。⛔ **人が何も打たなくても、曜日の行を 1 つも持たない暦が `workingCalendarOf` に届く** |

⭐ **`src/` は既に `ST-7` に寄りかかっていた。** `schedule.ts:677` は `NoWorkingDayReached` を「`ST-7` の形 —— 間違った日を答えるより止めて言う」と書いている。**裁定を経ずに先例を採っていた。**

## 2. 何をするか

**要求に MUST NOT を 1 つ、条件を不変条件の表に 1 行。** 2 ファイルだけ動く。

### (1) 表 T-220 に `IV-17` を 1 行（`05-07-design.md`）

**`IV-7`（暦が 1 つ以上あること）の直後、`IV-8` の前に置く。**
種別が `構造` の行を続けるためであり、**表は種別で束ねられていて席番号順ではない**（表 T-037 は `NT-5` を `NT-6` の後に、表 T-035 は `AG-9` を `AG-10` の後に置いている）。**番号は振り直さない。`IV-17` は空席である。**

```
| IV-17 | `FR-054` が解いた文書の暦が、稼働する曜日を 1 つ以上持つこと。⚠️ **解かれなかった暦は対象外** —— 数え上げに使わない暦は、稼働日を 1 つも持っていてもよい | `FR-054` の解き方と、その暦の `WeekDay` の並び | 構造 |
```

⭐ **表の 2 つの門をどちらも通る** —— 条件が `WeekDay` の並びにまたがるので「1 つの列だけで決まる条件」ではなく、生成したスキーマが表せない。
⭐ **判定に要るものの欄が列名でなく要求の解き方を指すのは、表自身の注（列の名前で並べない）が求めている形である。**

### (2) `FR-088` に段落を 1 つ（`01-04-requirements.md`）

**RATIONALE の直後に置く。** `FR-085` が上限の MUST NOT を置いている位置と同じで、**書ける中身の制約を、確定の手順より先に読ませる。**

```
**稼働する曜日を 1 つも持たない暦を、文書の暦（`FR-054`）にしてはならない（MUST NOT）。受け付けずに知らせること（MUST）** —— 条件は表 T-220 の `IV-17` が持ち、知らせ方は `FR-076` の `NT-1` に従う。⚠️ **表 T-014 の `ST-7` のように処理を止めない** —— あちらは「届いたときは入力か操作の異常である」と自ら書く安全弁であり、こちらは**人が曜日を 7 つ外していけば普通に届く**。`FR-085` と `FR-098` が上限で採っている形に揃える。⚠️ **既定の暦（表 T-209）へ黙って戻してはならない（MUST NOT）** —— 戻すと、外したはずの曜日で日数が数え直され、人は自分の操作が通ったのかを読めない。データを黙って変えない規則は `FR-012` が同じ形で既に持っている。
```

### なぜこの形か（採らなかった案とその代価）

| 案 | 代価 |
|---|---|
| **(b) 描画側で捕まえて通知する** | ⛔ **原因から最も遠い場所で報せることになる。** 手立てを示さない通知は `NT-3a` が MUST NOT で禁じ、毎フレーム出れば `NT-2` に触れる。しかも 1 件の通知に `Task` ごと 8 万回超の歩きを払う。`src/` に初めての `try/catch` を作り、表 T-037（作法の表であって誰が捕まえるかを定めない）の外に受け手を発明する必要がある |
| **(c) `dateFromWorkingDays` が値で答える** | ⛔ **問いを 5 か所へ複写するだけである。** `actualSpanOf` が `null` を返せば実績バーが消える（`FR-011` は描くことを求める）、`dummiesOf` が空を返せば `GR-9` / `GR-17` が消える（`FR-043` が求める）。**各所が地の規則を発明する** —— `edit-calendar.ts:227` が拒んだのはまさにそれである |
| **(e) 既定の暦へ落とす** | ⛔ **黙ってデータを変える形であり、`FR-012` が同じ形を MUST NOT で退けている。** `FR-054` の 3 段の解き方の横に 2 つ目の答えを置くことにもなる |
| **(a) だけ（`CM-39` で拒むが不変条件を立てない）** | ⚠️ **取り込みの経路が開いたままになる**（上記 (d)）。**人が見えないところから来る半分が残る** |
