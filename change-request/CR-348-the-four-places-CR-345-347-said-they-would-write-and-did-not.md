⛔ **当てて出たのは、前の 3 本が残した「在り処の嘘」が 3 つあったことである:**

⛔ **台帳の ✅ は、書いた本人の申告であって、機械が測った事実ではない。**

### 2.3 表 T-051 の `HF-14` — `No name` の行と、そのプロパティパネル（`D-243`）

⛔⛔ **取り下げた 3 つの MUST:**

```
名前は空で立て、その場で打たせること（MUST）
既定の名を与えてはならない（MUST NOT）
名前が空のまま確定されたときは、その行を立てないこと（MUST）
```

⭐⭐ **取り下げてよい理由は、禁止の理由のほうが先に消えていたことである** ——
**禁止の根拠は「改名の入口が 表 T-109 に 1 つも無いので、既定の名で立てると直せない行ができる」
であった。**⛔ **`FR-085` が 2026-09-01 の裁定で改名の道を得た時点で、その根拠は失われていた。**
**3 日間、理由の無い禁止が MUST として立っていたことになる。**

置いたもの: **押された瞬間に既定の名前で行を立て、その行のプロパティパネルを出し、
名前の欄で名づけさせること（MUST）。道は `FR-085` が改名について定めるものと同じとすること（MUST）。**
⛔ **その作法をここに書き写してはならない（MUST NOT）** —— 同じ MUST を 2 か所に置かない。
⭐ **既定の名前の綴りは辞書が持つ**（`FR-038`）—— **仕様書に綴りを刷らない。**

### 2.5 表 T-051 の `HF-14` — 詳しさの段が落とした行（`D-237`）

⛔⛔ **本節だけは台帳が「未検討」と書いていた行である。**
⭐ **本巡に実測して原因が割れた**（出荷ビルド、1920×1080）:

```
行は文書にできている            createTaskGroup は拒んでいない
描かれないのは詳しさの段のせい   FR-018 の深さの上限が新しい行を層から落とす
「深さ 3」ではない              上限と同じ深さの行すべてで起きる
                                上限を 2 に下げれば深さ 2 で、4 に上げれば深さ 3 で起きなくなる
通知が出ないのは HF-17 の手当てが 表示位置を送るだけだからである
                                送っても、詳しさが落とした行は現れない
```

⛔ **「名前が空のまま確定された」という既存の MUST が働いていたのではない** ——
**名前は打ち込まれており、その分岐に入っていない。**
⇒ **`D-243` に吸収されない。**⚠️ **むしろ `D-243` は本件を大きくする** ——
**上限の深さでは、誰にも見えない行のプロパティパネルが開くことになる。**

置いたもの: **立てた行が、現に描かれている詳しさの段（`FR-018`）で落ちる深さになるときは、
その行が描かれるまで詳しさの段を開くこと（MUST）。表示位置を送るだけで済ませてはならない（MUST NOT）。**
