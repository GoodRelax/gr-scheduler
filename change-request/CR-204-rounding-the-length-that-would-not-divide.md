> **閉じるもの**: ⭐ **利用者の裁定（2026-08-22）** —— **PD-164 を案 ④（四捨五入）で裁定する。**

## 2. 何が壊れていたか（**逐語**）

### #1 —— `FR-054` は片方向しか持っていない

`FR-054` の `STATEMENT`（`01-04-requirements.md:2518`）:

```
稼働日を交換相手の期間（時間の量）へ換算するときは Project.minutesPerDay に従い、
それが空のときは表 T-209 の S-128 に従うこと（MUST）
```

⛔ **逆向き（期間 → 稼働日）を述べる文が無い。** ⭐ **取り込みは毎回その向きを走る。**

### #2 —— 読み捨てた値は、書き出しで消える

```
mspdi-codec.ts:1524   if (!Number.isInteger(days)) { … return null }
mspdi-codec.ts:2409   if (task.actualDuration === null) return []
```

⛔ **`null` は「書かない」である。** ⚠️ **`ActualDuration` は `TASK_CONSUMED` に載っているので `carryElements` にも残らない**（`mspdi-codec.ts:1233`）——
⭐ **`PT41H` の 1 要素が、往復して跡形もなく消える。**

### #3 —— 振る舞いを変えても、いまの試験は 1 件も落ちない

⛔ **`tests/` を全数検索したところ、`actualDuration` は固定データの組み立てにしか現れない。**
**割り切れない長さを取り込ませる試験は 1 件も無い。** ⚠️ **`R6.2` の違反であり、本 CR が変える経路をいま誰も見ていない。**

## 4. 原稿の中身（**書く前に置く**）

`FR-054` の `STATEMENT` に足す文:

> **交換相手の期間（時間の量）を稼働日へ換算するときも同じ 1 日あたりの分数を用い、1 日単位に四捨五入すること（MUST）。ちょうど半日のときは絶対値の大きいほうへ寄せること（MUST）。割り切れないことを理由に値を捨ててはならない（MUST NOT）** —— 捨てると、交換相手が書いた長さが書き戻しで消える。**年と月を持つ長さは換算せず、知らせること（MUST）** —— 年と月の長さは、どこから数え始めるかで変わる。**四捨五入した `Task` の件数を知らせること（MUST）**（知らせ方は `FR-076` の `NT-1`）—— **丸めた値は元の長さではない。**
