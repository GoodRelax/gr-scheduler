## 2. 変更の背景・目的

### 2-1. 見つかった経緯

**CR-129 で新設した表 T-019a が、書き出した HTML に出ていなかった。** 原因を調べたところ、**CR-129 とは無関係の、変更前から在る欠陥だった** —— 表 T-019 も、表 T-021a も、表 T-052 も出ていなかった。

```
HTML の実際の並び:
  … FR-010 の RATIONALE … ORIGIN: UC-005 手順 2 〜 4、拡張 3a
  → FR-011  4.1.29. 実績バーの両端を人が置いた日付に保つ
      ↑ この間にある 表 T-019・表 T-019a・注記がすべて消えている
```

### 2-2. 相関を機械で当てた —— **例外 0 件**

| 表の位置 | 描画される |
|---|--:|
| 要求ノードの **`**Relations**:` より前** | **6 / 6** |
| 要求ノードの **`**Relations**:` より後** | ⛔ **0 / 40** |

**`**Relations**:` ブロックより後ろに置いた自由文を、StrictDoc は全ビュー（`.html` / `-TABLE` / `-TRACE` / `-DEEP-TRACE`）で捨てる。**

**動いている 6 例が移動先を決めている** —— いずれも `RATIONALE` と `**Relations**:` の間に自由文を置いている（例 —— `FR-047` の 表 T-021b）。

```

**本表の 3 行が、表 T-021 の `PM-4`（遅れ）が成立する条件の全数である。**

**Relations**:

```

### 2-4. 欠陥② 生の `**`

**太字が `<strong>` にならず生の `**` のまま出ている箇所が 21 あった**（①を直して隠れていた文が出たことで、11 から 21 に増えた）。

**失敗の形は 1 つである** —— **閉じの `**` が `。` の直後にあり、かつ次の文字が CJK か `*` のとき、docutils はそれを閉じと認めない。**

```
…いても状態が変わらない。**再開日を未定のままにもできること。****中断のあいだは…
                          ↑ この閉じが成立しない（次が `*`）
…とすること（MUST）。**選ぶ面には、…添えること。****一覧のすべてを…
                                              ↑ 同じ
```

**改行が続く場合は成立する。** そのため大半の太字は無事で、**次に文字が続く 21 箇所だけが落ちていた。**

### 2-5. ⚠️ 機械検査はこれを見つけられない

**16 検査は全緑のままだった。** 検査が見ているのは**原稿の中で参照が解決すること**であり、**参照先が刊行物に出ているかどうかは見ていない。**

⚠️ **`SKILL.md` は「緑は参照が解決することの証明であって、仕様書が自分と整合していることの証明ではない」と書いている。本件はその一歩先である** —— **原稿が整合していても、刊行物が原稿と同じ内容とは限らない。**
