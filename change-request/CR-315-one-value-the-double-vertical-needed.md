# CR-315 — 「縦 2 本」が要っていた値は 1 つだけだった

⭐ **台帳 D-148。ガイドカーソルの 4 モードのうち、「縦 2 本」だけが何も描いていなかった。**
⛔ **止めていた根拠は 2 つ書いてあり、そのうち 1 つは誤りであった。**

| | 何を | どこ |
|---|---|---|
| 1 | **2 本の隔たりを表 T-206 に立てる** | `S-209`（新設。既定 8px 🔎）|
| 2 | **描く**（`pointer.x ± S-209 / 2`）| `svg-renderer.ts` の死んでいた枝 |
| 3 | **描き直しの除外を外す** | `frame-loop.ts` の `GUIDE_CURSOR_DRAWS_NOTHING` |
| 4 | **分類を H から C へ落とす** | `PD-343` |

## 0. ⛔ 立ちどまって答える 3 つ

### ① この変更は `CH-` / `GL-` のどれを前へ進めるか

`CH-4`（**すぐわか**）と、その下の `GL-006`（アフォーダンスとシグニファイア）。
⛔ **コマンドパレットに「ガイドカーソルを縦 2 本にする」という入口が在り、押すと効いたように見えて、
画面は何も変わらない。** ⭐ **押しても何も起きない入口は、読めない入口より悪い** ——
読めない入口は試されないが、これは試されたうえで「この道具は壊れている」と教える。

### ② レビュー観点のどの条項を当て、何が出たか

`docs/development-rules/07-review-standards.md` の `R2` —— **POLA（最小驚き原則）**、
「関数・メソッド名から期待される動作と実際の動作が一致しているか」。
⇒ ⛔ **`S-66 = 'double-vertical'` の書き込みは正しく効いていた。**十字が消えることで確かめられる。
**名前どおりでなかったのは描く側だけである。**

⚠️ **もう 1 条項当てた** —— 同じ `R2` の **PIE**、「コメントが**なぜ**そうしているかを説明しているか」。
⛔ **死んだ枝にはちゃんと理由が書いてあった。その理由が半分まちがっていた。**
⭐ **コメントは「無い」より「古い」ほうが危ない** —— 無ければ調べるが、
在れば読んで納得して立ち去る。実際、この枝は 2 回そうやって見送られている。

### ③ 利用者に**問わずに決めた**こと（**覆してよい**）

1. ⭐ **隔たりの既定を 8px にした**（🔎。測って決めた値ではない）。
   **2 本が離れて見えるだけの隔たりを取りつつ、日を刻む目盛の 1 日の幅（`S-85` の 26px）を
   大きく下回る**ように選んだ —— 1 日ぶんに届くと、日数を測る `CU-2` の 2 本に見えてしまう。
2. ⭐ **ポインタは 2 本の「あいだ」に置いた**（`pointer.x − gap/2` と `pointer.x + gap/2`）。
   ⛔ **片側に 2 本をぶら下げると、案内している当の場所から手が外れる** ——
   表 T-029 の `CU-3` は「ポインタに**追従する補助線**」と書いている。
3. ⭐ **`FR-048` の本文・表 T-029・表 T-202 は 1 文字も動かしていない。**
   **足りなかったのは値 1 つであって、規則ではない。**
4. ⭐ **`PD-343` を分類 H から C へ落とした**（規則 06）。
   下の「測った」がその根拠である。⚠️ **`@provisional PD-343` の印は残してある** ——
   **隔たりの数そのものは、まだ利用者の裁定を受けていない。**

## 1. ⛔ 測った

### 「縦 2 本」だけが描いていない（出荷ビルド、2026-08-30）

```
`svg line` の本数
  IC-47 十字      : 97 → 99   (縦 1 + 横 1)
  IC-48 縦 1 本   : 97 → 98   (縦 1)
  IC-49 縦 2 本   : 97 → 97   ← 何も増えない
```

⇒ ⭐ **`S-66` は正しく `'double-vertical'` になっている**（押すと十字が消える）。
**欠けているのは描く側だけである。**

### 「未決が 2 つ積み上がっている」は**偽**であった

⛔ 死んだ枝はこう書いていた ——
「隔たり」と「`CU-2` の 2 本との見分け」の**両方**が未決なので、規則 06 の分類 H に当たる、と。

```
同じブロックの 12 行上（@provisional PD-341）:
  ガイドカーソル : themed('S-148') / 太さ 1
  Dual Cursor    : S-195           / S-194
⇒ 色も太さも別である ⇒ 画面上で区別が付いている
```

⭐ **`FR-048` の結びが求めているのは、まさにそれである** ——
「**同じ見た目なので、どちらが出ているかを画面上で区別できるようにすること（MUST）**」。
⇒ **未決は「隔たり」の 1 つだけであった。1 つ・推奨値あり ＝ 規則 06 の分類 C** ——
**進めて、印を付けて、あとで問う。**

### 描かないままだと、描き直しの側も嘘になる

```
frame-loop.ts:856   GUIDE_CURSOR_DRAWS_NOTHING = 'double-vertical'
frame-loop.ts:6047  guideMode !== NONE && guideMode !== DRAWS_NOTHING
```

⇒ ⛔ **この 2 つを外さないと、2 本は 1 度描かれたきりポインタを追わない。**
⭐ **外したあとは「なし」だけが除外である** ——
`FR-048` の MUST NOT が言う「ポインタに追従する線が **1 本も無く**」に、
もう「縦 2 本」は当たらない。

