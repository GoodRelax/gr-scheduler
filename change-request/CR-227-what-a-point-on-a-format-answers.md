# CR-227 — 形式の上の点が何を答えるか

> **閉じるもの**: ⛔ **`FR-096`（MUST）は書き出しの選択面に 表 T-024 の書出方向の形式を並べさせるが、`IF-9` はその上の点について何も答えられない。**
> `IF-9` の供給は「どの UI パーツ（表 T-103）のどの入口（表 T-109）の上か」であり、**形式は 表 T-024 の行であって 表 T-109 の行ではない。**
> ⭐ **`CR-192` が `IF-9` に `readScreenPartAt` を足したのと同じ形の広げ方である。**

## 0. ⛔ 立ちどまって答える 3 つ（**検査 22 が空欄を許さない**）

### ① これは `CH-` / `GL-` のどれを前へ進めるか

⭐ **`CH-2`。受ける目標は `GL-001` / `GL-002`。** ⛔ **書き出せない道具は、1 枚で俯瞰した結果を外へ出せない。**

⚠️ **満たされていない MUST である** —— `FR-096` は「表 T-024 のうち書出の方向を持つ形式から選ばせる」と定めるが、**選択面は 6 つの行 ID を並べても、押されたことを誰にも返せない。** e2e の 1 件が実測でそう言っている。

### ② `review-standards` のどの条項を当て、何が出たか

| 条項 | 当てた対象 | 結果 |
|---|---|---|
| **`R1.4`**（網羅性）| `IF-9` の供給の欄 | ⛔ **表 T-109 の入口しか答えられない。** 形式は別の表の行である |
| **`R2.1`**（仕様の名前を使う）| 新しいメンバの名 | ⭐ **`format`。** 表 T-024 の行 ID を運ぶ。⛔ `entry` に相乗りさせない —— 相乗りさせると「どちらの表の行か」が読めなくなる |
| **`R1.3`**（唯一の正がある）| 形式の全数 | ⭐ **表 T-024 が持つ。** `src/` へは `exchange-formats.json` が生成で運ぶ |
| **`R4`**（POLA）| 既存の `entry` | ⭐ **1 文字も動かさない。** 形式の上では `entry` が `null` になるだけである |

### ⑧ 利用者に問わずに決めたこと（**覆してよい**）

| | 決めたこと | 何に載せたか |
|---|---|---|
| 1 | ⭐ **`IF-9` の供給の欄を広げ、新しい継ぎ目を立てない** | ⚠️ **`CR-192` が同じ欄を同じやり方で広げた前例がある。** 継ぎ目を増やすと 表 T-065 の員数が動く |
| 2 | ⭐ **形式の上では `entry` を `null` にする** | ⛔ **1 つの点が 2 つの表の行を同時に指すことはない。** どちらか一方が `null` である |
| 3 | ⭐ **`data-format` を頁の印にした** | ⚠️ **`data-icon` の 3 つ目の綴りではない** —— 表 T-109 の行と 表 T-024 の行は別物であり、同じ属性に混ぜると読む側が表を取り違える |
