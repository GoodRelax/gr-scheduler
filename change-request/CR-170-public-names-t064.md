# CR-170 — 表 T-064 が「全数」と書きながら落としている 5 つの名前

> **閉じるもの**: 表 T-064（公開インターフェース）の `PI-1` と `PI-9` が、
> **コンポーネントの境界を実際に越えている名前を宣言していない**こと。
> ⭐ **表を 2 行直すだけである。** 表も要求も図も増えない。

## 1. 出どころ

表 T-064 は 5.3 の「コンポーネントの外から呼んでよい名前の全数」であり、
表 T-061 の `LR-2`（他のコンポーネントの公開エントリより奥へ手を伸ばさない）は**この表があって初めて検査できる**。
`src/` の相対 import を全部読み、コンポーネントの境界を越える名前を数えた。

## 2. 何をするか

**`docs/spec/05-07-design.md` の表 T-064 を 2 行だけ直す。**

### `PI-1`（`documentModel` / `Schedule`）—— 末尾に 3 つ足す

`workingCalendarOf` の後ろに、順に次を足す。**前の並びは 1 文字も変えない。**

```
／ `dayOf`（日付の字面を日にする。規則は `FR-054`）／ `textOfDay`（日を日付の字面に戻す）／ `compareDays`（2 つの日の前後）
```

⭐ **値を写していない。** 規則は `FR-054` が持ち、説明はそこを指すだけである（1.9）。`_assets/tbl-settings.md` は触らない。

### `PI-9`（`UseCase` / `EditDocument`）—— 中身を入れ替える

```
| PI-9 | `UseCase` | `EditDocument` | `editDocument`（表 T-108 の命令を集約へ振り分ける。表 T-067 の `WS-3` が呼ぶ。集約ごとの割りは 表 T-063 の `UT-2`）／ `Refusal`（型。拒んだ理由。`AG-9a`）／ `SettingsLimits`（型。`editDocument` に渡す下限・上限） |
```

**8 つの `editX` を落とす理由**（重い順）:

1. ⭐ **表 T-064 は「外から呼んでよい名前の全数」であり、`LR-2` の柵である。** `src/` の中で `EditDocument` が公開する名前のうち実際に呼ばれているのは `editDocument` 1 つだけで、**8 つ宣言することは柵を 8 つぶん広げることに等しい。**
2. **5.3 の camelCase の規則。** `PI-8` / `PI-10` 〜 `PI-16` はすべて自分の camelCase を書いている。`PI-15` は `watchChanges` / `unwatchChanges` を併記しているが、**それらは実際に外から呼ばれているから在る。**
3. **8 つの並びは 表 T-063 の `UT-2`（`edit-document.ts` と集約ごとの 8 ファイル）と 表 T-075 が既に持つ。** 1.9 は他の表が持つものを写すことを禁じる。**新しい欄は `UT-2` を指すので、情報は失われない。**
4. **外の呼び手は単体テストだけであり、9.1 がそれを仕様書の外に置いている。**

⚠️ **採らなかった案（B）とその値打ち。** `editDocument` を**足して 8 つも残す**（9 名）と、公開エントリが今日 export している名前と表が 1 対 1 で並ぶので、
「エントリの export は 表 T-064 の部分集合であること」という機械検査を `src/` を直さずに書ける。
**その代わり `LR-2` の許す面が 8 つ広がり**、`editTask` へのコンポーネント越えの呼び出しが検査を通ってしまう ——
`PI-8` が `applyDocumentChange` を「唯一の書き込みの経路」と書き、`WS-3` が全ての書き込みを `editDocument` へ通す以上、それは通してはならない。
⚠️ **採った案（A）が残す正直な澱**: `edit-document.ts:83-92` は単体テストのために 8 つを re-export し続けるので、**エントリが表の宣言しない名前を出す状態が残る。** 今日それを見る検査は無く、9.1 がテストの木を仕様書の外に置いている。
