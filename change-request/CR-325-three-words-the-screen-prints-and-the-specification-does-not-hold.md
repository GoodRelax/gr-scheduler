# CR-325 — 画面が出しているのに、仕様が行を持っていない語 3 か所

⭐⭐ **利用者の裁定（2026-09-02）** —— **前に立つ者が 3 つの案を並べ、利用者が 3 つとも推奨案を採った。**

> **① 書き出しの面の英語の見出し** ⇒ **`Save to File`**（`Export Chooser` から）
> **② タスクグループのプロパティ欄の項目名** ⇒ **表 T-016 に行を足す**（辞書に枠を新設する案は落ちた）
> **③ 「この形式はまだ書けない」の理由の行** ⇒ **表 T-233 に新しい行を足す**（`RS-27` を当てる案・`RS-15` のままにする案は落ちた）

**台帳の行**: `D-184` ／ `D-185` ／ `D-186`。

⭐ **3 つを 1 つの変更要求にまとめた理由は 1 つである** —— **どれも「画面が語を出しているのに、その語の行が仕様のどこにも無い」という同じ欠け方をしている。**⛔ **別々に書くと、同じ欠け方への同じ答えが 3 か所に散る。**

---

## 0. ⛔ 立ちどまって答える 3 つ

### ① この変更は `CH-` / `GL-` のどれを前へ進めるか

`GL-006`（アフォーダンスとシグニファイア）と `GL-003`（1 つの正）。

⭐ **3 つとも、画面が「内部の綴り」を人へ見せている。**
`Export Chooser` は面の役目ではなく実装の呼び名であり、`label` / `color` / `height` は
`GRS JSON` の列名そのもの、`RS-15` の「もう一度行ってください」は**何度やっても書けない**。
⇒ ⛔ **どれも、人が読んで次の一手を決められない。**

### ② レビュー観点のどの条項を当て、何が出たか

`docs/development-rules/07-review-standards.md` の **`R3.1`**（同じ規則を 2 か所に持たない）と
**`Naming`**（命名はソフトウェアの主要なインターフェースである）。

⛔⛔ **`R3.1` を当てて、仕様書の中に古い MUST を 1 つ見つけた。**
`01-04-requirements.md:316` が **「表 T-016 の「項目名（英語・画面表示）」の綴りがそのまま画面に出る」** と
書いている。⭐ **その列は表 T-016 に無い。** 2026-08-27 の利用者の指示
（「別のデータとして紐づけて管理しろ」）で表示名は辞書へ移り、表 T-016 の前文はいま
**「画面に出す名は本表に無い（MUST NOT）」** と書いている。
⇒ ⛔ **`:316` は、存在しない列を名指す MUST として 6 日間残っていた。** 本要求で直す。

### ③ 利用者に**問わずに決めた**こと（**覆してよい**）

1. ⭐ **表 T-016 に「対象」の欄を足すことにした。**
   ⛔ **足さないと、`height` がタスクのパネルにも出る。** 表 T-016 の並びは `FR-006` が
   **印刷順そのもの**と定めているので、行を足せば必ずどちらのパネルにも出る。
   ⇒ **どちらの選択に属する行かを、行自身が言うほかない。**
2. ⭐ **足す 3 行の英語の名は、列名に近い綴り（`label` / `color` / `height`）のままにした。**
   **利用者の指摘は日本語の側である**（「出るべきは 名称／色／高さ」）。
   ⭐ **既存の行も `name`・`actualStart` と綴っており**（`PR-1`・`PR-4`）、そちらへ揃えた。
   ⛔ **`PR-12` が `Color` を落としているのは、列が 3 つ並ぶからである**（利用者の指示
   2026-08-27「色の設定ということは値部分を見れば分かる」）—— **列が 1 つの行には当たらない。**
3. ⭐ **新しい理由の行を `RS-40` とし、作法は `NT-3a`（失敗の通知）にした。**
   ⛔ **`NT-1`（入力を受け付けないとき）ではない** —— **人の入力に誤りは無く、失敗したのは
   こちらである。**⭐ **`NT-3a` は「次に取れる手段を添えること（MUST）」を課すので、
   「別の形式を選んでください」がその手段になる。**
4. ⚠️ **`RS-40` は `D-173`（`.svg` と単一 `.html` の書き手を作る）が終わっても残す。**
   **将来また書けない形式が並んだときの落ち先だからである。**
   ⛔ **`RS-15` へ戻すことはしない** —— 同行は「行の無い理由」の落ち先であって、
   **行の在る理由をそこへ落とすのは `FR-076` の定めに反する。**

## 1. ⛔ 測った —— 3 つが今どうなっているか

**① 書き出しの面の見出し**（`_source/display-words.json` の `surfaces`）

```
{"ja": "ファイルに保存", "en": "Export Chooser"}
```

⇒ ⭐ **日本語だけが 2026-08-29 に直り、英語が取り残されていた。**

**② タスクグループのプロパティ欄**（出荷ビルド、2026-09-01）

```
画面    label / color / height
辞書    _source/display-words.json の properties に該当の行が 0 件
表      表 T-016 の 16 行はすべて Task の列であり、TaskGroup の行は 0 件
```

⇒ ⛔ **`FR-006` は「表 T-016 の項目をパネルに出す」と定めている。**
**表に行の無い項目が出ている以上、いまのパネルは `FR-006` の外で描かれている。**

**③ 書けない形式を選んだとき**（`src/framework/single-html-shell/frame-loop.ts:1325`）

```
unsupported:  'RS-15'
tooLarge:     'RS-15'
rasterFailed: 'RS-15'
```

⭐⭐ **実装は正しい。** `FR-076` が `RS-15` を「行の無い理由の落ち先」と定めており、
表 T-233 に行が無いのだから、そこへ落ちるのが定めどおりである。
⛔ **誤っているのは、行が無いことである。**

⚠️ **前の巡の引継書は「`FR-029` が落ち先を `RS-27` と定めており、いま使われている
`RS-15` と食い違う」と書いていた。**⛔ **これは偽である。**
`RS-27` は **「押した入口が、いま行えることを持たない」**（対象の有無の話）であり、
**書き手が居ないこととは別の場面である。**⇒ **食い違いではなく、行の不在であった。**

## 2. ⭐ 書くもの

### 2.1 ① 見出しの語

### 2.2 ② プロパティ項目に「対象」を持たせ、行の属性を 3 行足す

**表 T-016 に欄を 1 つ足す。**

| 欄 | 値 | 意味 |
|---|---|---|
| **対象** | `Task` ／ `TaskGroup` | **その行を出すのは、どちらが選ばれているときか** |

⛔ **`FR-006` に 1 文を足す（MUST）**:
**プロパティパネルは、いま選ばれているものと同じ「対象」を持つ行だけを出すこと（MUST）。
対象の違う行を出してはならない（MUST NOT）。**
⭐ **印刷順は表の並びのままである** —— **同じ対象の行どうしの相対順は変わらない。**

**足す 3 行**（原稿は `_source/property-items.json`。表 T-016 は生成物である）:

| 行 ID | 列（`GRS JSON`）| 入力の型 | 対象 | 備考 | MSPDI |
|---|---|---|---|---|---|
| `PR-18` | `label` | 文字 | `TaskGroup` | 行の名前。⚠️ **実体は `_assets/fig-erd-detail.md` の `AT-53` である** | 無い（`GRS JSON` のみ）|
| `PR-19` | `color` | 色 | `TaskGroup` | 行の帯の色。`null` ＝ テーマから解く | 無い（`GRS JSON` のみ）|
| `PR-20` | `height` | 数値 | `TaskGroup` | 倍率 1 のときの論理の高さ。`null` ＝ 自動 | 無い（`GRS JSON` のみ）|

⚠️ **MSPDI の欄が空なのは `TaskGroup` が軸 B であり、書き出さないからである**
（`erd.json` の `TaskGroup` は `export: false`）。⭐ **`PR-17` / `PR-12` / `PR-13` / `PR-15` と同じ形である。**

**辞書に 3 項**（`_source/display-words.json` の `properties`）:

| 行 ID | ja | en |
|---|---|---|
| `PR-18` | 名称 | `label` |
| `PR-19` | 色 | `color` |
| `PR-20` | 高さ | `height` |

⛔ **`:316` の古い MUST を直す（MUST）** —— **「表 T-016 の「項目名（英語・画面表示）」の綴りが
そのまま画面に出る」を、「画面に出す名は `FR-038` の辞書が同じ行 ID で持つ」へ。**
⭐ **`W-2`（JSON のプロパティは camelCase）を当てる先は、辞書の `en` の綴りである。**

### 2.3 ③ 理由の行を 1 つ足す
