### ③ 持ち主に**問わずに決めた**こと（**覆してよい**）

1. ⭐ **形は、`UID` が一致する `Task` の予定の形である。** 表 T-012 の `SH-1`〜`SH-4`（矩形・矢羽根・矢印・ダンベル）か、マイルストーン（`SH-5`）ならその `Task` の `AT-101`（`milestoneGlyph`）の図形である。横は前回の `start`〜`finish`、縦は今のまま（`BL-2` の縦の 2 文）である。
2. ⭐ **点か期間かは、前回の `milestone`（`AT-138`）が決める。形の種類が食い違うときは、その種類の既定の形を描く。**
   - 前回がマイルストーン、今のタスクもマイルストーン → 今のタスクの図形を、前回の `start` を中心に置く。
   - 前回がマイルストーンでない、今のタスクもマイルストーンでない → 今のタスクの形を、前回の `start`〜`finish` に置く。
   - 前回がマイルストーン、今のタスクがマイルストーンでない → 菱形（`AT-101` の既定 `'diamond'`）を前回の `start` を中心に置く。
   - 前回がマイルストーンでない、今のタスクがマイルストーン → 矩形（`SH-1`）を前回の `start`〜`finish` に置く。
   理由: 前回の日付が点か期間かは前回の記録であり、今の形で塗り替えると日付の読みが崩れる（期間を点の図形で描くと終了が消え、点を期間の形で描くと幅の無い形になる）。β の GRS JSON では、マイルストーンのタスクは `taskShape` を持たず、マイルストーンでないタスクは `milestoneShape` を持たない。借りる形が無いので、既定の形を描く。この 2 つの既定は今の描き方（矩形か菱形）と同じなので、食い違うときの絵は今と変わらない。
3. ⭐ **フェード（`FR-075`、表 T-012a）は継がない。** 矢羽根の切り欠き（表 T-221 の `LF-6`）と矢じりの横幅（`LF-7`）は、輪郭自身の横幅と縦幅から求める。理由: フェードは今のタスクの日付に結んだ値であり、前回予定は持たない（`IMPS-1455` —— 前回予定は重ねて描くのに要るものだけを持つ）。
4. ⭐ **線と色と刻みは今のまま（`BL-3`）。** 線だけの形（`SH-3` / `SH-4`）の輪郭も、線を `S-39` の太さの破線で描き、矢じりと端の点は塗らずに縁だけを描く（「輪郭を塗らない」）。マイルストーンの図形は、外側の輪（本体）だけを描き、内側の線と点（`LF-18` の `inner` / `dot` / `shade`）は描かない —— 輪郭は外形で対応を示す絵である。
5. ⭐ **当たり（`GR-27`）は、描いた形を `HT-1` と同じに読む。** 輪郭の形の内側（線だけの形は、矢じりと点の縦幅を含む線の帯）である。

### ④ 持ち主に問うたこと

無し。`JDG-3749` が食い違いの描き方をこの席に任せた。

### 1.1 変える規則
