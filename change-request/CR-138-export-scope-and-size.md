## 2. 利用者の裁定（2026-08-15 〜 16）

| 問い | 結論 |
|---|---|
| 出力サイズ | **1600 × 900 固定。** 4K でも縦長でも変えない。A3 横 / A4 横は廃止 |
| 由来 | 標準画面 1920 × 1080（`MC-6`）と同じ 16 : 9 |
| 切り出す範囲 | ⭐ **画面の全体。** バーを描かなくても場所は残す —— 狭く取ると 16 : 9 が崩れる |
| 縮める比 | **1600 ÷ 画面幅。** 横長も縦長も画面幅基準 |
| WYSIWYG の定義 | ⭐ **b) = c)** —— a) 基準環境で Fit したキャプチャ ／ b) a) を比で縮めたもの ／ c) 出力 |
| ヘッダー | **帯の高さを保ち、文書名だけを描く。** ロゴとコマンドの場所は空白。**文書名は動かさない** |
| プロパティパネルとコマンドパレット | ⭐ **閉じた状態として書き出す。** ——「編集のために一時的に表示したものであるため、消し忘れたものとして非表示にして出力すべき」 |
| 収まらない分 | **縮めずに `TaskGroup` 単位で落とす。件数を知らせる** |
| 文字が可読の下限を割ること | ⭐ **受け入れる。** 12px → 10px |
| 透かし | **タスクエリア限定** → 確定名 `Row Area`（`U-50`）で書く |
| 行名が幅を超えたら | **末尾を打ち切る。** 全文を見たい者はパネルを広げる（幅は文書が持つので相手も同じ絵になる） |
| `svgPadding` | **廃止してよい**（用途を定めた規則が 1 行も無いことを確認済み） |

## 4. 検算が差し戻した 11 点（抜粋）

| 指摘 | どう直したか |

### ⚠️ 検査 11 が 1 度落ちた（`A=17 (new 1)`）

```
FR-085  使える幅は、rowTitlePanelWidth（_assets/tbl-settings.md の表 T-203 の S-79）から…
EP-3    幅は rowTitlePanelWidth（_assets/tbl-settings.md の表 T-203 の S-79）をそのまま使うこと（MUST）
```

**`EP-3` から幅の指定を落とし、「書き出し専用の幅を設けてはならない（MUST NOT）」だけを残した。** 幅の持ち主は `FR-085` 1 つになった。**再実行で `A=16 (new 0)` に戻り、基準線の張り直しは要らなかった**（`U-14` はこれで閉じる）。
