## 2. 何をするか

**未記入行 1 行を差し替える。表も行も図も UID も 1 つも増やさない。**

| | |
|---|---|
| **置き場を書く** | 生成物の名と、それを書き出す生成器の名を書く。**これが席の本体である** |
| **中身を写さない** | **本節はスキーマの中身を持たない**（1.9 の「同じことを 2 度書かない」）。既に `:724` が「本節はスキーマ本体を持たない」と述べており、**そこを言い直さず、置き場だけを足す** |
| **弱さを明示する** | **スキーマは原稿が綴っていない値を作らないこと（MUST）。スキーマを通ったことをもって本仕様書に適合したとみなしてはならない（MUST NOT）** |
| **席を閉じる** | 引用行を落とす。**6.2 の `> 未記入` は 0 件**になり、`grep -n "^> 未記入"` は **11 → 10** に減る |

**前後（`old` は 1 行、`new` は 2 段落）**

```text
BEFORE > 未記入。原稿が機械可読になってから起こす。

AFTER  **起こしたスキーマは `_assets/grs-document.schema.json` である。** 日程データの群の原稿と見せ方の群の原稿を `_assets/source/erd_json_to_schema.py` が読んで書き出す。⚠️ **中身をここへ写してはならない（MUST NOT）** —— 写しは、原稿を直したときに一緒に腐る（1.9）。

       **スキーマは、原稿が綴っていない値を作らないこと（MUST）** —— 列挙の値を原稿が綴っていない列は、素の文字列に広がる。どれを広げたかは生成物自身が残す。⚠️ **したがって、スキーマ検証を通ったことをもって本仕様書に適合したとみなしてはならない（MUST NOT）** —— スキーマが見るのは形であり、規則と理由の正は要求の側である。
```
