# CR-173 — 取り込みの上限が単位と起点を言っていない 2 件

> **閉じるもの**: `UF-22`（`validate-imported-document.ts`）の冒頭が ⛔ STOP 1 / ⛔ STOP 2 として
> 報告した穴。**どちらも「仕様書が決めていないので実装が決めた」と自ら明記している。**
> ⚠️ **決まっていないのは値ではなく、値の読み方である** —— 32 という数も 64 という数も既に在る。
> **利用者の裁定**（2026-08-17）: **F-1 は係数を書く。F-2 は根を深さ 1 とする。**

## 1. 出どころ

`src/use-case/validate-imported-document/validate-imported-document.ts:74-91` の逐語:

```
⛔ STOP 1 -- the megabyte. S-113 is named `importMaxBytes` but its value
column reads "`32` MB", and its lower and upper bounds (1 and 256) are in
megabytes too. So the setting is a COUNT OF MEGABYTES and the byte count has
to be converted, and docs/spec never states how many bytes a megabyte is.
This file uses 1 MB = 1024 * 1024 bytes.

⛔ STOP 2 -- where depth starts counting. S-115 gives the WBS a maximum depth
of 64 without saying whether a root row is at depth 1 or 0.
```

⚠️ **どちらも境界が 1 つずれるだけで、例外にも警告にもならない** —— 32,000,001 バイトのファイルが
通るか弾かれるか、64 段の WBS が通るか弾かれるかが黙って入れ替わる。**`FR-023` が受け入れの正である以上、
これは受け入れ判定の仕様である。**

### ⭐ 在ったので本 CR が触らないもの

| | 仕様書のどこが持っているか |
|---|---|
| **32 と 64 という値そのもの** | 表 T-211 の `S-113` / `S-115`。⛔ **本 CR は値を 1 つも変えない** |
| **上限を超えた入力の扱い** | 表 T-211 の直後の注が `FR-023` を指している |
| **`S-115` と `S-125` が別物であること** | `S-115` の備考が既に書いている（WBS はクランプしない）|
| **深さ 3 が「大 / 中 / 小」であること** | `FR-004`。⭐ **F-2 の裁定はこの読みを追認するものである** —— 3 段が 大 / 中 / 小 なら、1 段目は「大」であって「0 段目」ではない |

### ⛔ 本当に無いもの

| | 無いもの | 測った事実 |
|---|---|---|
| F-1 | **1 MB が何バイトか** | `1024` は `docs/spec` に **0 回**しか現れない（`01-04-requirements.md` と `tbl-settings.md` の両方で 0）。**2 通りの読みのどちらも仕様書に無い** |
| F-2 | **WBS の深さの起点** | `S-115` は「WBS のネストの深さの上限」としか書かない。⭐ **`FR-004` は深さ 3 を「大 / 中 / 小」と対応づけているが、`S-115` はそこを指していない** |

⚠️ **`S-113` も `S-115` も、`impact.py` が「指している箇所が無い。行が浮いている可能性がある」と答える。**
⛔ **本 CR はそれを直さない** —— 浮いている行は `S-49` を含めて他にも在り、参照を足すのは別の CR である。
**繰り越しに残す。**

## 2. 何をするか —— **編集は 2 か所。どちらも備考欄への追記である**

⚠️ **表 T-211 は `型` の列を持たない。** 生成器（`erd_json_to_schema.py`）が読むのは `名前` `値` `下限` `上限` であり、
**備考欄は読まない。** よって生成物は 1 バイトも動かない（第 4 節で予測し、第 5 節で突き合わせる）。

| | 対象 | 追記する文 |
|---|---|---|
| **1** | `S-113` の備考 | 「**1 MB = 1024 × 1024 バイトとする。**」を末尾に足す |
| **2** | `S-115` の備考 | 「**根の行を深さ 1 と数える**（`wbsParentUid` が `null` の `Task` が深さ 1）。」を末尾に足す |

⚠️ **`（MUST）` を書かない** —— 検査 12 が値の表への MUST を禁じている。規則としての強さは `FR-023` が既に持っており、
**本 CR が足すのは、その規則が読む数の単位と起点である。**

### コード側

⭐ **実装は 2 件とも既に裁定どおりに書かれている** —— `BYTES_PER_MEGABYTE = 1024 * 1024`、根を深さ 1。
**変えるのは注記だけである** —— ⛔ STOP 1 と ⛔ STOP 2 を消し、**仕様書のどこが答えを持つようになったかを 1 行で指す。**
⛔ **⛔ STOP 3（日付でない文字列を持つ日付列）は残す** —— 本 CR の裁定に含まれておらず、**無関係な直しを混ぜない。**

## 3. ⚠️ 書かないと決めたもの

| | |
|---|---|
| **`S-113` の単位をバイトへ改めること** | 利用者が「係数を書く」を選んだ。⭐ **`S-113` は 🔎 付きで人が選び直す値であり、`33554432` より `32` MB のほうが選び直せる。** |
| **`S-115` の値 64 の見直し** | 裁定にも報告にも無い。値は動かさない |
| **浮いている行に参照を足すこと** | `S-49` / `S-113` / `S-115` ほかに及ぶ。**別の CR** |
| **⛔ STOP 3** | 日付でない文字列を持つ日付列の扱い。**まだ裁定を受けていない** |
