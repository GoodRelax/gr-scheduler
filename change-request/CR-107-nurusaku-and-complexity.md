# CR-107 — `GL-003` を「ぬるサク」で書き直し、計算量の非機能要求を新設する

## 1. 変更概要

`GL-003`（操作が引っかからない）の `STATEMENT` を差し替える。**対象を「ズーム・パン・ドラッグ」から「どの操作を行っても」へ広げ**、
達成された状態を **「ぬるサク」** と名付ける。**外部の応答を待つ時間と、大量のデータを読み書きする時間は含めない**という除外を 2 つ足す。

そのうえで、**計算量の制約を非機能要求 `NFR-013` として新設する**（`GL-003` の子）。
対象の処理は**新しい表 T-050** が持ち、判定に使う規模は**表 T-025 に足す `MC-9`** が持ち、
測る節目は**表 T-043 に足す `PG-13`** が持つ。

**目標には計算量を書かない。** 利用者の原案は 3 文とも `GL-003` に入れるものだったが、分けることに利用者が同意した（§2）。

⚠️ **「ぬるサク」を用語辞書へ足すのは `CR-105` である。本 CR は辞書を触らない。**
**本 CR は `CR-105` より後に適用すること** —— 先に適用すると、目標が辞書に無い語を使う状態になる。

## 2. 変更の背景・目的

### 2-1. 対象が狭かった

現行の `GL-003` は対象を **ズーム・パン・ドラッグの 3 つ**に限っている。**同じ狭さは過去に一度指摘されている** ——
`docs/review/requirement-gaps-2026-08-12.md:131`（`G-2`）と `:140`（`H-3`）が
「`NFR-002` / `NFR-003` の対象がズーム・パン・ドラッグに限られている」「ホバー中のヒットテストが計測対象外」を挙げ、
**`H-3` は「訂正」として扱われている。** そのときは測る側（表 T-025 の `MC-8`）に範囲選択とポインタ移動を足して塞いだが、
**目標そのものの文言は 3 つのままだった。** 本 CR は同じ穴を目標の側で塞ぐ。

### 2-2. 除外を書かないと、目標が守れない約束になる

「どの操作を行っても」へ広げると、**ファイルの読み書きと外部の応答待ちまで目標の中に入る。**
どちらも本ツールの計算では短くできない（前者はデータ量が決め、後者は相手が決める）。
除外を書かずに広げると、**達成できない約束を目標に置くことになる。**

### 2-3. なぜ計算量を目標に書かないのか（利用者と合意した分け方）

**利用者の原案は 3 文とも `GL-003` に入れるものだった。**
分けた理由は次の 2 つで、**利用者が同意した（2026-08-14）。**

| | |
|---|---|
| **目標は「達成された状態」を述べる場所である** | 「ぬるサク」は利用者から見える状態である。**`O(n log n)` は作り手から見た内部の性質**であり、利用者の状態ではない |
| **禁止は要求が持つ** | 「`O(n²)` を用いてはならない（MUST NOT）」は規則である。**本仕様書は規則の正を要求（Chapter 1 〜 4）に置く。** `GOAL` は文法上 `STATEMENT` しか持たず（`spec.sgra:10-20`）、`ORIGIN` も `RATIONALE` も `Relations` も持てない —— **禁止を置いても、根拠も測り方も紐づけられない** |

### 2-4. なぜ既存の `NFR` に足さず、新設するのか

**既存 12 件を全数読んだ**（§4-2 に一覧）。**計算量・規模の増え方に触れているものは 1 件も無い。**
`docs/spec` 全体を `計算量` / `O(n` / `log n` / `オーダー` で走査しても、当たるのは
`_assets/tbl-settings.md:287`（`S-120` の「稼働日の数え上げが計算量に効く」）**1 か所だけ**で、要求ではない。

**最も近いのは `NFR-002` / `NFR-003` だが、別のものを測っている。**

| | 測るもの | n の扱い |
|---|---|---|
| `NFR-002` / `NFR-003` | 平均フレームレート / 95 パーセンタイル | **n を 1000 に固定して 1 点だけ測る**（`MC-7`） |
| **`NFR-013`（新設）** | **n を変えたときの所要時間の増え方** | **n を動かす。これが要点である** |

**1 点で合格しても増え方は分からない。** `O(n²)` の実装でも n = 1000 なら通りうるので、
`NFR-002` / `NFR-003` に条件を足す形では書けない。**軸が違うので新しい要求にする。**

### 2-5. 測る対象を必ず定めること

⚠️ **本仕様書には「測る対象が定まっておらず合否を出せない `NFR`」が過去に見つかっている。**
`.claude/skills/spec-graph-check/SKILL.md:49-50` が、目標から降ろす観点の初回実行で
**「measurement target is undefined and so can never be judged」な `NFR` を 5 件**検出したと記録している。
実例も残っている ——

- `docs/review/requirement-consistency-2026-08-12.md:264`（`IC-39`）: `NFR-012` は外から観測できない
- 同 `:100-106`（`IC-37` / `IC-38`）: `NFR-011` の数値化は未了、表 T-025 に足す 3 行も未了

**したがって `NFR-013` は、対象（表 T-050）・規模（`MC-9`）・判定の式・測る節目（`PG-13`）を同時に置く。**
⚠️ **そのうえで「実測は計算量を証明しない」ことを要求の中に明記する**（§5-4）。
