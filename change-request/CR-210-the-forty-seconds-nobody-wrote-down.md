## 0. ⛔ 立ちどまって答える 3 つ（**検査 22 が空欄を許さない**）

### ① これは `CH-` / `GL-` のどれを前へ進めるか

⭐ **`CH-1`（作図ソフトと同じ操作感で描きながら、構造化した日程データを出す）。受ける目標は `GL-004`。**

⛔ **ファイルを開く操作は、人がファイル選択の窓を見ているあいだ何十秒も走り続ける。** ⚠️ **仕様はその時間について 1 文字も書いていない** ——

⭐ **`CH-3`（軽快に動かす）にも掛かる。** **`NFR-010` の「表 T-078 に無い契機でフレームを起こしてはならない」は、待っているあいだに何を起こしてよいかを決めていないと守れない。**

## 2. 何が欠けていたか（**逐語**）

### 2.1 仕様は非同期という語を 1 度も使っていない（**実測**）

```
docs/spec 全体で  非同期 / Promise / async / await / 待機  の出現回数 = 0
```

⭐ **`Promise` はすべて `src/` 側の決定である。** ⛔ **したがって「仕様は既に非同期を受け入れている」とは言えない。**

### 2.2 `CA-3` が挙げる 2 つの拒否は、待っているあいだ何も拒否しない

`05-07-design.md` の 表 T-071（逐語）:

```
| CA-3 | 許容する陳腐化 | **1 フレームぶん。** ⚠️ **フレームの途中で文書が変わることは無い** ——
        身振りの最中の書き込みは 表 T-035 の `AG-9` が、通知の配布中の書き込みは 表 T-067 の
        `WS-2` が拒否する |
```

⛔ **`AG-9` が拒否するのは身振りの最中、`WS-2` が拒否するのは通知の配布中である。** ⚠️ **ファイル選択が開いているあいだはどちらでもない。**

### 2.3 ⭐ 着地そのものは既に許されている（**表 T-078 に行が要らない理由**）

```
ファイル選択が閉じる → 文書が組み上がる → replaceDocument → WS-6 → FT-2
                                                              ⭐ 既に許された契機
```

⛔ **問題は「着地の契機」ではなく「待っているあいだ」である。**
