# CR-155 — 日付は日であり、時刻を扱わない

> ⛔ **未適用である。** 2 編集。`01-04-requirements.md` の 表 T-033 に 1 行、`FR-054` に 1 段落。
> ⭐ **利用者の裁定である。** W1 の実装で `Schedule` の 4 メンバ（`isDelayed` / `delayWorkingDays` / `workingDaysBetween` / `dateFromWorkingDays`）が書けずに止まったのが出どころである。

## 1. 何が決まっていなかったか

**日付をモデルが何として持つか。** 3 つの要求が同時に掛かり、素直に実装するとどれかが破れていた。

| | 実測した根拠 |
|---|---|
| **① そのまま書き戻せ** | 交換相手に面した**日付列 12 本すべてが `Own`** —— `erd.schema.json` が「取り込んだ値をそのまま書き戻す」と定義する出自である。`Consume` は 0 本 |
| **② 書式を変えるな** | `EX-4`（`:2883`）「取り込んだ値の書式を踏襲すること（単位・**日付の形式を勝手に変えない**）」／ `EX-2`（`:2881`）「編集していないタスクの値を**書き換えてはならない（MUST NOT）**」 |
| **③ 解釈しないと計算できない** | 遅れの量は**稼働日**で数え（表 T-021b）、`actualDuration` は**稼働日の整数**、フェードは**日数**、横軸は 1 日の幅（`S-1`）。`S-128`（1 日 = 480 分）は交換相手の時間量へ**換算するため**に在る |

### 交換相手の型（公式 XSD をローカル複製で実測）

| | |
|---|---|
| `Start` / `Finish` / `Deadline` / `ActualStart` / `ActualFinish` / `Resume` / `StatusDate` / `CreationDate` / `LastSaved` / `FromDate` / `ToDate` | **すべて `xsd:dateTime`** |
| `xsd:date`（日付だけの型） | ⛔ **0 件** —— **時刻部分は必須である** |

## 2. 裁定

> **`GRS` は時刻を扱わない。日付の最小単位は日とする。**
> **`GRS` が書く日付の時刻は常に `00:00:00` とし、綴りは交換相手の型（`xsd:dateTime`）に合わせる。**

⭐ **取り込んだまま触っていない値は、入ってきた文字列のまま書き戻す** —— そうしないと `EX-2` と `FR-021` が破れる。実ファイルは 8:00 開始で入ってくるためである。
⭐ **したがって列は交換相手の文字列を持ち続け、日はそこから導出する。** 列が日だけを持つと 8:00 を書き戻せなくなり、往復が壊れる。**データモデルは 1 列も動かない。**

## 3. 何をするか —— 2 編集

### ① 表 T-033（書き出しの規約。`FR-057` が持つ）に 1 行

```text
| EX-7 | **`GRS` が書く日付の時刻は `00:00:00` とすること（MUST）。** 綴りは交換相手の型（`xsd:dateTime`）に合わせる。⚠️ **取り込んだまま編集していない値には掛からない** —— そちらは `EX-2` と `EX-4` が元の文字列のままを求める |
```

### ② `FR-054` に 1 段落（稼働日の数え方を持つ要求）

```text
**日付の最小単位は日とすること（MUST）。時刻を解釈してはならない（MUST NOT）** —— 期間も遅れもフェードも稼働日と日数で数えており（表 T-021b ／ `FR-012` ／ `FR-075`）、横軸の目盛も 1 日である。**交換相手の値から日を取るときは、字面の日付の部分を取ること（MUST）。時差を換算してはならない（MUST NOT）** —— 換算すると、書き出した日が取り込んだ日と 1 日ずれる機で入れ替わる。**時刻の部分は解釈せず、書き戻すためにそのまま保つ**（表 T-033 の `EX-2` / `EX-7`）。
```

## 4. 採らなかった案と、その理由

| 案 | 却下の理由 |
|---|---|
| **日付列を `Consume` にし、解釈した値だけを持つ** | ⛔ `EX-4` と `EX-2` を正面から破る。⚠️ **版 0.37 が `actualDuration` を `Own` → `Consume` にした前例は移らない** —— あれは「保存は稼働日の整数、相手は時間の量で、**そのまま書き戻すことが原理的にできない**」からであり、日付は**そのまま書き戻せる** |
| **解釈した値と元の文字列を両方 文書に持つ** | ⛔ 表 T-053 直後の「構造から決まるものを列にしないこと（MUST）」と同型。**CR-151 がちょうどこの理由で 2 列を落としたばかりである。** `FR-024` により文書の日付欄が倍にもなる |
| **解釈を使う場所ごとに置く** | ⛔ 生の文字列どうしを比べる実装が必ず出る。解釈は `Schedule`（`CP-1`）に 1 か所置く —— 表 T-062 が同コンポーネントに「**暦に従った稼働日の数え上げ**」を既に負わせている |
