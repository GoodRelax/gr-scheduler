# CR-302 — 仕様だけを読む体が見つけた 3 つの穴と、隙間を飛ばしていたパン

> **閉じるもの**: 台帳 D-138（縦のパンが行の隙間を飛ばす）／ 台帳 D-139（何も描かない文書が `FR-055` の言う日から開かない）。
> **直すもの**: CR-300 と CR-301 が書いた 3 か所の私自身の誤り。
> ⭐⭐ **この CR に載っている穴は、1 つも前に立つ者が見つけていない。**⛔ **4 つとも、実装した当人ではない体が見つけた。**

## 0. ⛔ 立ちどまって答える 3 つ

### ① この変更は `CH-` / `GL-` のどれを前へ進めるか

| | 進めるもの | なぜ |
|---|---|---|
| パンの隙間 | **`CH-3`（ぬるサク）** | 利用者の逐語（CR-260）が「**飛び飛びだと UI 上気持ち悪くて『ぬるサク』を達成できない**」である。行の境目で 8px 追い越す絵は、その逐語がまさに退けたもの |
| 何も描かない文書の日 | **`CH-5` / `GL-005`** | 単一の `.html` で配る構えでは、**同じ JSON がいつ開いても同じ絵を出す**ことが成立の条件である。`Project.startDate` を動かすと初回の絵が動いていた |
| 私の 3 つの誤り | **土台** | どれも「仕様書が自分自身と食い違っている」ことの後始末である |

### ② レビュー観点のどの条項を当て、何が出たか

| 条項 | 当てた対象 | 結果 |
|---|---|---|
| **`R1.3`**（唯一の正）| `S-176` と 表 T-023d の「錠の上にしか着地できない形にしてはならない（MUST NOT）」 | ⛔⛔ **2 つが正面から矛盾していた。**`S-176` は「行**自身の高さ**に対する比」で、**帯と帯は接していない**（実測: 送り − 高さ = 8, 8, 8, 8, 8）ので、**隙間に立つ上端をどう書いても名指せない** ⇒ その MUST NOT は満たしようがなかった |
| **`R1.2`**（曖昧・非検証）| CR-300 が `OP-10` に書いた「**この除外**」 | ⛔ **直後の一文の「この除外」と別のものを指していた。**同じ語で 2 つを指すと、どちらの話か読めない |
| **`R1.3`** | CR-301 が 表 T-023 の結びに書いた射程 | ⛔ **`MK-1` 〜 `MK-4` と書いたが、ホイールの行は `MK-5` まである。**⛔⛔ **さらに深い誤り**: `MK-2` 〜 `MK-5` は修飾キーを伴うので `MK-10`（画面全体で止める）が届き、結びの規則と正面から矛盾していた |
| **`R2.7`**（DRY）| `S-176` を px に戻す 2 か所 | ⚠️ **同じ分母が書く側（`rowAnchorAt`）と読む側（`scrollOffsetOf`）の両方に立つ。**⛔ **1 つにまとめられない** —— 2 つは別のコンポーネントに在り、 表 T-061 が一方から他方への import を禁じている。⭐ **重複を承知で残し、両方の注記が相手を名指すようにした** —— **1 つの全単射であり、片側だけ書き換えると絵が相手の名指さない場所へ行く。**⚠️ **今回の欠陥はまさにその形で出た**（片側だけ直した時点で、動く量が 帯 ÷ 送り = 7/9 になった）|
| **`R1.4`**（異常系）| `Task` を 1 件も持たない文書 | ⛔ **`FR-055` は「表示位置を `scrollDate` に合わせること（MUST）。`null` のときは実行日に合わせてよい（MAY）」と定めるのに、木は `Project.startDate`（`AT-12`）から描いていた** —— 同要求はその列を 1 度も名指していない |

### ③ 利用者に問わずに決めたこと（**覆してよい**）

| | 決めたこと | 何に載せたか |
|---|---|---|
| 1 | ⭐ **`S-176` の分母を「行が占める送り」にした** | ⚠️ **帯どうしを接させる案もあった。**⛔ 採らなかったのは、絵そのものが変わるからである。⭐ **送りにする案は 1 つの値の意味だけを動かし、しかも写像を全単射にする**（いまは隙間ぶんが写像の像に無い）。⚠️ **保存された数の意味が変わるが、往復（`NS-4`）は数そのものを比べるので壊れない** |
| 2 | ⭐ **ホイールの射程を 5 つに揃え、`MK-10` の例外であると明記した** | ⛔ **5 つを分けない理由を書いた** —— 同じ面の上で「素のホイールは面を送り、修飾を足したホイールは日程を動かす」という絵は読む人に説明できない |
| 3 | ⭐ **何も描かない文書の足場の日を `scrollDate` → 実行日 の順にした** | ⛔ **日を落とすことはできない**（`S-77` が時間軸を固定しないとレイアウトが測れない）。⭐ **実行日は `FR-055` が明示で許した唯一の場合である** |

## 5. ⚠️ 決めずに残したもの

体が「仕様に行が無いので書かなかった」と報告した穴が 6 つある。⛔ **どれも発明していない。**

1. **行の削除を単体試験から押せない** —— `FR-032` が行見出しパネルと確認の裏に置いている。⚠️ 表 T-050 の `CD-2` は「選ばれていない `Task` が消える」唯一の入口であり、表 T-023c の結びの 2 つ目の MUST NOT がまさにその形を述べている。
2. **表 T-023c の結びは「いつ落とすか」を定めない** —— 毎フレーム選択を空にする実装も満たしてしまう。
3. **`SWS-` 節点が無い** —— Chapter 6.1 に 8 つあり、矩形にもパンにも届かない。⛔ **体は起こさなかった**（正しい）。
4. **矩形の角の許容が無い。**
5. **パンが文書の端で止まるかを述べた行が無い。**
6. **`FR-011` が「稼働日でない日に始まる期間」を定めない** —— 数え方が 2 通りあり、1 日ずれる。
