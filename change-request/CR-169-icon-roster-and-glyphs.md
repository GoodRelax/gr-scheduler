## 2. 何をするか

**新しい要求は立てない。表を 1 つ、図を 1 つ足し、`FR-029` の指す先を仕様書の中へ向け替える。**

### (1) 図 F-019 — アイコンの図形（新設。`_assets/fig-icons.svg`）

**57 個の図形を 1 枚に並べ、各図形の下に行 ID だけを刷る。** 語も要求 ID も刷らない。
⭐ **本図は本仕様書が持つ原稿であり、生成物ではない** —— `_assets/source/build.py` が読むのは `components.json` と `overview.json` だけで、本図に触れない。5.2 と 6.2 の「生成物を手で直してはならない（MUST NOT）」は掛からない。
⭐ **図形は本プロジェクトが起こしたものであり、第三者の素材ではない**（表 T-003 の `CN-7`）—— 参照先に素材集の名は 1 つも現れず（`feather` / `lucide` / `material` ほかで 0 件）、8 つのマイルストーンの図形は 1 つの外接円に内接し、☆ の内外比は `S-48` の 0.45 である。**本プロジェクトの設定値と一致する図形が第三者の素材であることはない。**
⛔ **第三者のアイコン集から図形を差し替えてはならない** —— `CN-7` に触れ、線の太さと作画の格子が 1 家族でなくなる。

**⛔ Mermaid は使えない。** Mermaid は節と辺の図を描く記法であり、**任意の図形を表す構文を持たない** —— 角を丸めた矢羽根も、外接円 7.5 に内接する五角形も、内外比 0.45 の ☆ も書けない。
**⭐ SVG は新しい形ではない。** `_assets/` は既に `fig-components.svg` と `view-*.svg` を持ち、図 F-014 〜 F-017 が本文から直接それを参照している。**`_assets/fig-*.md` の包みは作らない**（A-appendix 0.16 が廃した形であり、`_assets/` の新しい `.md` は StrictDoc に 1 つの文書として拾われる）。

### (2) 表 T-109 — アイコンの名簿（新設。`_assets/tbl-glossary.md` の §8）

**列は `行 ID | 面 | 群 | 何の入口か | 正` の 5 列、61 行。**

⭐ **図と表は違う事実を持つので、2 か所管理にならない。**

| | 何の正か |
|---|---|
| **図 F-019** | **各アイコンの図形**。それだけである。要求も語も持たない |
| **表 T-109** | **どのアイコンが在るか・どの面のどの群に在るか・何の入口か・どの要求が持ち主か**。⛔ **図形を語で説明しない**（1.9）|
| **繋ぎ目** | 行 ID `IC-nn`。図では各図形の下に刷り、表では第 1 列に立つ。**鍵は写した事実ではない** |

⛔ **`確定名` の列を持たない。** 持つと 57 個の英名を新たに確定させることになり、
(i) 表 T-103 / T-104 が持つ確定名の体系に断りなく足すことになり、
(ii) **`milestoneGlyph` の 8 つの綴りは CR-172 が利用者の裁定に回した未決事項**なので、ここで先に綴ると裁定を奪う。
**表 T-012 の `SH-5` が既に書いている表記（〇 / 六角形 / 五角形 / ◇ / □ / ☆ / △ / ▽）だけを使う。**

⭐ **`面` の欄は 表 T-103 の確定名を使い、新しい面の名を作らない。**
⭐ **`IC-4`（変更前の予定）は「重ねの表示を切り替える」入口であって、ファイルを読む入口ではない。**
仕様書が自分で決着している —— 表 T-024a の `OP-9` が「選ぶ入口は `OP-3` の第 3 の選択肢である」と書き、`OP-2` が読む入口を 1 つに定めている。**`baselineVisible`（`S-69`）は 表 T-202 の真偽の行であり、`FR-049` の切替の対象である。** これで `OP-2` の断定が仕様書の中だけで確かめられる。

⚠️ **図形の無い 4 行は `IC-58` 〜 `IC-61` に置き、「未描画 🔎」と書く。** 図形をここで発明しない —— 発明は利用者がしていない設計の裁定である。
