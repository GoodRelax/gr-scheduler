### 2-4. ユニットの分割基準は純粋性だけである

**`R7.9`（SHOULD）の原文** —— 「純粋性でユニットを分割しているか（純粋な core と非純粋な shell を別ファイルに）」。

### 2-5. どの部品もインスタンスを作らない —— `LY-5` の帰結である

**`LY-5` の原文** —— 「**現在値を保持するのはこの層だけである** —— 内側の 3 層はすべて値を引数で受け取る」。

**保持する状態が無いのだから、作るべきインスタンスも無い。公開するのは型と関数だけになる。**
⭐ **これにより `R2.19` の 3 条目「公開面が内部の実装詳細（内部専用の型・可変状態）を漏らしていないか」は、内側の 3 層では起こり得ない** ——
**漏らせる可変状態がそもそも存在しないためである。**

### 2-6. `UseCase` の操作の名前 —— 部品名を camelCase にする

**`R2.1` は 2 つのことを言っている。**

| 表 | 何を定めるか | 本件への適用 |
|---|---|---|
| **品詞の規約** | クエリ（`pure`）は名詞句、コマンド（`non-pure`）は動詞＋目的語 | 関数の品詞 |
| **レイヤー別のコンポーネント・クラス名** | **`Use Case` は動詞句**（`ConvertUnit` / `PlaceOrder`） | **部品とユニットの名前** |

**`UseCase` の部品は `pure` でありながら動詞句である**（`EditTask` / `UndoEdit`）。**層別表のほうが層を名指ししており、こちらが効く。**
**そのうえで、公開する操作に別の名前を与えると 1 概念 2 語になる**（1.9 の `:292`）。
**したがって操作は部品名を camelCase にしたものとする** —— `EditTask` → `editTask`。**表 T-006a の `W-1` と `W-2` の違いにすぎず、食い違いではない。**

⚠️ **`semi-pure-b` のメンバだけは品詞の規約が勝つ**（`R2.1`「**副作用が無いことと、呼んで安価であることは別である**」）——
`exportPng` / `exportEmbeddedHtml` / `openDocumentFile` / `restoreDocumentSnapshot` は動詞＋目的語である。

### 2-7. 4 つの名前が 表 T-107 と同じ語になるのは正しい

**`importDocument` / `undoEdit` / `redoEdit` / `watchChanges` は 表 T-107 の `AM-8` / `AM-9` / `AM-10` / `AM-17` と同じ語である。**
**同じ概念だからであり、1.9「1 つの概念には 1 つの語しか与えない」がまさにこれを求めている。**
⚠️ **`Agent API` の面（外向き）と `UseCase` の面（内向き）で綴りが違ったら、そちらが誤りである。**
