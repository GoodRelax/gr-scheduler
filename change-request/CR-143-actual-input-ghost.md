# CR-143 — 実績入力のダミーと、未着手のマーカー

> ⛔ **未適用である。** 本書は設計の裁定と編集の草案であり、`docs/spec/` にはまだ 1 文字も当たっていない。
> **編集一覧は逐語検証（`count=1`）をまだ通していない。** 当てる前に §7 の手順を踏むこと。

**閉じるもの**: 実装着手前レビューの **F-4**（掴んで着手したときの `actualDuration` の量が決まらない）。

## 1. 何をするか —— 2 つある

**① 未着手のタスクに、実績の掴みシロ（ダミー）を薄く出す。** どちらを掴んでも実績が確定する。
**② 未着手にも進捗マーカーを出す。** これで**掴む的と押す的が完全に分かれる。**

```
実績があるとき   | ------ |  ( )      掴みシロ 2 つ ＋ マーカー
予定しかないとき  ||        ( · )      ダミー 2 つ ＋ 薄いマーカー
```

**マーカーは実績バーの右端の外側にある**（`GR-7`）。**掴みシロはバーの両端。位置は元から被っていない。**

## 2. なぜ入口がマーカーを兼ねていたのか（＝何を直すのか）

`PM-1a` が「**未着手はマーカーを出さない**」と決めていた。押す的が無いので、`FR-043` の入口に役を兼ねさせていた ——

> **本要求の入口は、未着手のあいだ進捗マーカーの役も兼ねる**（表 T-021 の `PM-1a`）。したがって**未着手のタスクの状態を変える経路は、画面上で直接掴む経路のうちでは本要求の入口が唯一である**

**`PM-1a` に記号を与えれば、この兼任も「唯一の経路」という但し書きも要らなくなる。** 状態機械が一様になる —— **どの状態でもマーカーを押せば巡り、どの掴みシロも掴むだけ。**

⚠️ **`PV-1`（未着手 → 完了）・表 T-021a の 4 行・図 F-018 の辺は 1 つも動かない。** 押す的が入口からマーカーへ移るだけである。

## 3b. ⭐ 遅れている未着手タスクの `(!)` をマーカー位置へ移す（利用者の裁定）

**いまの `FR-043`（`:1945`）はこう定めている:**

> **そのタスクが遅れていると判定されたときは、入口を `(!)`（表 T-021 の `PM-4`）の形にすること（MUST）**
> ⚠️ **`(!)` は進行中・中断の遅れと同じ記号なので、未着手であることは位置が担う** —— 入口は**タスクの上**、進捗マーカーは**実績バーの右端の外側**にある。

**未着手にマーカーを与えると、この「位置で見分ける」規則が崩れる** —— `(!)` がマーカー位置へ移り、進行中の遅れと同じ記号・同じ位置になる。

**裁定: `(!)` をマーカー位置へ移す。**「未着手であることは**実績バーの有無**が担う」に書き替える。

**根拠** —— 未着手のタスクには実績バーが無い（薄いダミーが 2 つあるだけ）。進行中には実物のバーがある。**バーの有無のほうが位置より確かな手がかりであり、記号の位置が状態によって動かなくなるので規則が 1 つ減る。**

## 5. なぜこの形が仕様と噛み合うか（実測）

| | |
|---|---|
| **幾何** | `GR-7`（進捗マーカー）の場所は「**実績バーの右端の外側**」。掴みシロは両端。**被らない** |
| **薄い操作子には前例がある** | 表 T-051 の `HF-6`「操作子は薄く描き、ポインタが乗っているあいだだけ濃くすること」。`FR-053` も同じ |
| **⚠️ 薄さだけで分けない** | `FR-030` が「色だけで伝えない」を求める（`GD-6` が実線／点線で実現している）。だから `PM-1a` に**形の違う記号**を与える。薄さは補助に留める |
| **1 稼働日 ＝ 9/1→9/2** | `FR-012` の `round(actualDuration ÷ (finish − start) × 100)` は引き算なので**終了日は排他**。予定側と数え方が割れない |
| **「開始のみ・終了のみ」は起きない** | 表 T-019 の 5 状態は `actualStart` と `actualDuration` が常に一緒に空／一緒にあり。**規則を足さずに保証されている** |
| **右端は `actualStart` ＋ `actualDuration`** | `FR-011` と `PL-5` がそう定め、`GR-6` も `actualDuration` を書く。⚠️ **`actualFinish` は `PA-5`（完了）でしか入らない**（`AT-36`） |
| **0 長でも消えない** | マーカーは 16px 固定（`markerSize`。CR-137）。幅 0 でも印が残る |
| **マイルストーンは点** | `SH-5` が実績バー「なし」、`GD-4` が「点なので重なる概念を持たない」、`:977` が「点と期間で持つデータが違う」 |

## 8. 残る懸念

| | |
|---|---|
| **`FR-012` の分母** | 完了率 `actualDuration ÷ (finish − start)` は、マイルストーン（`start` ＝ `finish`）だと**分母が 0** になる。**本 CR の前から在る穴。**`milestoneActualDuration` を決めるなら同時に閉じるのが自然だが、別件として起票してもよい |
| **`PM-4`（遅れ）との重なり** | `PM-4` は「他の行と必ず同時に成立し、印は 1 つしか出ない」と定める。**未着手が記号を持つようになると、未着手かつ遅れのときに `PM-4` が勝つ** —— これは既存の規則どおりで矛盾しないが、`PM-1a` の「遅れているときを含む」という但し書きは書き替えが要る |
| **濃さの値そのもの** | ⭐ **決め打ちしない。**🔎 を付けて暫定とし、表 T-026 の `RC-` で「実物を触って選び直す」対象にした。**これは先送りではなく、この仕様書が持つ正規の作法である**（`RC-1`「🔎 付き既定値は…外すのではなく**選び直す**対象である」） |
| **中間色へ移るとき** | 濃さで足りないと分かったら、予定と実績の中間色へ移る。⚠️ **そのときは `themeHue = 214` で測り直しが要る** —— 測ってあるのは 実績 ÷ 予定 ＝ 4.81 : 1（ライト）だけで、中間色は測られていない |
