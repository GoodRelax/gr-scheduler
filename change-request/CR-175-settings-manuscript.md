## 3. 何をしたか —— **5 段。各段の終わりで全検査を通した**

### S1 —— 原稿を `_source/` へ移し、`npm run gen` を置いた

⭐ **原稿は言語に属さない。** `_assets/` は日英で分かれるので、そこに原稿を置くと原稿が 2 つに割れる。
`docs/spec/_assets/source/` → **`docs/spec/_source/`**。

⛔ **移動の途中で本物の破損を捕まえた** —— 生成器の区間の印が
`// <generated from docs/spec/_assets/source/erd.json …>` と、**印そのものにパスを埋めていた。**
パスを変えた瞬間に印が一致せず、`region()` が「区間がまだ無い」の枝に入り、**置換ではなく追記**した
（`schedule.ts` が **+344 行 / −0 行**、内容が丸ごと二重）。⚠️ **typecheck も検査も通る形の壊れ方である。**

**直しは 2 つ**: 印からパスを外し（`// <generated -- do not edit by hand>`）、パスは毎回書き直される本体側へ移した。
知らない印を見つけたら**追記せず終了コード 1 で落ちる**ようにした。

### S2 —— `settings.json` を原稿にし、`tbl-settings.md` を生成物にした

⭐ **移送は「人が転記」でも「エージェントが転記」でもなく、パーサを書いて往復で証明した。**
135 行を手で写せば誤りが混じり、**混じったことを誰も検出できない。**

| | |
|---|---|
| 受け入れ条件 | ⭐ **`md → settings.json → md` がバイト一致** |
| 結果 | **一致した。** `git diff` に `tbl-settings.md` が現れない |

⛔ **往復が捕まえたもの** —— 空セルを原文は `| |`（空白 1 つ）で書いており、`' | '.join` は `|  |`（2 つ）を出す。
**S-122 と S-123 の 2 行だけがズレた。** ⚠️ **人の目視でも 21 検査でも絶対に出ない差である。**

`settings.schema.json` を置き、⭐ **原稿自身を検査できるようにした。** ⚠️ **検証器が落ちることも確かめた**
（列のセル欠落 → `T-201 row S-1: no cell for max`、表に無い列 → `blocks/1/rows/1: Additional properties …`）。

`kind` での分岐に変え、160 字で切った。

**書き手の精度は値の一部である。**
