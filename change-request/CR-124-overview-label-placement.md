# CR-124 — 全体図の辺ラベルが部品名を隠すのを、ラベルの位置を動かして直す

## 1. 変更概要

**図 F-013（全体図）で、部品 `RedoEdit` の名前が辺ラベル「geometry only」に完全に隠れている。**

| # | 決めること | 置き場 |
|---|---|---|
| ① | **`build.py` に「ラベルの置き場を探す」段を足す** —— 辺ラベルを自分の辺に沿って動かし、どの部品の箱にも当たらない位置に置く | `_assets/source/build.py` |
| ② | **置ける位置が見つからない辺があれば build を止める** —— 黙って隠れたまま出さない | 同上 |

**`model.json`（SSOT）は 1 バイトも変えない。矢印も 1 本も消さない。**

## 2. 変更の背景・目的

### 2-1. 実測 —— 隠れているのは 2 本である

**`.drawio` の座標から、辺ラベルの位置（経路の中点）が部品の箱の内側に入るかを計算した。**

| 図 | ラベル | 箱に乗る |
|---|--:|--:|
| **図 F-013（全体）** | **8** | ⛔ **2** |
| 図 F-014（書き込み） | 18 | 0 |
| 図 F-015（読み取り） | 11 | 0 |
| 図 F-016（出し入れ） | 15 | 0 |
| 図 F-017（起動） | 15 | 0 |

| 辺 | ラベル | 隠している部品 |
|---|---|---|
| `Adapter → layoutEngine` | **geometry only** | ⛔ **`RedoEdit`**（指摘された箇所） |
| `UseCase → documentModel` | **updates** | ⛔ **`ScheduleGeometry`**（気づかれていなかった 2 件目） |

### 2-2. 原因は構造的である

**8 本の矢印すべてが x = 1768 の 1 本の縦の通路を走る。**
**draw.io は辺ラベルを経路の中点に置く**ので、**その矢印が通り抜けるだけの帯で、たまたま箱に当たった 2 本が隠れる。**

**引継書はこれを既知の罠として記録していた** ——「**層を飛び越す矢印のラベルは、途中の帯の箱に乗る。間隔を変えても解消しない**」。
**間隔（`node_separation` / `rank_separation`）を変えても中点は通路の上に留まるので、その記録は正しい。**

### 2-3. なぜ矢印を消さずに済ませるのか

**利用者は「矢印を削除してもよい」と述べたが、消さずに済むなら消さないほうがよい。**

⚠️ **`geometry only` は 5.1 が名指しで挙げている例そのものである**（`05-07-design.md:39`）——

> 層を飛び越す例（`LR-1`）—— SVG を作る部品は `Adapter` にあるが、`UseCase` を通らずに `layoutEngine` を直接読む。

**この矢印を消すと、5.1 の本文が挙げる唯一の例が図から消える。**

### 2-4. なぜ `draw.py` を直さないのか

**`draw.py` は共有スキル**（`~/.claude/skills/drawio-uml/scripts/`。`gr-tools/drawio-uml` と**バイト一致**）である。
**本プロジェクトの都合で書き換えると、他のプロジェクトの図に影響する。**
**`build.py` が生成後の `.drawio` に手を入れるほうが、影響が本プロジェクトに閉じる。**

⚠️ **これは「`.drawio` を手で直さない」に反しない。** 直すのは**人ではなく `build.py`** であり、`model.json` から毎回同じ結果が出る。

## 3. 変更箇所

| # | 対象 | 中身 |
|---|---|---|
| 1 | `docs/spec/_assets/source/build.py` | **ラベルの置き場を探す関数を足し、`draw()` の中で `.drawio` を書き出した直後・SVG に変換する前に呼ぶ** |
| 2 | `docs/spec/_assets/source/fig-components.drawio` ／ `docs/spec/_assets/fig-components.svg` | **再生成される** |

⚠️ **変更しないもの** —— `model.json`（**SSOT**）／ `overview.json` の辺 8 本 ／ 経路図 4 枚（**中点が箱に当たらないので動かさない**）／
仕様書の本文（`05-07-design.md` は 1 バイトも変わらない）／ `draw.py`（共有スキル）。

## 4. 変更前の仕様

**`build.py` の `draw()` は `draw.py` を呼んで `.drawio` を書き、そのまま draw.io で SVG に変換する。**
**辺ラベルは `<mxCell ... value="geometry only">` として辺そのものに載り、draw.io が中点に描く。**

## 5. 変更後の仕様

### 5-1. ラベルの置き場を探す

**辺ごとに、経路上の位置を 0.50 → 0.60 → 0.40 → 0.68 → 0.32 → 0.76 → 0.24 → 0.84 → 0.16 の順に試し、
どの部品の箱にも入らない最初の位置を採る**（0.50 が中点。既定のまま置ける辺は動かさない）。

**採れた位置は、辺の子として `edgeLabel` のセルに書く** —— draw.io の `mxGeometry` の `x` は
辺に沿った相対位置（`-1` が始点、`0` が中点、`1` が終点）なので、割合 `f` に対して `x = 2f − 1` を書く。

### 5-2. 置けなければ止める（②）

**9 通りすべてが箱に当たる辺があれば、`build.py` は `sys.exit` で止まる。**
**「黙って隠れたまま出す」ことをしない。**これは「裏づけの無い矢印は描けない」と同じ性質の門番である。

## 8. 反映記録（2026-08-15）

**`build.py` に `place_labels()` を足し、`draw.py` が `.drawio` を書いた直後・SVG へ変換する前に呼ぶようにした。**

### 8-1. 動いたラベル

```
labels moved clear of the boxes: geometry only@0.60, updates@0.40
```

**動いたのは 2 本だけである。**残り 6 本は既定の中点（0.50）で箱に当たらないので、**1 ピクセルも動かしていない。**
**経路図 4 枚（ラベル 59 本）は 1 本も動かなかった** —— `place_labels()` が「動かすものが無い」と判断してファイルを書き換えなかった。

### 8-2. SVG で検算した（**判定器が効いていることも確かめた**）

**書き出された SVG から部品の箱 33 個と辺ラベル 8 個を拾い、座標で重なりを測った。**

| SVG | 箱に乗るラベル |
|---|--:|
| **反映前**（`git show HEAD:` で取り出した） | **2 本 / 8 本** ——「geometry only → `RedoEdit`」「updates → `ScheduleGeometry`」 |
| **反映後** | **0 本 / 8 本** |
| 経路図 4 枚（反映後） | **0 本 / 59 本** |

⚠️ **判定器が空振りでないことを確かめた。** 最初に書いた検査は箱を 0 個しか拾えず、
**中身が無いまま「かぶらず」と出していた。**`data-cell-id="n_…"` で拾い直したところ 33 個を拾い、
**反映前の SVG に対して正しく 2 本を検出した。**「0 件」はこの検査が実際に検出できる状態で得た 0 件である。

### 8-4. 仕組み

**辺ラベルを、辺の子の `edgeLabel` セルへ移し、`mxGeometry` の `x`（`-1` が始点・`0` が中点・`1` が終点）に
割合から換算した値を書く。**`geometry only` は 0.60 → `x = 0.2`、`updates` は 0.40 → `x = -0.2`。
**SVG の側では `data-cell-id="edge1-label"` として出る**（動かさなかった辺は `data-cell-id="edge5"` のまま）。

**置ける位置が 9 通りすべて塞がっていたら `sys.exit` で止まる。**今回は使わなかったが、
**将来 部品が増えて隠れる辺が出たら、黙って隠れたまま出ずに build が落ちる。**
