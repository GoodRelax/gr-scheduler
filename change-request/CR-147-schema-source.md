## 1. 出どころ

**利用者の裁定 (b) である** —— **JSON Schema は生成器が 2 原稿（`erd.json` ＋ `_assets/tbl-settings.md`）を読んで出す。** 版 0.40 の判定（詳細仕様に入れる／BLOCKER 0 件）のあと、波で流す準備を調べて出た 3 つの穴の 2 つ目にあたる。

直す行は `docs/spec/05-07-design.md:724` の 1 行である。逐語は次のとおり。

```
> 未記入。上の図と表から JSON Schema を起こす。
```

⛔ **「上の図と表」は起こす先になれない。** 図 F-011 と 表 T-056 〜 表 T-059 は `_assets/fig-erd-detail.md` にあり、**同書の先頭には「本書は `_assets/source/erd.json` から `erd_json_to_md.py` が書き出す。手で直さない」と書いてある**（`:6`）—— 生成物である。原稿は `erd.json` の側にある。

**原稿の実測**（本 CR で数え直したものだけを載せる）:

| 調べたもの | 実測 |
|---|---|
| `erd.json` の規模 | entities **18** ／ columns **140** ／ relations **23** ／ derived **10** |
| 列の鍵 | **7**（`name` / `type` / `nullable` / `key` / `origin` / `exchange` / `meaning`）。`erd.schema.json` が 7 つとも必須にし、`additionalProperties` は `false` |
| `type` の異なり | **27 種。すべて日本語の散文である** —— `整数（0〜8）` `文字列（16 字以下）` `連想（文字列→文字列）` `{ dx, dy }` など |
| 列挙の列 | **5 列。うち 3 列は値を 1 つも持たない**（`列挙（5 値）` `列挙（8 値）` `列挙（2 値）`）。残る 2 列も 1 値だけを示す（`列挙（'left' ほか 3 値）` `列挙（'thin' ほか 3 値）`） |
| `nullable` の異なり | **8 種。これも日本語である** —— `可` `否` `否（空可）` `可（null = 根）` ほか |
| 見せ方の群 | ⛔ **`erd.json` に entity として存在しない。** 図 F-010 の器に 2 行（`scrollGroupId` → `S-78`、`pinnedGroupIds` → `S-126`）があるだけである |
| `_assets/tbl-settings.md` | **344 行・16 表・`S-` の行 134。** 既定値の欄は `rulerFont × 3 + 6（S = 42 / M = 48 / L = 54）` のような式と条件を含む |

⛔ **`erd.json` のままでは型を生成できない。** 原稿の作りを定める `erd.schema.json` が、`type` の説明として **「Written for a reader, not for a compiler.」**（読み手のために書く。コンパイラのためではない）と自ら書いている（`:231`）。**読み手向けの散文からは、列挙の値も範囲も機械的には取り出せない。**

⛔ **設定値表を機械可読な原稿へ持ち上げる案は却下された。** `tbl-settings.md` は 344 行の値表であり、既定値が式と条件を含む。**全体を移し替えるのは大工事で、目的（型を 1 つの起点から起こす）から遠い。** 見せ方の群は、いまの表の形のまま読む。

**守る形は既にある。** 検査 16 が `erd_json_to_md.py --check` を走らせ、**`erd.json` から作り直した結果と 2 つの生成文書が一致すること**を確かめている（`check.sh`）。スキーマにも同じ形を掛ける。

⚠️ **Chapter 6.2 の宣言と矛盾しない。** 同節は `:685` で **「設定値（`documentSettings`）の既定値と範囲は `_assets/tbl-settings.md`（`DOC-TBL-SETTINGS`）が持つ。本節はそこを指し、値を再掲しないこと（MUST NOT）。」** と定めている。**本 CR は値を 1 つも書かず、原稿を指すだけである。**

⚠️ **記法の縛りとも衝突しない** —— `01-04-requirements.md:296` が「**本仕様書を組み立てる道具**（`_assets/source/` の原稿と生成器、検査のスクリプト）**は同表の対象外とする**」と定めている。**同表とは 表 T-006a（面ごとの記法）である。** 原稿に機械可読な鍵を足しても、面ごとの記法の縛りは掛からない。⚠️ **エンティティ名と列名は 表 T-058 に出る本体の名前であり、これまでどおり縛られる**（本 CR はそこを 1 つも動かさない）。

⚠️ **コードは 1 行も無い**（`src/` も `package.json` も `tsconfig.json` も存在しない）。生成器も生成物もまだ無いので、**本 CR が定めるのは書き始めるときの起点だけ**である。

## 2. 何をするか

**未記入行 1 行を差し替える。表も行も図も UID も 1 つも増やさない。**

| | |
|---|---|
| **起こす先を書く** | **2 原稿から起こす**（MUST）—— 日程データの群は `_assets/source/erd.json`、見せ方の群は `_assets/tbl-settings.md` |
| **3 つ目の原稿を禁じる** | **値を写した 3 つ目の原稿を作ってはならない**（MUST NOT） |
| **原稿の側に条件を置く** | **日程データの群の原稿は、型・値の範囲・空を許すかどうかを機械が読める形で持つこと**（MUST）。⛔ **鍵の名前は書かない** —— 原稿の作りであって要求ではない |
| **見せ方の群は据え置く** | いまの表の形のまま読む。持ち上げを採らない理由を 1 文だけ残す |
| **生成物を守る** | **原稿から作り直した結果と一致すること**（MUST）。**手で直してはならない**（MUST NOT） |
| **器は器のまま残す** | ⭐ **スキーマ本体は生成物である。書いたことにしない。** 引用行を「原稿が機械可読になってから起こす」に書き替える。**`grep -n "^> 未記入"` の索きは効いたままである** |

**前後（`old` は 1 行、`new` は 6 段落）**

```text
BEFORE > 未記入。上の図と表から JSON Schema を起こす。

AFTER  **`GRS JSON` のスキーマは、原稿から起こす生成物とする（MUST）** —— 本節はスキーマ本体を持たない。図と表が持つ列の構成を 2 か所で抱えることになるためである。

       **起こす原稿は 2 つとする（MUST）** —— **日程データの群は `_assets/source/erd.json`、見せ方の群は `_assets/tbl-settings.md` である**。前者は 図 F-011 と 表 T-056・表 T-057・表 T-058・表 T-059 を書き出している原稿であり、後者は値の正である。⚠️ **どちらも既にあるものであり、値を写した 3 つ目の原稿を作ってはならない（MUST NOT）**。

       **日程データの群の原稿は、生成に要る型と、値の範囲と、空を許すかどうかを、機械が読める形で持つこと（MUST）** —— いまはそれらを日本語の散文で書いており、列挙の中には値そのものを持たない行がある。⚠️ **どの鍵をどう足すかは原稿の作りであり、本節は定めない**。

       ⚠️ **見せ方の群の原稿は、いまの表の形のまま読む** —— 値を機械可読な原稿へ移し替えると `_assets/tbl-settings.md` の作り直しになり、得るものに見合わない。

       **生成物は、原稿から作り直した結果と一致すること（MUST）** —— **生成物を手で直してはならない（MUST NOT）**。5.2 が `_assets/source/components.json` の生成物に同じ MUST NOT を定めている。

       > 未記入。原稿が機械可読になってから起こす。
```

## 3. ⚠️ 書かないと決めたもの

| | |
|---|---|
| **`.ts` の型** | ⛔ **起草は「JSON Schema と、それに対応する `.ts` の型は生成物とする（MUST）」と書いていた。落とした。** 利用者の裁定 (b) は **JSON Schema しか裁定していない**。`.ts` の型を生成物とする MUST は新しい規則であり、裁定を成り立たせるのに必須でもない（機械可読の MUST が既に足りている）。⭐ **型を生成器から出すこと自体は妨げていない** —— 仕様が命じないだけである |
| **機械可読な鍵の具体名** | `ts_type` のような鍵名を仕様に焼かない —— **原稿の作りが変わるたびに仕様を直すことになる。** ⚠️ ただし `erd.schema.json` は `additionalProperties` を `false` にして 7 鍵を必須にしているので、**鍵を足すときは同ファイルも広げる**。実装の作業である |
| **17 番目の検査** | `check.sh` に検査を足すのは実装作業である。**CR は「同じ形で守ること」を定めるところまで**にする |
| **設定値表の持ち上げ** | 却下済み（§1）。仕様には「いまの表の形のまま読む」だけを残す |
| **`FR-024` の書き替え** | 「`GRS JSON` にはどのエンティティも書き出す」は射程外である。**何を書き出すかは変えていない** |
| **変更履歴の行** | ⛔ **`A-appendix.md` の末尾は CR-146 / CR-148 と同じ席を取り合う。3 本を当て終えてから 1 回で書くこと。本 CR は席を取らない** |
