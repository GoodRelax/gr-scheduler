## 0. ⛔ 立ちどまって答える 3 つ

### ① この変更は `CH-` / `GL-` のどれを前へ進めるか

⭐ **`CH-1`**（作図ソフトと同じ操作感で描きながら、構造化した日程データを出す）である。
`FR-028` が `Agent API` を「人間向け UI と同格」と定めた時点で、機械が編集する道は既に `CH-1` の下にある。
MCP はその道に**標準の口金**を付けるだけで、能力を 1 つも足さない。

⚠️ **`GL-005`（1 つの `.html` をブラウザで開くだけで、サーバーもインストールも無しに編集できる）とは
正面からぶつかる。**
MCP サーバーは待ち受けるプロセスであり、ブラウザのページは待ち受けられない（3 節）。
⛔ **この衝突を隠して進めてはならない** —— 本書の推奨（3 節の A 案）は、
「MCP を使う人だけが `node` を足し、使わない人の `GL-005` は 1 ミリも動かさない」という形で
衝突を回避する案であって、衝突が無いという主張ではない。

⭐ **`CR-433` の `GP-1` が既に同じ地平を見ている** —— `01-04-requirements.md:1772` が
「⚠️ サーバーと連携したときは『自分のグループと一致するときは受け付ける』を足す」
「⛔ いま『自分のグループ』を仕様に持ってはならない（MUST NOT）—— `GL-005` の単体で動く `GRS` には
名乗る相手が無い」と書いている。
本書の 5 節 ① が決まると、この「いま持ってはならない」の**いま**が終わる。

## 2. 提案の核

**MCP は `Agent API` の上に載る薄い運搬層である。**

- tool は 表 T-107 の 18 メンバと **1 対 1**。名前も表の語そのまま。粒度を変えない・束ねない・足さない。
- 刻印（`DocumentStamp` の 3 値）を全 tool の引数と戻り値に載せる。
  MCP は 1 往復が独立した JSON-RPC なので、`AG-2` の楽観ロックとは相性が良い。
- 拒否は値（0 節 ③ の 3）。
- ⭐ **MCP 化で 1 つ消える問題がある** —— 将棋 PoC が踏んだ「日本語をシェル引数に載せると
  Windows で文字化けする」は、MCP では本文が JSON-RPC で渡るので**問題ごと消える**。
  `say.mjs --file` に相当する迂回は不要になる。

## 5. ⛔ 要検討事項（すべて裁定待ち）

### ① ⛔⛔ 日程の SSOT をどこに置くか —— これで本書の残り全部が変わる

| | いまの仕様 | 利用者が示した運用案（2026-09-21） |
| --- | --- | --- |
| SSOT | **ページの中**（サーバー無し。`GL-005`） | **サーバー上の JSON**（`GRSS`） |
| 編集経路 | 画面 と `Agent API` の 2 つ（表 T-070 の `MN-4`） | 4 つ —— (a) ブラウザで編集 (b) MCP で AI が編集 (c) `.html` を人がローカル編集してアップロード (d) 同じく AI が編集してアップロード |
| MCP の難しさ | **運搬が難所**（3 節の全部） | **難所が消える**。サーバー側の普通の MCP サーバーで済む |
| 代わりに要るもの | —— | **合流が主役**になる。版の親、3-way merge、ID の衝突、権限 |

⭐ サーバー案を採るなら、導かれる形は 1 つしかない ——
**`GRSS` を「GRS を走らせるサーバー」ではなく「文書の保管庫」にし、ドメイン中核（`entity` ＋ `use-case`）を
1 つのパッケージにして、サーバーとブラウザの両方で同じコードを走らせる。**
理由: (c)(d) を認める以上 `.html` は単体で完動せねばならず（中核はクライアント側に要る）、
(a)(b) を認める以上サーバーも検証と合流を裁かねばならない（中核はサーバー側にも要る）。
2 つ実装すれば `AG-5`（UI と同じ検証・同じ制限を通る）が破れる。
⇒ 中核は 1 つ、走る場所が 2 つ、となる。
1 節の (d) は、**それが今すぐ可能である**ことを測ったものである。

### ③ `watchChanges`（`AG-6`）の写し方

⭐ 将棋 PoC の `wait.mjs` が実装した意味論（自分以外が、自分の読んだ版より後に確定したものだけで起こす）が
そのまま `AG-6` になっている。形は既に在る。

### ④ `readDocument`（`AM-3`）の大きさ

文書まるごとが毎回モデルの文脈に載る。
資源（resource）として渡す／部分読みを足す、は「能力を足さない」原則と衝突する。

### ⑤ 合流の 3 択（表 T-032a の `MM-3`／`MG-9`）を誰が答えるか

`01-04-requirements.md:5058` の裁定は
「⭐ 呼ぶ側が機械であっても、選ぶのは人（MUST）。⛔ `Agent API` の呼び出しに、選択肢をあらかじめ渡させては

⚠️ ① でサーバー案を採ると、(d)（AI がローカルで編集してアップロード）は**人が居ない時刻に起きうる。**

### ⑦ 往復回数 と 18 対 18 の衝突

0 節 ② の `R5` で出た。
PoC の実測は「束ねろ」と言い、`R1.3` は「束ねるな」と言う。
⭐ 折衷案: tool は 18 のまま、`AgentWriteRequest` に発話を同梱できるようにして往復を 1 回に保つ。
⇒ 仕様の変更なので裁定が要る。

### ⑧ UID の衝突（① でサーバー案を採るときだけ）

⛔ **これが一番の地雷である。**
いまの裁定は「MSPDI の UID を主キーにする（代理キーを持たない）」であり、
**文書が 1 つしかない世界の裁定**である。
(c)(d) では 2 人が別々に持ち出して両方が同じ UID を採番できる。
合流した瞬間に参照が壊れる。
⇒ (i) 合流時にサーバーが振り直す（参照の書き換えが要る）／(ii) 出自 ID を持たせ〈出自＋UID〉で一意にする／
(iii) 採番をサーバーから借りる。
⭐ **いま決めれば安く、後で決めると全面改修になる。**

### ⑨ 版に親を持たせる（① でサーバー案を採るときだけ）

いまの刻印（`DocumentStamp` の 3 値）は「同じか違うか」しか答えない。
合流には「**枝分かれする前は何だったか**」が要る。
⇒ `GRSS` は版を追記のみのログ（各版 ＝ 全文スナップショット ＋ 親 ＋ 書いた者 ＋ 理由）で持つ。
日程データは小さいので全文で構わない。
