# CR-164 — 稼働日を数える暦を文書に 1 つと定める

> ⛔ **未適用である。利用者の裁定を受けて起草した。**
> **閉じるもの**: `RV-1`（実績バーの右端）を実装するのに要る「**どの暦で数えるか**」。
> ⭐ **裁定は「文書に 1 つ」である**（本セッション）。

## 1. 出どころ

`FR-011` が実績バーの右端を「`actualStart` に `actualDuration` を稼働日で加えた日」と定め、
表 T-069 の `RV-1` がそれを `ScheduleLayout` の担当と名指ししている。
`Schedule` は既に `dateFromWorkingDays` を公開しているが、**その引数に渡す暦を決める規則が無い。**

### ⛔ 仕様書が 2 つのことを言っていた

| どこ | 何と書いてあるか |
|---|---|
| `FR-054` の STATEMENT | 「**文書が持つ暦**に従って非稼働日を…区別して描くこと。期間の計算に用いる稼働日も**同じ暦**に従うこと」—— **単数** |
| `FR-054` の RATIONALE | 「取り込んだ暦があれば**それを文書の暦とする**」—— **単数** |
| `FR-088` の STATEMENT | 「稼働する曜日と例外日を**文書の暦**（`Calendar`）へ…反映すること」—— **単数** |
| ERD の `RL-9`（原稿 `erd.json`） | `Task.calendarUid` ＝「**このタスクが使う暦**」—— **タスクごと** |
| ERD の `RL-10` | `Resource.calendarUid` ＝「この担当者が使う暦」—— **担当者ごと** |

**両立しない。** タスクごとの暦を数え上げに使うなら `FR-054` の「同じ暦」が成り立たず、
文書に 1 つなら ERD の逐語が成り立たない。

⚠️ **`Task.calendarUid` の出自は `Consume`**（表 T-058 の `AT-33`）であり、
Chapter 5.4 は `Consume` を「取り込んで**解釈し**、書き出すときに作り直すもの」と定義している。
**「解釈する」が「稼働日の数え上げに使う」を含むのかが、どこにも書かれていない。**

## 2. 裁定 —— 文書に 1 つ

**`FR-054` の逐語を採る。** 決め手は 3 つである。

| | |
|---|---|
| ⭐ **要求の逐語が単数である** | `FR-054` は「文書が持つ暦」「同じ暦」、`FR-088` は「文書の暦」と、3 か所とも単数で書いている。ERD の辺のラベルは列の意味であって、導出の規則を持つ場所ではない |
| ⛔ **タスクごとにすると行の中で食い違う** | マルチバーは 1 行に複数の `Task` が載る。暦が `Task` ごとだと、同じ行の 2 本が違う日数で数えられ、**イナズマ線の頂点と遅れの日数が行の中で比較できなくなる**（`UC-006` が最も見たいもの）|
| ⭐ **数え方が 1 か所に閉じる** | 表 T-069 の注は「`RV-1` を求める `ScheduleLayout` も、完了率を格納する `EditDocument` も、実績の終了点を置き直す `GR-6` も、同じメンバを呼ぶこと（MUST）。数え方を 3 か所に書いてはならない（MUST NOT）」と定めている。**暦の解決も同じ理由で 1 か所に置く** |

## 3. 何をするか

### (a) `FR-054` に解決の順を足す（RATIONALE の直後に 1 段落）

```text
**文書の暦は 1 つとし、`Project.calendarUid` が指す `Calendar` とすること（MUST）。**
指していないとき、および指す先が無いときは、`isBaseCalendar` が真の `Calendar` のうち
`ordinal` が最小のものとし、それも無いときは表 T-209 の既定とすること（MUST）。
⚠️ **`Task.calendarUid` と `Resource.calendarUid` は、交換相手の値を往復させるために保持するだけであり、
稼働日の数え上げに使ってはならない（MUST NOT）** —— 使うと、同じ行に載る 2 つの `Task` が違う暦で数えられ、
イナズマ線の頂点（表 T-022）と遅れの日数（`FR-047`）が 1 つの行の中で比べられなくなる。
⚠️ **`Calendar.baseCalendarUid` を遡らない** —— 継承を解くのは取り込みの仕事であり（`FR-023`）、
描画のたびに解くと同じ答えを毎フレーム作り直すことになる。
```

⚠️ **`Calendar.baseCalendarUid` の辺（`RL-11`）は消さない。** 交換相手が持つ構造であり、往復に要る。

### (b) 表 T-064 の `PI-1` に 1 メンバ足す

`Schedule`（`CP-1`）が「暦に従った稼働日の数え上げ」を持つ（表 T-062 の `CP-1`）ので、
**暦の解決も同じコンポーネントに置く。** `RV-2` 〜 `RV-4` を `Schedule` に置いたのと同じ理由である
（日程データの群の列だけから決まる純粋な判定）。

```text
／ `workingCalendarOf`（文書の暦を解く。`FR-054`）
```

### (c) 原稿 `erd.json` の 3 か所の言い回しを直す

⚠️ **`fig-erd-detail.md` は生成物である**（検査 16）。**原稿を直して再生成する。**

| 対象 | 前 | 後 |
|---|---|---|
| `relations` の `Task → Calendar` | このタスクが使う暦（`calendarUid`） | 交換相手のタスクごとの暦（`calendarUid`） |
| `relations` の `Resource → Calendar` | この担当者が使う暦（`calendarUid`） | 交換相手の担当者ごとの暦（`calendarUid`） |
| `Task.calendarUid` の `meaning` | このタスクが使う暦 | 交換相手のタスクごとの暦。稼働日の数え上げには使わない（`FR-054`） |
| `Resource.calendarUid` の `meaning` | この担当者が使う暦 | 交換相手の担当者ごとの暦。稼働日の数え上げには使わない（`FR-054`） |
| `Project.calendarUid` の `meaning` | 既定の暦 | 既定の暦。文書の暦を指す（`FR-054`） |

## 4. ⚠️ 触らないと決めたもの

| | |
|---|---|
| **`origin` の欄（`Consume`）** | ⛔ **変えない。** 往復のために取り込んで書き戻す事実は変わっておらず、変えると表 T-058 の出自の欄と `FR-024` の書き出しに波及する。本 CR が決めたのは**導出に使うかどうか**であって、往復の扱いではない |
| **`Calendar.baseCalendarUid` の継承の解き方** | ⚠️ **射程外。** 取り込み（`FR-023` / `CP-10`）の仕事であり、W4 で決める |
| **`Project.weekStartDay`** | ⚠️ **無関係。** 週の目盛が書く日付の基準であり（`FR-054`）、稼働日の数え上げには効かない |
| **`Resource` ごとの暦を将来使うかどうか** | ⚠️ **表 T-039（後から足せるようにしておくもの）の話であり、本 CR は現在の導出だけを決める** |
