### 0.2 調べた結果（`842f3082`）

1. **いまの面。** `src/framework/file-system-access-file-store/file-system-access-file-store.ts:239` が開く面を `picker({ multiple: false })` で、`:457-465` が保存の面を `{ suggestedName }`（拡張子が分かれば `types` と `excludeAcceptAllOption: true` を足す）で呼ぶ。`id`・`startIn` はどこにも無い（`docs`・`src`・`tests`・`change-request` を `grep` して 0 件）。面を呼ぶ目的は 7 つ: 開く（`GRS JSON`・MSPDI、経路 `'chooser'` `:388`）・重ねる読み（`'baseline'` `:390`。取っ手を上書きする先にしない）・保存と書き出し（`'grsJson'`・`'mspdi'`・`'svg'`・`'png'`・`'singleHtml'`、`src/adapter/file-gateway/file-gateway.ts:56`）。上書き（`SK-11`）は持っている取っ手（`:417-440`、メモリだけ `:266`）へ面を出さずに書く。
2. **API が無いとき。** `window.showOpenFilePicker` か `showSaveFilePicker` が無ければ、面は `undefined` で、`FileStore` は「選ぶ面が無い（`CN-2` ／ `LM-14`）」を返す（`file-system-access-file-store.ts:233`・`:448`）。`<input type=file>` やダウンロードの代わりの道は無い。表 T-003 の `CN-2` は Chromium を対象にする。⇒ 本書は API の在る道だけを変える。
3. **仕様の枠。** `FR-060`（`01-04-requirements.md:6464-6484`）: 「⛔ 前回開いていたファイルを覚えてはならない（MUST NOT）」「⛔ そのためにファイルの取っ手を `localStorage` や `IndexedDB` へ保存してはならない（MUST NOT）」「⭐ 起動した直後の最初の保存で、人がファイルを選び直すのが本仕様である（MUST）」。`CR-572`（:60）は「好みを覚える別枠（`localStorage`）を足す案は、利用者が項目ごとに退けた（`JDG-624`・`JDG-625`）。⇒ 本書は別枠を 1 つも足さない」。表 T-206 の別枠（`localStorage`）は `S-99`・`S-99a`・`S-99b`・`S-99c` の 4 行。
4. **ブラウザの記憶（WICG File System Access、MDN）。** 面の `id` を渡すと、ブラウザは id ごとに最後のフォルダを覚える。`startIn` に取っ手を渡すと、ファイルの取っ手ならその親のフォルダ、フォルダの取っ手ならそのフォルダから開く。どちらも渡さないとき、ブラウザは id を空の文字列として同じく最後のフォルダを覚える —— 仕様どおりならいまの `GRS` でも覚えるはずだが、利用者の手元では毎回既定のフォルダに戻る（`JDG-998`）。⚠️ ブラウザの記憶は **起源（origin）ごと** である。`file://` の頁の起源が読み込みごとに変わるなら `id` は再読み込みをまたがない —— ⚠️ ただし反証がある: `docs/review/inventory/A03-agent-open-items.md:89` は、`file://` で取っ手を IndexedDB に入れて再読み込みしても残ったと記す（起源は読み込みごとに変わらなかった）。⇒ いまの `GRS` で既定のフォルダに戻る理由は、起源ではなく別（例: ブラウザが `file://` の起源について最後のフォルダを覚えない）かもしれず、理由は分かっていない。⇒ 見本 29 で確かめる（利用者が試している）。`startIn` に渡す取っ手は、理由によらず同じ起動の中なら効く。
5. **`id` の形。** WICG の仕様は、id を 32 文字以下の英数字・`-`・`_` に限る。
