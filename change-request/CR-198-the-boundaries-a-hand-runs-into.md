## 2. 何が壊れていたか（**逐語**）

### `a` —— 落とした日を稼働日へ寄せてよいかが読めない

`docs/spec/01-04-requirements.md:2306`:

```
| GR-6 | 実績の終了点 | 実績バーの右端 | actualDuration を変える（置いた日付から稼働日数を算出する） |
```

⛔ **出力の単位しか言っていない。** ⚠️ **すぐ隣の `FR-043`（`:1993`）が寄せる先例を作っている:**

```
終了点の掴みシロは、予定の開始日から S-129 ぶん進んだ稼働日に置くこと（MUST）
—— 暦に従う（FR-054）。暦日で進めると非稼働日に置くことになる。
```

⭐ **数えた** —— `スナップ` 0 件・`吸着` 0 件・`四捨五入` 0 件・`最も近い日` 0 件。**どちらとも書いていない。**

### `b` —— 「押しは受けない」が、裁定と正面から衝突する

`docs/spec/01-04-requirements.md:2309`（`GR-9` の末尾）:

```
掴めば actualStart と actualDuration を置く（値は FR-043）。押しは受けない
```

⛔ **`GR-17` と `GR-18` には押しの句が無い。** ⭐ **3 行が同じ族なのに、1 行だけが違うことを言っている。**

### `c` —— BOM の規則が、読む側と書く側で分かれていない

`docs/spec/01-04-requirements.md:157`:

```
| CN-5 | 文字コード | UTF-8・BOM なしとする。JSON は RFC 8259 が BOM の付加を禁じており、MSPDI XML も同じ扱いとする |
```

⭐ **`BOM` は仕様書に 2 行しか出ない**（数えた）。**もう 1 行（`:2838`）は書き出し側の MUST NOT である。**
⛔ **入力に BOM があったときどうするかは、どこにも無い。**

### `d` —— 一度に N 件来たときの規則が無い

⭐ **`OP-8`（`:3172`）と `MG-9a`（`:2912`）が覆うのは「取込の最中に次のファイルが来た」だけである。**
⛔ **`OP-2` が名指しする 2 つの経路（ファイル選択・ドラッグ＆ドロップ）は、どちらも一度に N 件を渡せる。**

### `e` —— ポインタから日数を出す規則が無い

⭐ **掴み点の場所は決まっている** —— 表 T-012a の多角形（`:1083`）で `GR-1` は点 4（`start + fadeIn`）、
`GR-2` は点 2（`end − fadeOut`）であり、**どちらも時間軸の上の「ある日」である。**
⛔ **その日から日数を出す規則が無い。**

### `f` —— 上限の表に、自動保存の回数の行が無い

⭐ **表 T-211 の題は「保存と受け入れの上限」である。** 自動保存の行は `S-112`（間隔 3000 ms）1 つで、
**残る 5 行はすべて取り込みの上限である。** ⛔ **回数の上限を探した者は、そこで答えを得られない。**

### `g` —— 委任先が空き地である

`docs/spec/01-04-requirements.md:2824`（`FR-021`）:

```
⚠️ どの正規化を用いるかは Chapter 6.1 が持つ —— 本要求が課すのは、比べる前に双方へ同じ正規化を当てることだけである。
```

⛔ **Chapter 6.1（`05-07-design.md:679` 〜 `:833`）が持つのは 表 T-220・表 T-221・表 T-222 と
`SWS-1` 〜 `SWS-5` であり、5 本とも描画の幾何である。** ⚠️ **変更履歴 `:69` が「委任は書いたが行き先は埋めていない」と自ら記録している。**
