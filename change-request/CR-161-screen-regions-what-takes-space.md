# CR-161 — 画面の各部のうち、何が場所を取るかを決める

> ⛔ **未適用である。**
> **閉じるもの**: `ScreenRegions`（`UF-58`）を書こうとして当たった穴。**`Row Area` の矩形が出せない。**
> ⭐ **利用者の裁定を受けている。⚠️ 起草の途中で 2 度、自分の推奨を取り下げている**（§3）。

## 1. 出どころ

**W2 の `ScreenRegions` は「画面の各部の矩形」を出す**（表 T-062 の `CP-35`）。そのうち `Row Area` は、`_assets/tbl-glossary.md` の `U-50` が **「`Schedule Canvas` から `Time Ruler` の帯と余白を除いた、`Rows` が並ぶ領域。左右は `Row Title Panel` と `Properties Panel` の内側」** と定めている。⛔ **この定義から矩形を出そうとすると、決まっていないものが 3 つ出る。**

| | 決まっていないもの | 実測 |
|---|---|---|
| (a) | `App Header` の高さ | `S-116 appHeaderMaxHeight` は **`56` px、範囲 32〜96**。⚠️ **属する 表 T-212 の題は「画面の各部の寸法の上限（`FR-051`）と、待ち時間」であり、上限であって高さそのものではない。** 高さを定める行が無い |
| (b) | `Scrollbars` の太さ | ⛔ **設定値にも要求にも無い。** 表 T-212 の行は 2 つ（`S-124` の待ち時間と `S-116`）だけである |
| (c) | `Panel Divider` の幅 | ⛔ **同じく無い** |

⚠️ **画面の構成を描いた図も無い**（図は `F-001` の構成の概要と、`F-010` 〜 `F-018` のデータと経路だけである）。**`MS-0`（M0 設計）が絵として決めると書いているが、それは節目の成果物であって仕様ではない。**

### ⭐ 前プロジェクトの PoC が、3 つとも実測で答えを持っていた

`previous-project-result/08-poc/poc-integrated.html` の逐語である。

**スクロールバー**（`:218` 〜 `:224`）:

```
Scrollbars -- always visible, half the environment default width.
  previous-project-result/03-ui-naming/ui-detail-spec-ja.md  5-2

Always visible because a scrollbar that appears and disappears changes the
canvas width, and a changed width re-runs the layout and moves the stacks.
Half width because something shown at all times must not eat the drawing
area at full size. Windows draws 17px by default, so 8px is the half.
```

⭐ **1 行目の理由は、仕様書の `FR-051` が表 T-031 の直後に書いている文と同じである** —— 「**常時表示の規則は表 T-031 の `SC-4` が持つ —— 消えるとキャンバスの幅が変わり、再レイアウトが走る。**」 ⛔ **この理由が成り立つのは、スクロールバーが幅を取っているときだけである。** 取らないなら、消えても幅は変わらない。

**パネル境界**（`:843` ほか）:

```
/* Panel Divider: the grab strip over the Row Title Panel's right border. */
#panelDivider { cursor: col-resize; }
```

描画は `x = panelW − 4`、`width = 8` である。⭐ **境界に重なる 8 px の掴み帯であり、レイアウトの幅を取っていない。**

**ヘッダ**（`:274`、`:775`）:

```
ENV.canvasH = ENV.viewH - ENV.headerH;
.appHeader { flex:0 0 auto; ... }
```

⭐ **PoC はヘッダを測って引いている。** 固定の高さを持たない。

## 2. 何をするか

**`FR-051` に 3 段落を足す。表も行も図も UID も 1 つも増やさない。値も 1 つも足さない。**

| | 決めること |
|---|---|
| (a) | **`App Header` の高さと `Scrollbars` の太さは、起動時に環境から確定させる。設定値として持たない** —— どちらも環境ごとに違う。⚠️ **`appHeaderMaxHeight` はその上限であって、高さそのものではない** |
| (b) | **`Scrollbars` は `Row Area` から場所を取る。太さは環境の既定の半分とする** |
| (c) | **`Panel Divider` は `Row Area` から場所を取らない** —— 境界に重なる掴み帯である |

**足す文（逐語。`FR-051` の 表 T-031 のあとの 2 つの注記に続けて置く）**

```text
**`App Header` の高さと `Scrollbars` の太さは、起動時に環境から確定させること（MUST）。設定値として
持ってはならない（MUST NOT）** —— どちらも環境ごとに違い、持つと環境をまたいだときに絵が崩れる。
⚠️ **`appHeaderMaxHeight`（`_assets/tbl-settings.md` の `S-116`）はその上限であって、高さそのものでは
ない。** 確定させる位置は 表 T-077 の `BO-1` である。

**`Scrollbars` は `Row Area` から場所を取ること（MUST）。太さは環境の既定の半分とすること（MUST）**
—— 常時表示にする理由（`SC-4`）が幅の変動を避けることである以上、**場所を取らない形では `SC-4` が
意味を持たない。** 半分にするのは、常に出しているものが描画領域を丸ごと食わないためである
（由来は `previous-project-result/03-ui-naming/ui-detail-spec-ja.md` の 5-2）。

**`Panel Divider` は `Row Area` から場所を取ってはならない（MUST NOT）** —— パネルの境界に重なる
掴み帯である。**取ると、掴みやすさのために広げた帯がそのまま描画領域を削る。**
```

## 3. ⚠️ 起草の途中で取り下げた推奨（記録として残す）

⭐ **2 度、自分の推奨を自分で潰している。どちらも「実物を開いたら違った」である。**

| | 最初の推奨 | なぜ潰れたか |
|---|---|---|
| **1 度目** | `Scrollbars` と `Panel Divider` は **どちらも場所を取らない**。根拠は `FR-052` の理由文が判定式に 2 つとも含めていないこと | ⛔ **`FR-051` が 表 T-031 の直後に書く「消えるとキャンバスの幅が変わり、再レイアウトが走る」を読み落としていた。** この 1 文は、スクロールバーが幅を取っていなければ成り立たない。**判定式に現れないことより、こちらのほうが直接的である** |
| **2 度目** | `App Header` の高さは `appHeaderMaxHeight` を**そのまま使う**。測って渡す案は「2 パス起動になるので代償が大きい」 | ⛔ **代償の見積もりが誤っていた。** 測るのは**ヘッダ自身の箱**であって、日程を 1 枚も描かずに済む。それは `BO-1` の「画面の寸法を確定させ、`ScreenRegions` を求める」段そのものであり、`NFR-011` に触れない。**PoC も実際にそうしている** |

⚠️ **どちらも、PoC と `FR-051` の本文を先に読んでいれば出さずに済んだ推奨である。**

## 4. ⚠️ 書かないと決めたもの

| | |
|---|---|
| **スクロールバーの太さの設定行** | ⛔ **足さない。** 環境の値であり、設定値にすると環境をまたいだときに合わなくなる。⭐ **値を発明せずに済む形を採った** |
| **`appHeaderHeight` の新設・改名** | ⛔ **採らない。** 表 T-212 は「寸法の**上限**」の表であり、`S-116` はそこに正しく座っている。**高さは環境から来る** |
| **`Panel Divider` の幅（8 px）** | ⚠️ **仕様に焼かない。** 掴み帯の幅は掴みやすさの値であって、レイアウトに効かない（場所を取らないため）。**表 T-023d の掴み領域の側の話である** |
| **`regionsFromScreen` の引数** | ⛔ **仕様に書かない。** 署名は `src/` が持つ（CR-146）。**本 CR が定めるのは「環境から確定させる」ところまでである** |
**⚠️ 起草の途中で 4 つ目の編集が要ることが判った（3 度目の取り下げ）。** 当初は「`FR-052` の判定式は触らない」と書いていた。⛔ **誤りである。** `FR-052` の STATEMENT は判定式を逐語で持っている ——

```
`Schedule Canvas` の幅から `canvasPadding`（`S-56`）と 2 つの幅を引いた残りが `Row Area` の幅であり（`U-50`）
```

**スクロールバーが式に入っていない。** 本 CR が「スクロールバーは `Row Area` から場所を取る」と定める以上、**`Row Area` の幅の定義が 2 つになる**（式の側と、規則の側）。⭐ **式は仕様書で 1 か所にしかないので、そこを直す。**

```text
BEFORE `Schedule Canvas` の幅から `canvasPadding`（`S-56`）と 2 つの幅を引いた残りが
       `Row Area` の幅であり（`U-50`）

AFTER  `Schedule Canvas` の幅から `canvasPadding`（`S-56`）と 2 つの幅と縦のスクロールバーの
       太さを引いた残りが `Row Area` の幅であり（`U-50`。太さの決め方は 表 T-031 のあとの
       規則が持つ）
```

⚠️ **高さの式は足さない。** `U-50` が「`Time Ruler` の帯と余白を除いた」と既に定めており、本 CR の規則が横のスクロールバーを加える。**同じ算術を 2 か所に書かない。**
