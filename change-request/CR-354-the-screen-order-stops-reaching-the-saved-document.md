## 1. ⭐ 裁定 3 —— 何が破れていたか（**実測 2026-09-05、出荷ビルド**）

**ピン留めした行（木の順位 7）から、画面では下・木では上の行（順位 0）へ枠を引いた:**

```
文書に入った値   topGroupId = 順位 7 ／ bottomGroupId = 順位 0
IV-19 の要求     topGroupId が bottomGroupId より下でないこと
判定             満たさない
```

⛔ **原因は物差しの食い違いである** —— **正規化は描かれた `y` で上下を決め、`IV-19` は木の順位で
下を決めていた。**⭐ **ピン留め（`FR-098`）は、この 2 つを意図して食い違わせる機能である。**

### ⭐ 裁定の形

```
保存する値   木の順で正規化する   ⇒ 保存した文書が、開く人の画面の状態から独立する
描く絵       画面に出ている 2 行を囲んで描く ⇒ 引いた人が見たとおりに見える
```

⭐⭐ **この 2 つは排他ではない。**⛔ **排他だと思って一方を選ぶと、必ず高いほうを失う。**

## 2. ⭐ 裁定 4 —— 写し方は一意に決まる

⛔ **前に立つ者は「一意に決まらない」と述べたが、それは誤りであった。**
⚠️ **出どころは `edit-task-group.ts:749-753` の STOP 注釈で、それが `HM-10` を読み違えている** ——
**注釈は「行は WBS のどこからでも `Task` を持つ」と書くが、`HM-10` は逆に
「行の器は 1 つの `Task` ごとに紐づく」と書いている。**
⭐ **データの側もそうなっている** —— **`TaskGroup.derivedFromTaskUid` は 1 つである。**

### ⭐ 決まる写し方

```
各 Task の、同じ WBS 親を持つ兄弟の中での順位
  = その Task を描いている行の、行の木における位置
同じ行に兄弟が複数いるとき
  = 表 T-014 の ST-2（start 昇順 → finish 降順 → uid 昇順）
導出元を持たない行
  = 何も伝えない
```

**例で確かめた** —— 根の子が A・B・C。行 1（導出元 A）が A と C を描き、行 2（導出元 B）が B を描く。
行を「行 2、行 1」に並べ替えると: **B は 1 番目、A と C は同着の 2 番目 → `ST-2` で解いて `B → A/C`。**
⭐ **一意に決まる。**⛔ **移してきたバーを区別する必要は無い**（利用者の指摘のとおり）。
