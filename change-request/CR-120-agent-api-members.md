### 2-4. なぜ「出す」が 4 つではなく 5 つなのか

**表 T-024 は入出力の形式を 7 つ持つ**（`IO-1` 〜 `IO-7`。自分で数えた）。**そのうち機械向けの面に載せるのは 5 つである。**

| 行 ID | 形式 | 面に載せるか | 理由 |
|---|---|---|---|
| `IO-1` | MSPDI XML | **載せる**（`exportMspdi`） | 書出（`FR-021`） |
| `IO-2` | JSON | **載せる**（`exportJson`） | 書出（`FR-024`） |
| `IO-3` | SVG | **載せる**（`exportSvg`） | 書出（`FR-080`） |
| `IO-4` | PNG | **載せる**（`exportPng`） | 書出（`FR-025`）。⚠️ `AG-8`「**画像化に失敗したときも、呼び出した側が失敗を値で受け取れること**」 |
| `IO-7` | 単一 `.html` | **載せる**（`exportEmbeddedHtml`） | 書出（`FR-067`。`ORIGIN` に `UC-012` を持つ） |
| `IO-5` | localStorage | ⛔ **載せない** | **保存 / 復旧であって書出ではない。** `AutosaveGateway`（`CP-23`）が自動で行うものであり、人も UI から明示的には呼ばない |
| `IO-6` | クリップボード | ⛔ **載せない** | **「現在の画面を画像として他のアプリへ渡す」ための経路である**（表 T-024 の備考「ダウンロードを経由しない。資料へ貼る用途」）。**機械は `exportPng` で値として受け取れるので、クリップボードを経由する意味が無い** |
