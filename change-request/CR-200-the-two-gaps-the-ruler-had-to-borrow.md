## 2. 何が壊れていたか（**逐語**）

### #1 —— 目盛の間引きが、形状のラベル用の値を借りている

`docs/spec/_assets/tbl-glossary.md` の 表 T-104:

```
| K-31 | ラベル | labelPad  | 形状の内側の余白       |
| K-32 | ラベル | labelGap  | 形状の外へ出すときの隙間 |
```

⛔ **どちらも「形状」（バー・マイルストーン）のラベル用であり、目盛の帯の話ではない。**
⭐ **`labelGap` の他の 2 か所は、どちらも形状の外へ出したラベルである**（`schedule-geometry.ts:799` ／ `schedule-layout.ts:611`）。

⛔ **`src/entity/layout-engine/schedule-layout/schedule-layout.ts:325`（`tickStrideOf`）だけが違う:**

```ts
const needed = labelWidth('00', settings.rulerFont, settings) + settings.labelGap
```

### #2 —— `LF-1` は、その隙間を 1 文字も持っていない

`docs/spec/05-07-design.md:715` の 表 T-221:

```
| LF-1 | 日と曜日の段の間引き | ラベルの概算幅（FR-093）を 1 日あたりの表示幅で割り、
                              切り上げた日数ごとに 1 つを残す。…… |
```

⛔ **算式に隙間の項が無い。** ⚠️ **試験 `SWS-1` は算式のほうを読んで書かれており、いま赤い。**

⭐ **「仕様どおりコードから隙間を外す」は採らない。測って否定した:**

```
既定（rulerFont=12, labelCoef=0.5, pxPerDayAt1x=6）でラベルの概算幅 = 12px

zoomX   1 日の幅   仕様どおり(12px)   現行(20px)
 0.5     3.0px       4 日ごと          7 日ごと
 1.0     6.0px       2 日ごと          4 日ごと
 2.0    12.0px       1 日ごと          2 日ごと   ← 概算幅 = 1 日の幅。隙間ゼロで接する
```

⛔ **接した目盛は読めない。** ⭐ **`FR-017` の RATIONALE が「日と曜日の段はラベルが重なるので N 日ごとに間引く」と書いている以上、接する状態はその目的を満たしていない。**

### #3 —— 同じ「6」が 3 か所にあり、うち 1 か所はコードの打ち直しである

```
S-2 の既定値   `rulerFont` × 3 + 6（S = 42 / M = 48 / L = 54）🔎
S-2 の下限     `rulerFont` × 3 + 6
S-3 の上限     (`rulerHeight` − 6) ÷ 3
src/use-case/edit-document/edit-document-settings.ts:188
               rulerHeight: rulerFont * 3 + 6,
```

⭐ **4 か所目のコメントが、自分でこう書いている**（逐語）:

```
// ⛔ Change request: give the generated carrier the formula rows, so
// this asks DocumentSettings (CP-2 owns the saved values and their
// bounds) for the band height instead of owning the arithmetic.
```

⛔ **理由も書いてある** —— 「生成される担い手は `SETTINGS_BOUNDS` だが、それは**数として書かれた**上下限しか運ばず、**他の鍵の式として書かれた**既定値も下限も運ばない」。
⚠️ **つまり (b) を設定値にするだけでは、その値は 1 度もコードへ届かない。** ⭐ **担い手を足すところまでが本 CR の射程である。**
