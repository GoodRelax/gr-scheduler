```js
function thinTicks(kind, ticks, pxPerDay, labelPx) {
  if (kind !== "day" && kind !== "weekday") return ticks;
  var every = Math.max(1, Math.ceil(labelPx / Math.max(0.001, pxPerDay)));
  if (every === 1) return ticks;
  return ticks.filter(function (t) { return t.day % every === 0; });
}
```

**(b) 帯高**（`:1524` 〜 `:1536`）:

```js
var stackTop = [], y = 0;
for (var s = 0; s < stacks.length; s++) {

  if (!stacks[s].length) tallest = ctx.metricsOf("rectangle").reserved;
  stackTop.push(y);
  y += tallest + settings.stackGap;
}
return { ..., height: Math.max(0, y - settings.stackGap), ... };
```

## 2. 何をするか

**Chapter 6.1 に 表 T-221 を作り、`SW_SPEC` ノードを 2 本置く。** ⚠️ **6.1 の未記入行は残す** —— `SWS-` は波ごとに足す。

### 表 T-221（新設・3 行）

**表 T-221 — レイアウトの算式**

| 行 ID | 求めるもの | 算式 |
| --- | --- | --- |
| LF-1 | 日と曜日の段の間引き | ラベルの概算幅（`FR-093`）を 1 日あたりの表示幅で割り、切り上げた日数ごとに 1 つを残す。⚠️ **年・月・週の段には掛けない**（`FR-017` が間引きを禁じている）|
| LF-2 | 行の帯高 | 段ごとに、その段に載る `Task` が縦に取る高さの最大を採り、それらを合計して、段と段のあいだに `stackGap` を段数から 1 を引いた数だけ加える。**`Task` を 1 つも持たない段は、矩形が縦に取る高さとする** |
| LF-3 | 行の縦位置 | 前の行の縦位置に、前の行の帯高と `rowGap` を加える。**帯高は矩形が縦に取る高さを下回らない** |

⚠️ **`Task` が縦に取る高さは本表が持たない** —— 表 T-012 の「実績の置き方」の欄と `FR-094` の床の規則が既に持っている。
⚠️ **`TaskGroup.height` の指定があるときは `FR-042` が優先する** —— 指定は下限であり、段数がそれより高い帯を要するときは超えて広げる。

### `SW_SPEC` ノード 2 本

```text
#### 目盛の細かい段を間引く

**Type**: SW_SPEC
**UID**: SWS-1

**STATEMENT**: 目盛が日または曜日の段を出している間、`GRS` は、表 T-221 の `LF-1` に従って間引くこと。

**RATIONALE**: `FR-017` が「ラベルが重なるので N 日ごとに間引く」と定めた `N` を与えるものである。
**罫線が同じだけ間引くことは `FR-089` が定めており、同じ `N` を使う。**

**Relations**:

- **Type**: `Parent`
  **ID**: `FR-017`
  **Role**: `Satisfies`

#### 行の帯高と縦位置を決める

**Type**: SW_SPEC
**UID**: SWS-2

**STATEMENT**: 段を割り当てたあと、`GRS` は、行の帯高と縦位置を 表 T-221 の `LF-2` と `LF-3` に従って決めること。

**RATIONALE**: 表 T-014 の `ST-9` が「行の帯高は段数で決まる」と定めた、その決まり方である。
⚠️ **空の段と空の行が矩形 1 段ぶんを取るのは、行の帯が消えて行見出しと縦位置がずれるのを防ぐためである。**

**Relations**:

- **Type**: `Parent`
  **ID**: `FR-003`
  **Role**: `Satisfies`
```
