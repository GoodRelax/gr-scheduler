## 7. ⛔ 裁定 `D8` を本 CR から外した理由（**測ってから分かった**）

⭐ **一度は書いた。書いてから、図の生成器が止めた。**

### 何が分かったか

| | |
|---|---|
| いまの絵の経路 | `ClipboardGateway → SvgRenderer`（`picture out`）**1 本だけ** |

**組み立てを通らない絵を取っている。** ⭐ **足すべき辺を足したうえで、この辺が残ってよいのかを決めねばならない。**

### なぜ `CR-196` なのか

⭐ **`ImageExporter`（`PI-21`）は、いま `exportPng` しか公開していない**（`docs/spec/05-07-design.md:351`）。
**組み立てた画面を SVG として返すメンバを持たない。** ⛔ **そのメンバは `CR-196` が足す** ——
裁定 `D5b`（`AM-13` は画面全体を返す）が要求するのが、まさにそのメンバだからである。

⚠️ **そのメンバが在って初めて、`ClipboardGateway` は SVG も PNG も `ImageExporter` から取れる。**
⭐ **つまり `D8` と `D5b` は、同じ 1 つの穴の 2 人の呼び手である。**

### ⛔ 分けたら壊れる形になっていた

技能書の第 1 則:

```
WRONG   for each finding:  edit the objects it touches
RIGHT   for each object:   apply every finding that touches it, once
```

⛔ **本 CR で `D8` を書けば、`_source/components.json` の `ClipboardGateway` の辺を触る。**
**`CR-196` は同じ 3 本をもう一度触る。** ⚠️ **後の回は前の回が何を動かしたかを知らない** ——
これが「同じ行を 2 度書く」形そのものである。

⭐ **だから `ClipboardGateway` の辺は 1 度だけ、`CR-196` で書く。** ⛔ **本 CR は
`_source/components.json` を 1 バイトも触らない**（辺は **89 のまま**）。
