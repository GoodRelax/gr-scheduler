## 2. 変更の背景・目的

### 2-1. 5.6 が負っていた借金は 4 件

| # | 中身 | 出どころ |
|---|---|---|
| 1 | **ADR-000「最小構成と比べて何を増やしたか」** | `R2.18`。**無ければ即違反**と規約が明記 |
| 2 | **キャッシュの ADR** | `R2.20`。**題材は CR-126 §7 がここへ送った** |
| 3 | **描かなかった図とその理由** | 5.3 が図を描かなかった |
| 4 | **4 つの代償** | 5.1 / 5.2 / `LM-2a` / 表 T-043 の `PG-13` |

### 2-2. ⭐ キャッシュの題材を実測した —— **1 フレームに 4 回走りうる**

```
描画   SingleHtmlShell → SvgRenderer → ScheduleLayout          （目盛と行）
                                    → ScheduleGeometry → ScheduleLayout   （座標）
入力   SingleHtmlShell → InputCommandTranslator → ScheduleLayout          （ポインタ → 日付）
                                               → ItemHitArea → ScheduleGeometry → ScheduleLayout
```

**`ScheduleLayout` を必要とする経路が 1 フレームに 4 本ある。** **どの部品もインスタンスを持たない**ので（5.3）、**各々が自分で `layoutFromSchedule` を呼ぶと、ポインタが動くたびに表 T-068 の 11 段が 4 回走る。** 11 段には段割当の貪欲割当（`ST-3`）と依存線の経路（表 T-018a）が含まれる。

⚠️ **`NFR-002`（平均フレームレート）と `NFR-003`（95 パーセンタイル）の予算に収まらない。** `R2.20` の「キャッシュを用いない設計では NA」は、**入力の経路では選べない。**

### 2-3. 決定 —— **シェルがフレーム先頭で 1 回計算して配る**

**`LY-5` が「現在値を保持するのは `Framework` だけ」と定めている**ので、フレームごとに 1 つだけ作る値の持ち主はシェルである。

⭐ **表 T-066 の `CS-1` が既にこの形を書いている** —— 「1 フレーム（描く）／ 文書の凍結された複製・画面の寸法・基準日 ／ **フレームの先頭で 1 回**」。**レイアウトをそこへ加えるだけである。**

⚠️ **計算する場所が `Framework` になるが、計算そのものは `layoutEngine` の純粋関数のままである** —— シェルは呼んで結果を持つだけで、算法を持たない。**`LR-1`（内向きだけ）に反しない。**

### 2-4. これは CR-126 §7 が送った件である

> **シェルから `Entity` へ直に辺を引く**（レイアウトをフレーム先頭で 1 回だけ計算する）／ **`framework → entity` という新しいクラスタ対ができ、`build.py` にラベルを足すことになる。****重複計算の是非は `R2.20`（キャッシュ）の論点であり、Chapter 5.6 の ADR が持つ**

**本 CR がその ADR である。**

⚠️ **クラスタ対は `framework → entity` ではなく `framework → layoutEngine` である**（機械で確認）—— `build.py` の `labelled_cluster_of` は**内側のラベル付きクラスタ**へ写すので、`entity` ではなく `layoutEngine` に落ちる。**必要なラベルは 1 件である。**

### 2-5. 代償の 4 件はいずれも既に持ち主がある

| 代償 | 正 |
|---|---|
| WCAG 1.4.12 を適合範囲に数えない | `LM-2a` ／ 5.1 |
| 自動保存 1 回の書き込み時間に上限を定めない | 表 T-043 の `PG-13` ／ `LM-11` |
| `R2.13`（CQS）と `R2.5`（ISP）を意図して満たさない | 5.2 |
| `AgentApiEndpoint` が現在値を持たず、呼ばれるたびに引く | 表 T-065 の `IF-7` |

⭐ **表 T-073 は索引にする。理由も規則も書き写さない。** 1.9 の「同じことを 2 度書きたくなったら、置き場を 1 つ決め、他方は行 ID か `UID` で指すこと（MUST）」に従う。**CR-131 §8-2 で重複検出に引っかかった直後なので、同じ轍を踏まない。**

### 2-6. ADR の書式

**`previous-project-result/20-spec-template/spec-template.md` が `Context` / `Decision` / `Status` / `Consequences` の 4 項目を定めている。**

⚠️ **テンプレートは 4 項目を表で書いているが、本仕様書では散文にする** —— 1.9 が「表の第 1 列は行 ID とする（MUST）」と定めており、**`項目` / `内容` の 2 列表は行 ID を持てない。** 検査 8 も無番号の表を守れない。**数え上げられる中身（増やしたもの・4 点・図・代償）だけを番号付きの表にする。**
