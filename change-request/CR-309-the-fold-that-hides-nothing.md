narrow したが、⛔ **利用者が実際に踏んだ場面はそれでは直らない。**

## 1. ⛔ 測った

### (a) ⭐ CR-307 の narrow では、利用者の場面が直らない

**実測（2026-08-30、出荷ビルド）。**既定の文書は次の 5 行を描く:

```
深さ1  Whole Product
深さ2    Phase Bars       ← 配下を持たない
深さ2    Phase Gates      ← 配下を持たない
深さ1  Mobile Client
深さ2    Phone App
```

`Whole Product` で `IC-77`（配下をすべて畳む）を押すと:

| | |
|---|---|
| 畳む相手 | `Phase Bars` と `Phase Gates` —— **どちらも描かれている** |
| CR-307 の判定 | **対象は 2 つ在る ⇒ 構える** |
| ⛔ **実際に起きること** | **描かれる行は 5 行のまま。`text`・`polygon`・`line`・`svgBytes` が 1 バイトも動かない** |

⇒ ⛔⛔ **「描かれている行を数える」では足りない。**
**畳む相手は描かれているが、その相手が配下を持たないので、畳んでも隠れるものが 1 つも無い。**

⭐ **対照（同じ実測）**: `Mobile Client` で同じ操作をすると `Phone App` の配下 3 行が消え、
`text` が **700 → 625** に動く。⇒ **こちらは正しく構えるべきである。**

## 4. 落ちる／緑になる試験

⛔ **本 CR だけでは、いま在る試験は 1 件も動かない** —— **構えの判定を見張る試験が
どこにも無いからである。**⚠️ **CR-307 を配線した体が「わざと壊して」確かめ、
①の narrow を落としても赤が 1 件も増えないことを報告している。**

⇒ ⭐ **仕様だけを読む体が、次の 2 つを直接主張する試験を書くこと**:

1. **配下を持たない行だけを配下に持つ行では、`IC-77` が構えない**（`Whole Product`）
2. **配下に描かれる行を持つ行では、`IC-77` が構える**（`Mobile Client`）
