# CR-163 — タスク LOD の判定を、深さからバーの幅へ移す

> ⛔ **未適用である。**
> **閉じるもの**: `ScheduleLayout` の `LC-2` が書けないこと —— **深さから幅を出す規則が存在しない。**
> ⭐ **利用者の裁定である。** ⚠️ **グループ LOD は 1 字も変えない**（§3）。

## 1. 出どころ

`FR-018` の RATIONALE の逐語（`01-04-requirements.md:2516`）:

```
タスク LOD の判定は WBS の階層の深さで行い、**しきい値は表 T-205 の `S-86` に従うこと（MUST）**。
```

⛔ **`S-86` は px の幅であり、深さは数字である。深さから幅を出す規則が仕様書のどこにも無い。**

### PoC も解いていなかった

`previous-project-result/08-poc/poc-integrated.html` の逐語:

```js
var MEDIAN_DURATION = { 1: 240, 2: 80, 3: 27, 4: 13, 5: 6 };                        // :1201
var span = Math.max(2, Math.round(MEDIAN_DURATION[wbsDepth] * (0.6 + rand() * 0.8)));  // :1362
/* MEDIAN_DURATION is declared with the dataset: the generated spans follow it. */   // :1802
if (MEDIAN_DURATION[d] * pxPerDay >= settings.taskLevelOfDetailReadablePx) best = d;   // :1806
```

⭐ **PoC はデータを自分で生成しているので、深さごとの期間を最初から知っていた。** 実物の文書には無い前提である。**コメント自身がそう書いている。**

### ⭐ `S-86` の欄が答えを持っていた

`_assets/tbl-settings.md:207` の逐語:

```
| S-86 | `taskLevelOfDetailReadablePx` | `24` | `fontMin` | 200 | この幅を割った深さのタスクを描かない（WBS の深さ）。文字が 1 つも入らない幅にしない |
```

**「文字が 1 つも入らない幅にしない」** —— 見ているのは **形状そのものが文字を抱えられるか** である。**比べる相手は形状の幅であって、深さの代理値ではない。**

⚠️ **占有幅（表 T-038）では判定できない** —— 占有幅は**バー ＋ 外へ出したラベル**であり、バーが 5px でも名前が 60px なら 65px になる。**`S-86` を割ることが原理的に起きない。**

## 2. 何をするか

**要求の 1 節と、参照している 2 行を直す。表も行も図も UID も 1 つも増やさない。**

| | 直すもの |
|---|---|
| (a) | `FR-018` の RATIONALE の 1 節（判定の単位）|
| (b) | 表 T-005a の `L-2` の説明（「深い WBS の `Task`」→「幅の狭い `Task`」）|
| (c) | 表 T-205 の `S-86` の備考（「深さのタスク」→「`Task`」）|

**(a) 前後**

```text
BEFORE タスク LOD の判定は WBS の階層の深さで行い、**しきい値は表 T-205 の `S-86` に従うこと（MUST）**。

AFTER  **タスク LOD の判定は `Task` ごとに行い、その `Task` の形状が占める幅がしきい値を割るときは
       描かないこと（MUST）。しきい値は表 T-205 の `S-86` に従うこと（MUST）** —— 幅は期間に
       1 日あたりの表示幅（`FR-017`）を掛けた値である。⚠️ **占有幅（表 T-038）で判定しては
       ならない（MUST NOT）** —— 外へ出したラベルを含むので、しきい値を割ることが起きない。
       ⭐ **深さを代理に使わないのは、「深いほど短い」が相関にすぎないためである** —— 平らな WBS に
       短いタスクが並ぶ文書や、深い段に長期のタスクがある文書で外れる。**タスクごとに測れば、
       縮めるほど描く集合が縮むことが構造で決まり、上の逆転の禁止が論証を要さずに成り立つ。**
```

**(b) 前後**

```text
BEFORE | L-2 | タスク LOD | 深い **WBS** の `Task` を描かない | 横（`zoomX`）＝ 幅 |
AFTER  | L-2 | タスク LOD | **形状の幅が狭い** `Task` を描かない | 横（`zoomX`）＝ 幅 |
```

**(c) 前後**

```text
BEFORE この幅を割った深さのタスクを描かない（WBS の深さ）。文字が 1 つも入らない幅にしない
AFTER  形状の幅がこれを割る `Task` を描かない。文字が 1 つも入らない幅にしない
```

## 3. ⚠️ 触らないと決めたもの

| | |
|---|---|
| ⭐ **グループ LOD** | ⛔ **1 字も変えない。** `threshold(d) = S-87 × S-88^(d − 2)` を `zoomY` と比べる形のままとする。**「入るだけ出す」は `FR-055`（全体表示）が既に担っており**、表 T-068 の 2 回走行がまさにその往復である（高さを測る → 倍率を出す → 表示量が変わったらもう 1 度 → 3 回目は禁止）。⛔ **LOD 自身を高さ依存にすると、同じ機構が 2 つになり、`LC-2` が `LC-9` を待つ** —— 捨てる行のレイアウトまで先に計算することになり、**最も縮めたときに最も働く**形になる（`NFR-001` と `NFR-013` に直撃）|
| **`S-87` / `S-88`** | **そのまま生きる。** 廃止しない |
| **`S-125` で頭打ちにする節** | ⚠️ **触らない。** `FR-004` が「`S-125` で頭打ちにしてよいのは LOD の判定のときだけ」と定めており、**`S-125` は `TaskGroup` の深さである**。タスク LOD の変更は掛からない |
| **`S-86` の値（24）と範囲** | **触らない。** 意味は変えていない —— 元から「文字が 1 つも入らない幅」である |
| **`L-2` の駆動の欄** | **`横（zoomX）＝ 幅` のまま。** 幅で判定する形はこの欄と**むしろ整合が良くなる** |
