## 0. ⛔ 立ちどまって答える 3 つ

### ① この変更は `CH-` / `GL-` のどれを前へ進めるか

⭐ **`GL-006`（マニュアルを読まずに使える）**。予定日はいま、掴むかツールチップ（表 T-040 の `EZ-6`）でしか読めない。名前の隣に日付の文字を置けば、ポインタを動かさずに全タスクの予定日を 1 画面で読める。⚠️ 同時に `GL-002`（1 画面の情報量）と引き換えになる —— ラベルが長くなると段が増える ⇒ 既定は隠す（決定 5）。

### ② レビュー観点のどの条項を当て、何が出たか

- **`R1.1`（曖昧さがない）** —— 「終了日」は位置（バーの右端）とも日付とも読める（`JDG-04` の食い違いと同じ型、handoff の 0.1）⇒ 表 T-251 の `ND-3` と `FR-002` の段で「`finish` の日そのもの、翌日にずらさない」と書いた。
- **`R1.3`（矛盾がない）** —— 表 T-013 の `NL-1` は「ラベルがタスクの幅に収まる」で置き場を決める。足した文字を幅に数えないと、中に書いたラベルが形状を越える ⇒ 幅に含める MUST を置いた。`FR-049` の「隠した予定は名称ラベルを動かさない」と衝突しないよう、`S-227` と `S-232` を結ばない MUST を置いた。
- **`R2`（命名）** —— キーは `planDatesVisible`。表 T-104 の `表示の切り替え` の既存の綴り（`planVisible` / `assigneeVisible`）に揃えた。⚠️ 利用者の語「基準線」は仕様では変更前の予定を指す（1.9 の `A-9`）ので、仕様・辞書には書かず、基準日（`IC-44`）と書いた。
- **`R4` グリッジ** —— 日付の文字を表示範囲・基準日・実行日から決めると、スクロールや日付の移り変わりでラベル幅が変わり `OC-1` を経て段が組み替わる ⇒ 文書の値だけから決める MUST NOT を置いた。
