> ⚠️ **5 件目（`setTaskVisualNamePlacement` の 9 点の対応）は W2 を止めないので、本 CR に含めない。**

## 1. 出どころ

**W2 の 4 ユニット**（`UF-5` `ScheduleLayout` ／ `UF-58` `ScreenRegions` ／ `UF-6` `ScheduleGeometry` ／ `UF-7` `ItemHitArea`）を書く準備で、`previous-project-result/temp/wave-slice.md` が挙げていた 5 件を調べた。**5 件とも、仕様書に本当に穴があった。** 1 件ずつ実物を開いて確かめている。

| | 穴 | 止まる者 |

| ④ | ポインタの無い経路のズームの中心が、どこにも無い | `ScheduleLayout` |

### ① `shapeKind` の `null`

`_assets/fig-erd-detail.md:401` の `AT-100` は `列挙（5 値）` `可` とだけ書き、**`null` の意味を持たない**。⭐ **同じ表の `AT-102`（`fillColor`）は `可（\`null\` = テーマから解く）` と綴っている。** 綴る形は既にある。`FR-083` は変える先しか定めず、表 T-012 に `null` の行は無い。**生成スキーマだけが `null` を許している。**

⭐ **利用者は当初「期間の情報があれば矩形」を検討したが、実測により採らないことにした。**

| 確かめたこと | 実測 |
|---|---|
| `Task` の `duration` の列 | ⛔ **無い。** 期間は `start` と `finish` から出す |
| `percentComplete` | 在るが、**マイルストーンでも意味を持つ**（済んだか否か）ので分けられない |
| 日付の粒度 | `FR-054` により**日**。⛔ **長さ 0 を表せない** |
| マイルストーンの正 | `AT-30` が **「マイルストーンかどうかの正」** と明記。`Own` で `Task/Milestone` に対応する |

⛔ **`AT-30` が正と定めている以上、描く形をそれ以外から導くと、同じ事実に正が 2 つ立つ。** ⭐ **「長さを持つものはバー、点はマイルストーン」という判断は `FR-001` が作成時に `Task.milestone` へ書き込んでおり、取り込み時は交換相手が持ってくる。導き直す必要が無い。**

### ② 隠した行の配下

**`HR-1a`（畳み）は 3 つの禁止を持つ** —— 配下の行とその `Task` を描かない／親へ載せ替えない／グループ LOD と同じ絵になる。⛔ **`HR-6`（隠し）は「行を隠す」の 4 文字だけで、配下にも `Task` にも触れていない。** `05-07-design.md:510` の `LC-1` は「人が畳んだ行と非表示の行を落とす」と書きながら、**正の欄が畳みの規則 `HF-7` を指している。**

⭐ **裁定は「畳みと同じ。ただしグループ LOD の縛りは掛けない」である。** `HR-1a` が載せ替えを禁じた理由（**全畳みや縦ズームの縮小で 1 行に文書中のほぼ全 `Task` が集まり `ST-7` の安全弁に達する**）は隠しにもそのまま当てはまる。⚠️ **一方「LOD と同じ絵」を掛けると、拡大したときに隠した行が戻るという読みが生まれる。** 隠しは人が駆動するので、`HF-7` の「人 > 倍率」と同じ側に置く。

⚠️ **隠す対象は行（`TaskGroup`）であって `Task` ではない** —— 入口は `setTaskGroupHidden` の 1 本であり、`Task` を個別に隠す入口は仕様書に無い。

### ③ 起動時の全体表示

**原稿が食い違っている。** `05-07-design.md:567` の `BO-3` は「`OP-10` に当たるときは、**この 2 つ**を `BO-4` が決める」（＝倍率と表示位置）と書くが、`01-04-requirements.md:3110` の `OP-10` は**条件も結果も表示位置だけ**である。

さらに `FR-055` は `HF-8`（**人が畳んだ状態をすべて捨てる**）を連れてくる一方、`HR-6` は**隠した状態を保存することを `WY-1` のために MUST にしている**。⛔ **起動のたびに `HF-8` が働けば、保存させた状態を黙って捨てることになる。**

⭐ **裁定** —— **`OP-10` は倍率と表示位置の両方を決める。`HF-8` は起動時には働かせない。人が全体表示を求めたときの `HF-8` は既存のまま（畳みを捨てる）。** ⚠️ **隠しはどちらの場合も残る**（`HF-8` は畳みだけを捨てると書いている）。

### ④ ズームの中心

中心を述べているのは **2 か所だけ** —— `MK-2`（`Ctrl` ＋ ホイール = ポインタ中心）と、`:2281` の **「ズームはポインタ位置を中心とし、カーソル下の日付と行が動かないこと（MUST）」**。⛔ **`MK-9`（画面上のボタン）・`SK-16` / `SK-16a` / `SK-17`（ショートカット）・`setZoom` には中心が無い。** しかも `:2281` の MUST は無条件に書かれており、**ポインタの無い経路では満たしようがない。**

⭐ **裁定は `Row Area` の中心である。** `:2281` の MUST が守っているのは「見ているものが動かない」ことであり、ポインタはその代理にすぎない。
