## 4. ⛔ 起草時の編集 ③（`PI-8`）を落とした —— 検証で覆った

起草では `05-07-design.md:338` の `PI-8`「`DocumentCommand`（型。**全数は Chapter 6.1 が持つ**）」も `src/` へ移すつもりだった。**敵対的検証で 3 つの理由により落とした。**

| | |
|---|---|
| **①** | 起草の理由「前書きだけを直すと持ち主が 2 通りになる」が**成り立たない** —— `:325` の前書きが述べるのは 引数・戻り値・境界値 であって、`PI-8` の「**全数**」には改定前も改定後も一切触れていない。**改定後も食い違いは生じない** |
| **②** | ⛔ **型の全数（どんな命令があるか）を誰が持つかは、利用者が裁定していない第三の論点である。** `src/` へ移せば**仕様側から命令の一覧が完全に消える** —— 並列実装の前に決めておくべき共有物を各実装者の裁量へ落とすことになり、**本 CR が閉じようとしている穴と同じ穴を新たに開ける** |
| **③** | 起草自身が「`DocumentCommand` の全数は別 CR」と宣言しながら、その半分（持ち主）だけをここで確定させており、**内部矛盾である** |

⭐ **`PI-8` は 1 文字も触らない。** 落としても数は 1 つも動かない。
