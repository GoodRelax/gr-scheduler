# MK-6 の落ち込みの調べ（2026-10-08）

記録のみ（`PW-3` の ②）。段 0 との比べ ① はしていないので合否を言わない。

## 問い

`MK-6`（範囲選択）が 56.5 fps から 42.9 fps に落ちた（調整役の `GRS_PERF=1` の走行、`f5bd70a3`）。いつ、なぜか。

## 測り方

- 各 sha を `git archive` して作業木の `scratch/perf/<sha>` に展開し、根の `node_modules` の `vite` でビルドした（`perf-2026-10-04/setup.sh` と同じ）。
- `GRS_PERF=1` の `tests/nfr/nfr-002-003-frame-time-is-the-interval.test.ts` を、各ビルドの写しを作業ディレクトリにして 1 回ずつ（`perf-2026-10-04/perf.config.mjs`、1 worker、既定の倍率 100）。1 回の組ごとに根の `tools/gate/gate-queue.mjs run` の錠を取り、候補の順を組ごとに 1 つずつ回した。各点 3 回。
- 機械: i7-12650H、Windows_NT 10.0.26200、node v24.12.0、msedge 154.0.4258.62 headless、renderer は NVIDIA GeForce RTX 4050 Laptop（走行 5 の Intel UHD とは違う —— 前の走行の絶対値とは比べない）、1920×1080、`Task` 1000。静けさ: 錠の待ちは 0。OneDrive と同期サービスが 10 秒に 12.6〜32.8 CPU 秒を使い続けた（`perf-2026-10-04/load.sh`、組の前ごと）。

## なぜ（探り針。`GRS_PERF=1` の判定ではない）

- 圧縮しないビルド（`vite build --minify false`）の写しで、試験の `MK-6` の区間だけを CDP の標本取りの profiler で包み、押す点の下の要素と、区間の終わりの `data-figure="marquee"` を読んだ（1 回ずつ）。
- `f5bd70a3`: 押す点 (320, 180) の下は「Command Palette」の「Palette Commands」（パレットは行の領域の左上 188,72 190×181）。区間の終わりに範囲の枠は無い。描いた SVG は毎フレーム同じで、`showSvg` は差し替えない（自己時間 6.8 ms）。⇒ `CR-707` より前の `MK-6` は範囲選択を測っていなかった。
- `3db0f2b8`: パレットは右上 1713,72 に移り、押す点の下は透かし（`Watermark`）の文字。区間の終わりに範囲の枠がある。`showSvg` の自己時間 882 ms、`(program)` 1612 ms（`f5bd70a3` は 6.8 ms と 45 ms）—— 枠 1 つの変化で約 27 万文字の SVG を毎フレーム `innerHTML` で組み直している。
- `MK-7` の `5f5b9922`: `zoomEntranceEndsOf` が区間で計 1760 ms（`rowsAtZoomY` 1750 ms、`layoutFromSchedule` 630 → 2313 ms）。パンでは配置が毎フレーム変わるので、作り置き（`frame-loop.ts` の `zoomEntranceEndsHoldOf`）が毎回外れる。
