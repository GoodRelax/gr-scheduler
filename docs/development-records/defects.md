# 不具合・改善要望の管理台帳

**規則は [`docs/development-rules/05-working-method.md`](../development-rules/05-working-method.md) の 7.（5 段のパイプライン）。**

⛔ **利用者が指摘した不具合は、直るまでこの表から消さない。** ⭐ **消してよいのは `テスト完了` になり、かつ利用者が実物で確かめたときだけである。**
⚠️ **「実装済」は試験が緑という意味であって、実物で動いた証拠ではない**（規則 04）。**だから `テスト完了` と「実物で確認」を分けて持つ。**

---

## ステータスの定義

| ステータス | 意味 | 次に動かす者 |
|---|---|---|
| `未検討` | 受け付けただけ。原因も対応案も無い | 前に立つ者（調査を出す）|
| `追加裁定待ち` | 原因は分かったが、**仕様に行が無い**か、利用者にしか決められない | ⛔ **利用者** |
| `仕様確定` | 裁定は下りた。⚠️ **まだ仕様書に書かれていないことがある** | 前に立つ者（変更要求）|
| `実装待ち` | 仕様は揃った。着手していない | 実装の体 |
| `実装中` | 体が書いている | 実装の体 |
| `テスト中` | 実装は入った。仕様だけを読む体が試験を書いている／走らせている | 試験の体 |
| `テスト完了` | 試験が緑。⚠️ **実物での確認は別欄で持つ** | 前に立つ者（実物で確かめる）|
