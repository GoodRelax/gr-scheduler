## 行（タスクグループ）

1 行が 1 つの持ち手である。席は並行に動くセッションで、5 つ。1 つの席は 1 度に 1 つのタスクだけを持つ。調整役の合流は短いので届いた順にさばくとし、調整役の行だけは重なってよい。利用者の行のバーは利用者の時間帯をまたいで長く見える —— 中身は時間帯の分で、バーの全体ではない。

| 行 | 中身 |
|---|---|
| 済み（3 行） | 10-15 02:00〜07:36・07:36〜22:30・22:30〜10-16 05:00 に済んだ 47 件 |
| 調整役 | 作業木の GT-2 → 根の GT-2 → push と Pages → 性能の試験・CR-774 の合流 → α 版の仕事の合流 → α 版の GT-2 → チェックリストの刷り直し → 直しの GT-2。完了確認の残り 6 席の片付け |
| 利用者 | 根の早送りと OneDrive の停止（今朝）、α 版に入れるものを決める、1 枚のチェックリスト、α 版のお披露目、正式公開の判断 |
| 席1 | CR-774 の実装 → チェックリストの直し → （α の後）T-064・STOP・罠・実装待ち |
| 席2 | CR-774 の仕様だけを読む試験 → CR-767 → CR-768 の C → （α の後）W4 → W5 |
| 席3 | JDG-2361 の改名 → DFC-2912 → DFC-2903 → DFC-2700〜2702 → （α の後）小さな片付け・試験待ち・用語集 → CR-695 |

| 席5 | DFC-557 → DFC-2870 → DFC-2890・2891 → （α の後）仕様待ち・DFC-730 → DFC-2214・2215 |

**α 版の候補**（引継書の 🆕 の節の 5）は**薄い灰の仮置き**である —— 何を入れるかは利用者と決める（利用者 2026-10-15「どの実装に入るかは俺と協議の上で決めろ」）。決めた分だけが α 版の GT-2 に入り、外れた分は α の後へ回る。いちばん長い候補は CR-767 → CR-768 の C（席2、10-17 13:15 まで）で、これを外せば α 版の GT-2 は早まる。

**いちばん長い道**: α 版に入れるものを決める（10-16 21:15）→ CR-767 → CR-768 の C → α 版の GT-2（土 15:15）→ チェックリスト（土 18:15）→ 直しと push（土 23:15）→ お披露目（月 09:00）。お披露目の後: 片付けと台帳 → 3 度目の GT-2（10-20 16:00）→ W4 → W5 → 合流（10-22 02:00）→ 正式公開の判断（10-22 06:45）。

**依存線**は「前が終わってから始める」（終了→開始、ずれ 0）だけを使い、次の線は描かない（利用者の指示 2026-10-15）: 同じ行の中の線（行の並びが順を言う）・もっと長い道で同じ所へ届く線・「α 版の GT-2」と「全部の合流と台帳の締め」へ集まる線（表の下のコメントが何を待つかを言う）。全 76 本のうち描いているのは 35 本。⚠️ 描かない線は文書の依存にも無いので、遅延診断（`BD-2`）はその先の遅れを出さない。

## スキーマで迷った点

書式はスキーマ（`docs/spec/_source/grs-document.schema.json`）だけを読んで書いた。次の点はスキーマだけでは決められなかった。台帳の行は括弧の中。

1. **始まっていないタスクの `percentComplete`** —— 0 か `null` か（0 と書いた）。（`DFC-2690`）
2. **予定の全体が稼働の時間帯の外にあるタスク** —— 予定の長さが稼働の分で 0 になるとき、マイルストーンの決まりが及ぶか。（`DFC-2691`）
3. **マイルストーンとプロジェクトの開始を稼働の外の瞬間に置いてよいか**。（`DFC-2692`）
4. **`fadeInDays`／`fadeOutDays` が日の単位** —— 数時間のタスクの「確かでない端」を表せない。仮置きは色で表した。（`DFC-2693`）
5. **ハイライトの箱とコメントの付け根の時刻** —— コメントの付け根は日の列の中央と行の帯の中央（仕様 `LF-15`）、`anchorDate` は `00:00:00` で書く 1 つの日（`WT-8`）だが、スキーマはどちらも言わない。`bodyOffsetPx` の向きと単位も言わない。（`DFC-2694`）
6. **ずれ 0 の依存の `lagFormat`**（7 と書いた）。（`DFC-2564`）
7. **`minutesPerWeek`・`daysPerMonth` を暦と揃えるか**（10080 と 30 と書いた）。（`DFC-2568`）
8. **基の暦の `baseCalendarUid`**（`null` か `-1` か）と `Calendar.ordinal` の意味。（`DFC-2562`・`DFC-2560`）
9. **マイルストーンでないタスクの `milestoneGlyph`**（`diamond` と書いた）。（`DFC-2563`）
10. **名前の色の暗いテーマでの見え方**。（`DFC-2695`）
11. **「誰がやるか」は行と担当のどちらで表すか**（席を行にした）。（`DFC-2696`）
12. **`documentStamp.lastEditedBy`・`Project.author` に何を書くか**（公開の文書で個人の名を避けたいとき）。（`DFC-2562`）
13. **24 時間稼働の暦の書き方** —— 1 本の時間帯 `00:00:00`〜`00:00:00` で全日になるか。`defaultFinishTime` は `00:00:00` か `23:59:00` か（`23:59:00` と書いた）。（`DFC-2697`）
14. **持ち手ごとの稼働時間を書けない** —— 暦は文書に 1 つで、利用者の時間帯を持たせる場所が無い。（`DFC-2698`）
15. **「この時刻より前には始めない」を書く場所** —— お披露目は 10-19 09:00 と決まった日の行事だが、依存だけでは表せず、`deadline` は「遅くとも」の意味なので、マイルストーンの `start` にその時刻を直に書いた（新しい点。台帳の行は調整役に任せる）
