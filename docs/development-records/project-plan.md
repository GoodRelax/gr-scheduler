## 行と色

1 行が 1 つの持ち手である。席は並行に動くセッションで、5 つ。1 つの席は 1 度に 1 つのタスクだけを持つ（調整役の行だけは重なってよい）。

| 色 | 意味 |
|---|---|
| 濃い灰 | 済み（実績の開始と終了を持つ。4 つの「済み」の行） |
| 青 | CR の当て |
| 緑 | 並行の仕事（片付け・台帳・リファクタ） |
| 薄い灰 | 仮置き（チェックリストに行を足す・チェックリストの直し・トリアージの直し） |
| 紫 | 調整役の合流と関門 |
| 橙 | 利用者の手番 |
| 青緑 | AI 連携 |
| 赤（星） | α 版のお披露目・正式公開の判断・計画の終わり |

**依存線**は「前が終わってから始める」だけを使い、同じ行の中の線・もっと長い道で同じ所へ届く線・「全部の合流と台帳の締め」へ集まる線は描かない（利用者の指示 2026-10-15）。全 48 本のうち描いているのは 22 本。締めの合流へ集まる仕事は、そのバーの下の中央に吸い付けたコメントが言う（`CR-777` で、コメントの線先をタスクの 8 点に吸い付けられるようになった）。⚠️ 描かない線は文書の依存にも無いので、遅延診断（`BD-2`）はその先の遅れを出さない。

## スキーマで迷った点

書式はスキーマ（`docs/spec/_source/grs-document.schema.json`）だけを読んで書いた。台帳の行は括弧の中。

1. 始まっていないタスクの `percentComplete` は 0 か `null` か（0 と書いた）。（`DFC-2690`）
2. 予定の全体が稼働の時間帯の外にあるタスクの完了率。（`DFC-2691`）
3. マイルストーンとプロジェクトの開始を稼働の外の瞬間に置いてよいか。（`DFC-2692`）
4. `fadeInDays`／`fadeOutDays` が日の単位で、数時間のタスクの確かでない端を表せない。（`DFC-2693`）
5. ハイライトの箱の時刻、`bodyOffsetPx` の向きと単位。（`DFC-2694`）
6. ずれ 0 の依存の `lagFormat`（7 と書いた）。（`DFC-2564`）
7. `minutesPerWeek`・`daysPerMonth` を暦と揃えるか。（`DFC-2568`）
8. 基の暦の `baseCalendarUid` と `Calendar.ordinal`。（`DFC-2562`・`DFC-2560`）
9. マイルストーンでないタスクの `milestoneGlyph`。（`DFC-2563`）
10. 名前の色の暗いテーマでの見え方。（`DFC-2695`）
11. 「誰がやるか」は行と担当のどちらか。（`DFC-2696`）
12. `lastEditedBy`・`author` に何を書くか。（`DFC-2562`）
13. 24 時間稼働の暦の書き方と `defaultFinishTime`。（`DFC-2697`）
14. 持ち手ごとの稼働時間を書けない。（`DFC-2698`）
15. 「この時刻より前には始めない」を書く場所が無い（`deadline` は遅くともの意味）。時刻の決まった仕事は `start` に直に書いた
16. **新しい点**: コメントの線先をタスクに吸い付けたとき（`anchorTaskUid`・`anchorTaskFigure`・`anchorSnapPoint`）、自由な点の列（`anchorDate`・`anchorTaskGroupId`・`anchorBandFraction`）に何を書くか —— 両方を書いてよいか、片方を `null` にするかをスキーマが言わない（吸い付けた側を書き、日と行も残した。`anchorBandFraction` は `null`）
17. **新しい点**: `CR-777` で `CommentBox` に必須の列が 5 つ増えたのに、`schemaVersion` は変わっていない —— 古い文書が「形に合わない」と断られる理由を、版で見分けられない
