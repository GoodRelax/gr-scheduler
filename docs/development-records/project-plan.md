## レーン（タスクグループ）

1 行が 1 つの持ち手である。席は並行に動くセッションで、同時に 5 つまで（調整役の既定）。1 つの席は 1 度に 1 つのタスクだけを持つ。

| 行 | 中身 |
|---|---|
| 調整役 | 波ごとの合流と確かめ、台帳の締め、チェックリストの刷り直し、一括の GT-2、push |
| 利用者 | 残りの裁定、聞き取り、OneDrive の停止、1 枚のチェックリスト、正式公開の判断 |
| 席1 | CR-753 → CR-755 → CR-754（＋DFC-2517）→ W4 → W5 → チェックリストの直し |
| 席2 | CR-740 → CR-756 → 罠の束 → 実装待ちの残り → DFC-730 → CR-695 |
| 席3 | 工程の強制の道具 → CR-752 → T-064 の呼び方 → 聞き取り分の CR → CR-697 |
| 席4 | CR-758 → CR-757 → 用語集の JSON → 仕様待ちの残り → DFC-2214・2215 |
| 席5 | JDG-2071 の調べ → 再検討 → 規則と検査 → 試験待ち 7 行 → 未検討のトリアージ → その直し |

薄い箱（ハイライトの箱）は **波 A・B・C** の幅である。波は「1 つのファイルの組に書き手は 1 人」を守るための順で、波 B は波 A の合流を、波 C（CR-754）は波 B の合流を待つ（パネルの幅は波 B が足す行の後に測る）。依存線は「前が終わってから始める」（終了→開始、ずれ 0）だけを使った。

## 置いた仮定（調整役が直してよい）

- 動いている席（聞き取り・JDG-2071 の調べ・工程の道具）は始まりの時刻を測っていないので、実績を書かず 10-15 09:00 からの計画として置いた
- AI 連携は一括の GT-2 の後に回し、正式公開の判断はその完了を待たない（`JDG-1740` の 3 条件は解明・リファクタ・分刻みの日程）
- W4・W5 は波の CR と同じファイルを割るので、波 C の合流の後に 1 つの席で順に置いた（`JDG-1479`: W5 は W4 の後）
- T-064 の呼び方は仕様の設計の原稿を波 B と同時に触る。合流は調整役が受ける

## スキーマで迷った点

書式はスキーマ（`docs/spec/_source/grs-document.schema.json`）だけを読んで書いた。次の点はスキーマだけでは決められなかった。

1. **始まっていないタスクの `percentComplete`** —— 「日付が与えるものを書け」とあるが、`actualStart` が無いとき 0 か `null` かを言わない（0 と書いた。出荷物は数え直さなかった）。
2. **予定の全体が稼働の時間帯の外にあるタスク** —— 予定の長さが稼働の分で 0 になる。`percentComplete` の「予定の長さが無い（マイルストーン）」の決まりがマイルストーンでないタスクにも及ぶかを言わない。夜中に済んだ CR-751 は、これを避けてマイルストーンにした。
3. **マイルストーンとプロジェクトの開始を稼働の外の瞬間に置いてよいか** —— CR-751 の完了（03:04）と `startDate` を稼働の外に置いた。開始側の値として次の時間帯の始まりへ読み替えられるのかを言わない。
4. **`fadeInDays`／`fadeOutDays` が日の単位である** —— 数時間のタスクの「確かでない終わり」を表せない。日が稼働日か暦の日か、`minutesPerDay` の長さかも言わない。仮置きは色で表した。
5. **ハイライトの箱の範囲に分の時刻を書いてよいか** —— 説明は「日の全体の範囲は 00:00:00 から 23:59:00」とだけ言う。波の幅を分で書いた。分で描かれるか、日へ丸めて描かれるかを言わない。`topGroupId`／`bottomGroupId` が両端を含むかも言わない。
6. **ずれ 0 の依存の `lagFormat`** —— `lag` が 0 のとき何を書くか（7 か `null` か）を言わない（7 と書いた）。
7. **`minutesPerWeek`・`daysPerMonth` が暦と揃う必要があるか** —— `minutesPerDay` には揃えよとあるが、この 2 つは何に使われるかを言わない（毎日稼働なので 5040 と 30 と書いた）。
8. **基の暦の `baseCalendarUid`** —— `null` か、MS Project の書く `-1` かを言わない（`null` と書いた）。`Calendar.ordinal` が何の順かも言わない。
9. **マイルストーンでないタスクの `milestoneGlyph`** —— 必須の列だが、矩形のタスクに何を書くか（既定の `diamond` か `null` か）を言わない。
10. **名前の色の暗いテーマでの見え方** —— `#明/#暗` は両テーマを書けるが、`lightgray` などの名前の色が暗いテーマで何色になるかを言わない。
11. **「誰がやるか」をどこに書くか** —— タスクグループ（行）と担当（`Resource`＋`Assignment`）のどちらで表すのが本来かを言わない。席を行にし、担当は使わなかった。
12. **`documentStamp.lastEditedBy`・`Project.author` に何を書くか** —— 人の名か書き手の名か、公開の文書で個人の名を避けたいときにどうするかを言わない（`project-plan session` と `null` と書いた）。
