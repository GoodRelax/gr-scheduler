## 行（タスクグループ）と色

1 行が 1 つの持ち手である。席は並行に動くセッションで、5 つ。1 つの席は 1 度に 1 つのタスクだけを持つ（調整役の行だけは重なってよい）。利用者の行のバーは利用者の時間帯をまたいで長く見える。

| 色 | 意味 |
|---|---|
| 濃い灰 | 済み（実績の開始と終了を持つ。3 つの「済み」の行） |
| 青 | CR の当て |
| 緑 | 並行の仕事（紹介頁・片付け・台帳・リファクタ） |
| 薄い灰 | **仮置き** —— tier B の候補（利用者が選ぶ）、トリアージの直し、チェックリストの直し |
| 紫 | 調整役の合流と関門 |
| 橙 | 利用者の手番 |
| 青緑 | AI 連携 |
| 赤（星） | α 版のお披露目・正式公開の判断・計画の終わり |

マイルストーンは 7 つ: OneDrive を止める・refactor と main へ push・CR-774 と紹介頁の push・α 版のお披露目・週の使用量の戻り・正式公開の判断（`JDG-1740`）・計画の終わり。

**依存線**は「前が終わってから始める」だけを使い、同じ行の中の線・もっと長い道で同じ所へ届く線・「tier B の入った先端の GT-2」と「全部の合流と台帳の締め」へ集まる線は描かない（利用者の指示 2026-10-15。表の下のコメントが何を待つかを言う）。全 75 本のうち描いているのは 34 本。⚠️ 描かない線は文書の依存にも無いので、遅延診断（`BD-2`）はその先の遅れを出さない。

## スキーマで迷った点

書式はスキーマ（`docs/spec/_source/grs-document.schema.json`）だけを読んで書いた。台帳の行は括弧の中。

1. 始まっていないタスクの `percentComplete` は 0 か `null` か（0 と書いた）。（`DFC-2690`）
2. 予定の全体が稼働の時間帯の外にあるタスクの完了率。（`DFC-2691`）
3. マイルストーンとプロジェクトの開始を稼働の外の瞬間に置いてよいか。（`DFC-2692`）
4. `fadeInDays`／`fadeOutDays` が日の単位で、数時間のタスクの確かでない端を表せない。（`DFC-2693`）
5. ハイライトの箱とコメントの付け根の時刻（仕様 `LF-15`・`WT-8` はスキーマに無い）、`bodyOffsetPx` の向きと単位。（`DFC-2694`）
6. ずれ 0 の依存の `lagFormat`（7 と書いた）。（`DFC-2564`）
7. `minutesPerWeek`・`daysPerMonth` を暦と揃えるか。（`DFC-2568`）
8. 基の暦の `baseCalendarUid` と `Calendar.ordinal`。（`DFC-2562`・`DFC-2560`）
9. マイルストーンでないタスクの `milestoneGlyph`。（`DFC-2563`）
10. 名前の色の暗いテーマでの見え方。（`DFC-2695`）
11. 「誰がやるか」は行と担当のどちらか。（`DFC-2696`）
12. `lastEditedBy`・`author` に何を書くか。（`DFC-2562`）
13. 24 時間稼働の暦の書き方と `defaultFinishTime`。（`DFC-2697`）
14. 持ち手ごとの稼働時間を書けない。（`DFC-2698`）
15. 「この時刻より前には始めない」を書く場所が無い（`deadline` は遅くともの意味）—— 時刻の決まった仕事はマイルストーンやタスクの `start` に直に書いた（台帳の行は調整役に任せた）
