**ORIGIN**: UC-015.OK

**RATIONALE**: タスクグループ（`TaskGroup`）に詰めて描くので、`parentTaskUid` が書かれないまま残る。  
導いた親タスクを書き込むと、タスクグループを動かしたときに古い親が残って腐る。  
⭐ 同じタスクグループのバーは時間的に重なりうるので、区間の列として扱えない —— 両端で包含するものだけが候補である。  
親どうしが交差しているとき、どちらが親かは作成者の意図でしか決まらず、幾何に根拠が無い。  
点は中身を持てないのでマイルストーンは親になれない（表 T-311 の `VS-2` と同じ原則）。  
親を確かめる描き方は、導いた親タスクが正しいかを人が検算できる唯一の手段である。  
人が親を結ぶ道（表 T-351）が無いと、親の決まらない子の紫（表 T-316 の `DW-2`）を `GRS` の中で消せず、「紫を無くせ」が閉じない —— 選ぶのは人であり、並べるだけで選ばないのは、交差する親のどちらが親かは作成者の意図でしか決まらないからである。  
⭐ 一覧から親を選ぶ面を置かないのは、親タスク設定のドラッグが既に同じ仕事をし、2 つ目の作法を覚えさせないためである。  
⭐ パネルの親の名を押して親へ飛ぶのは、検索パネルと遅延診断レポートの青い下線のタスク名（表 T-331 の `SQ-1`）と同じ見せ方に同じ動きを持たせるためである。  
⭐ 親タスクと子タスクを矢印で見せるのは、`!!`（表 T-315 の `DG-3`）がどの親タスクと子タスクから来たかを画面で読めるようにするためである。  
家族だけを描くのは、全部を描くと 1 枚の図が線で埋まるからである。  
親を確かめる赤い名を親タスク表示の入の間に限るのは、遠く離れた親タスクと子タスクでは、関係の無いタスクの名が急に赤くなって意味が読めないからである。  
⭐ 結ぶ手を依存線を引く手（表 T-023b の `AR-4`）と同じ形にしたのは、説明を読まずに操作できるようにするためである（`GL-006`）。
