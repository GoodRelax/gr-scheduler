GRS とは

作図の描きやすさと、日程データの構造を、1 つにした道具。

  • 作図ソフトの日程表は絵であり、データにならない。
  • 日程管理ソフトは 1 行に 1 タスク。全体が 1 画面に収まらない。
  • 遅れたタスクは見えても、遅れの出どころは見えない。

GRS は、描く手軽さのまま、構造化した日程データを出す。

ペライチ

1 行に複数のタスク。全体日程を 1 画面に収める。

ぬるサク

操作が引っかからない。性能は節目ごとに実測する。

すぐわか

マニュアル無しで使える。画面は日本語と英語。

直接操作

描いたバーを掴んで、日付を変える。

構造化データ

日程と設定は GRS 独自の JSON に保存。
MS Project の XML（MSPDI）の読み書きも可能。

単一 HTML

サーバー不要。インストール不要。現時点では外部と連携しない。

遅延診断

遅れの発生源と、信用できない数字を示す。

AI 連携

Agent API と MCP 連携で、AI が人と同じ操作をできる。

透かし

開いた人の名前と日時を、画面に薄く重ねる。

持たないもの自動日程・資源とコストの管理・サーバーと共同編集・タッチ操作

1 つの文書を 1 つの JSON で表す。MSPDI の形をそのまま持ち、見せ方を別に足す。

更新と保存の時刻、最後に書いた者

全エンティティと列は、仕様書の ER 図 ↗にある。

  1. タスク・WBS は MSPDI 準拠の構造

    タスクグループと画面構成は GRS 専用のデータ。

  2. 識別子は MSPDI の UID

    代理キーを作らない。合流も UID で照合する。

  3. 予定と実績は 1 つのタスク

    MSPDI と同じ列名で持つ（start / actualStart など）。

  4. 未使用の MSPDI 要素

    GRS で使わない MSPDI の要素も破棄しない。

  5. JSON スキーマを提供

    AI が容易に解釈可能なスキーマ。grs-document.schema.json ↗

AI で開発しやすい理由
  • 仕様書が唯一の正。表や ER 図から型とスキーマを生成する。
  • 仕様と実装のずれを、機械の検査が毎回測る。
  • 変更は CR 1 件ずつ。影響範囲を測ってから当てる。
  • 試験は、書いた者とは別のエージェントが仕様書から書く。

機能拡張トライアル

手元のソフトの出力を、AI に GRS JSON へ変換させ、GRS に落として試す。

  1. 1 AI に渡す

    接続したいソフトの出力形式の仕様（あればスキーマ）と、そのサンプルデータ。

    もう 1 つ、GRS JSON のスキーマ: grs-document.schema.json ↗

  2. 2 変換を頼む

    「サンプルデータを GRS の JSON に変換して」と指示する。

    合わない所は、そのまま対話を続けて直させる。

  3. 3 詰まったら資料を足す

    GRS のリポジトリをダウンロードして、AI に渡す。仕様書（docs/spec）とコードが手がかりになる。

    GitHub のリポジトリ ↗

  4. 4 GRS に落とす

    AI が作った GRS JSON を、GRS の日程表へドラッグ＆ドロップする。

    「置き換える」を押すと開く。

AI への指示の例
添付のサンプルデータを、添付の GRS JSON スキーマに合う JSON に変換してください。
写せない項目は、どう扱うか私に聞いてください。
目的は、受け取った人が、GRS の拡張性を自分で確かめること。

GRS 側のコードは変えない。変換は、AI と手元の道具の側で済ませる。
