## 7. ⛔ 新しく出た本物 —— **測っている形が「保存形」ではない**

| | |
|---|---|
| どこ | `document-change-plan.ts` の `stepSize` |
| 破っている規則 | `FR-031`（MUST）|
| 逐語 | 「**1 段の大きさは、その段の保存形を UTF-8 で符号化した長さ（バイト）で測ること（MUST）。**」 |

```
実装      utf8Length(JSON.stringify(document))            → 655,969 バイト（詰めた形）
保存形    JSON.stringify(document, null, 1) + '\n'        → 895,286 バイト（json-codec.ts）
```

⛔ **同じ文書で 36% 違う。** ⚠️ **合計メモリの予算が仕様より緩い。**

⭐ **単純な直しではない** —— **保存形を作るのは `DocumentCodec`（`Adapter`）であり、測る側は `UseCase` である。**
⛔ **`LR-1` は外向きの依存を禁じている**ので、呼びに行けない。⭐ **道は 3 つある:**

```
1. FR-031 が「詰めた符号化で測る」と述べる（＝実装が正しかったことにする）
2. 段の大きさを引数で渡す（測る責務を外側へ出す）
3. 純粋な直列化を内側へ動かす
```

⚠️ **いまは効いていない** —— この文書なら 50 段で 32.8MB、`S-95` の 64MB に届かない。
⛔ **`S-95` が噛み始めるのは、およそ 1.3MB を超える文書からである。**
