# `D-` と `R-` の衝突を解く

⭐⭐ **裁定は 2026-09-13 に下りた（利用者の裁定、逐語: 「すべ提案通りにやれ」）。**
第 3 節の 3 つはすべて推奨案で確定している。下の表がその控えである。

| 裁定 | 決まったこと |
|---|---|
| **1 範囲** | **案 A —— 両側とも改名する。**`D-` と `R-` はどこにも残らない |
| **2 綴り** | 表 T-007 機器 → **`DEV-`**　表 T-008 経路 → **`CHN-`**　台帳の欠陥 → **`DFC-`**　台帳の裁定 → **`JDG-`** |
| **3 レビュー文書** | **既存の 309 行は触らない（範囲外として門で名指しする）。規則を立てて次を止める** |

⚠️ **綴りの根拠**（発明ではないことを記録する）:

- **`DEV`** —— 登録簿が `D` の `words` を **`Device`** と既に持っている。⭐ 登録簿は
  「読めない語を発明するな」と定めるので、これは**記録済みの展開**である
- **`CHN`**（Channel）—— ⛔ **`RTE-` を選ばなかった理由は実測である**: `RT` が既に
  「依存線の経路が満たす規則」、`RP` が「依存線の経路の分岐」であり、
  **「経路」は仕様書のなかで既に別のものに使われている。**`RT-1` と `RTE-1` を
  並べるのは、いま直している欠陥と同型である。表 T-008 の列（from / to / 運ぶもの /
  方式 / 信頼できるか）は channel の列である。⭐ **表の題名「経路」は変えない**
  —— `PTD`（判定順序の段）の先例どおり、**綴りは題名の訳でなくてよい**
- **`DFC`** —— `DEF-` は default ／ definition と読めて劣る
- **`JDG`** —— `RLG-` も空いているが `RL`（実体間の関係）と 1 字違いで、
  `RT`/`RTE` と同じ辍である。`RUL-` は「規則」と紛れる

⛔ `DEV` `CHN` `DFC` `JDG` はいずれも未使用である（実測 2026-09-13。
既存の 3 文字は `PLM` `PND` `PTD` の 3 つだけ）。

⚠️ **数はすべて 2026-09-13 の実測で、方法を添えてある。**
⛔ 前の巡（CR-371）で、引き継ぎの数の 7 つが実測と食い違った。
**本書の数も、信じる前に下の走らせ方で測り直せ。**
