# 裁定 02 —— 非同期の答えが、フレームへどう戻るか

**日付**: 2026-08-22 ／ **仕様**: 0.85 ／ **分類**: **G**（他の規則の論証が乗っている）
**止まるもの**: ⛔ **ファイルを開く・保存する**（人の応答を待つ操作すべて）
**止まらないもの**: いま動いているもの全部

⚠️ **本書は調査と提案の記録である。仕様ではない。**

---

## 1. ユースケース

> 作成者が日程を掴んで整えた。`Ctrl+O` を押す。ブラウザのファイル選択が開く。
> 共有ドライブを **40 秒**スクロールして目的のファイルを探し、ダブルクリックする。

⛔ **その 40 秒のあいだ、窓は生きています。** 大きさは変えられるし、ポインタは動くし、自動保存の時計も進みます。
⭐ **そしてダブルクリックした瞬間、40 秒前の画面に対して計算された文書が現在値にならなければなりません。**

⛔ **仕様は、この 40 秒について 1 文字も書いていません。**

---

## 2. 課題

### 2.1 ⛔ 仕様は非同期という語を 1 度も使っていない（**実測**）

```
docs/spec 全体で  非同期 / Promise / async / await / 待機  の出現回数 = 0
```

⭐ **`Promise` はすべて `src/` 側の決定です。** 継ぎ目の側（表 T-065 の `IF-3`）はこう書くだけです:

```
| IF-3 | FileStore | FileGateway（CP-22） | FileSystemAccessFileStore（CP-28） |
        ファイルの読み書き。ハンドルは実装が保持する（FR-060） |
```

⚠️ **つまり「仕様は既に非同期を受け入れている」とは言えません。** ⛔ **`src/` が決めたことです。**

### 2.2 ⛔ 3 つの MUST がこの隙間で衝突する

| | 逐語 | どこ |
|---|---|---|
| **表 T-078** | 「**本表に無い契機でフレームを起こしてはならない（MUST NOT）**」。契機は 5 つ（人の入力／現在値の差し替え／寸法／時間／発話）| `05-07-design.md:591` |
| **`R7.4`** | 「処理の途中で新たな外部読取を行わない。読取は処理開始前に完結させる」 | 規則 07 |
| **`CA-3`** | 「許容する陳腐化 ＝ **1 フレームぶん**。⚠️ **フレームの途中で文書が変わることは無い**」 | `05-07-design.md:648` |

⛔ **`openDocumentFile` の第 1 文は `await store.readFileToOpen(route)`** —— **`receiveInput` が既に外を 1 度集めて文脈を組んだ後に、新しい外部読取を始めます。** `R7.4` の正面です。

⛔ **そして `CA-3` の「フレームの途中で文書が変わることは無い」は、その根拠に 2 つの拒否（`AG-9` と `WS-2`）しか挙げていません。** ⚠️ **どちらもファイル選択が開いているあいだ何も拒否しません。**

### 2.3 ⭐ ただし、着地そのものは既に許されている（**重要**）

⚠️ **私は当初「表 T-078 に契機が無い」と読みました。それは半分だけ正しい。**

⭐ **`FT-2` の契機は「現在値の差し替え（表 T-067 の `WS-6`）」です。**
⭐ **そして `PI-8` は `replaceDocument`（「外で組み立てた文書を現在値にする。段は 表 T-067」）を公開しています。**

```
ファイル選択が閉じる → 文書が組み上がる → replaceDocument → WS-6 → FT-2
                                                              ⭐ 既に許された契機
```

⛔ **したがって「着地のフレームをどう起こすか」は問題ではありません。** ⚠️ **問題は「待っているあいだ」です。**

### 2.4 ⛔ 待っているあいだに壊れるもの

`frameLoop` が持っている値は全部 `let` です。**待っているあいだに、どれも動きます:**

```
held（文書と履歴）／ environment（寸法）／ selection ／ screenState ／ pressed ／
pointerAt ／ partUnderPointer ／ isDualCursorMode ／ values（フレームの 3 値）／ owed
```

⛔ **具体的に壊れる順序**:

> `Ctrl+O` → ファイル選択が開く → **その間に窓の大きさが変わる**（`FT-3` がフレームを走らせ `values` を作り直す）
> → ファイルが選ばれる → 40 秒前の `values` に対して組んだ文書が着地する

⚠️ **表 T-066 には、この操作を覆う一貫性の単位がありません。** `CS-1` は 1 フレーム、`CS-2` は身振り 1 回、`CS-3` は書き込み 1 回。**どれも「人の応答を待つ 1 回のファイル操作」を覆いません。**

## 4. 推奨 —— **C ＋ D。⛔ 表 T-078 には行を足さない**

⭐ **推奨**:

```
1. シェルが約束を持つ（C）
   carryOutAction は操作を「始める」だけで void を返す。await はシェル側にある
2. 表 T-066 に 4 つ目の単位を足す（D）
   「人の応答を待つ 1 回のファイル操作」——
   始める前に要るものを全部集め、待つあいだ現在値を読まない、
   終わったら replaceDocument で着地する
3. ⛔ 表 T-078 は 1 行も足さない
   着地は WS-6 であり、FT-2 が既に覆っている
```

**根拠**:

1. ⭐ **C だけが `R7.4` を修復する。** A・B は「外部読取が処理の途中に入る」ことを許したまま名前を付け替えるだけです
2. ⭐ **D は `R7.4` 自身が求めている形です** —— 逃げ道の文言が「一貫性の単位を明示し」と言っており、**表 T-066 はまさにその明示のための表です**（5.5 の前文がそう書いている）
3. ⭐ **前例がある。** 表 T-066 の注は既に「起動の収集は 3 単位のどれでもない」と書いて 4 つ目を散文で認めています。**行にするのは、その散文を表へ下ろすだけです**
4. ⭐ **B を退ける理由が強い** —— **着地は本当に `WS-6` です。** 6 行目を足すと、`FT-2` と同じ出来事に 2 つの名前が付き、**「全数」を謳う表が全数でなくなります**

⛔ **代償を正直に**: **`CA-3`（「フレームの途中で文書が変わることは無い」）は偽になるので、同じ回で直す必要があります。** ⚠️ 4 つ目の単位は「フレームをまたぐ」ので、`CA-3` は「1 フレームぶん、ただし待っている操作の着地は別」と書き換わります。
