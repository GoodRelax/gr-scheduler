# 裁定 04 —— 単位を名前に持たない上限（`maxTotalSize`）

**日付**: 2026-08-22 ／ **仕様**: 0.85 ／ **分類**: **E**（⚠️ **ただし覆すコストは A 並み。§5 を見よ**）
**止まるもの**: ⛔ **何も止まらない。** 直っており、試験も入っている
**なぜ裁定が要るか**: **同じ欠陥がもう 1 度出る形が残っているから**

⚠️ **本書は調査と提案の記録である。仕様ではない。**

---

## 1. ユースケース —— **実際に起きたことである**

> 作成者がバーを 12 日から 19 日へ動かす。もう 1 本動かす。`Ctrl+Z` を押す。
> 2 本目が戻る。もう一度 `Ctrl+Z` を押す —— **何も動かない。**

⛔ **履歴は、どの文書でも、永久に 1 段しか持てませんでした。**
`S-94` と `FR-031` は **50 段**を約束しています。**ずれは 1,048,576 倍**でした。

⛔ **原因**: シェルが `64` という裸の数を渡し、受け取った側は **UTF-8 バイト**で比べていました。

```
S-95 の既定  「64 MB 🔎」        ← 原稿は メガバイト で述べる
比べる側     totalSize(done) > limits.maxTotalSize   ← バイト で数えた合計
1 段の大きさ 655,969 バイト（起動テンプレート）
```

⛔ **`tsc` は通りました。両側とも `number` だからです。**
⛔ **2,296 件の試験も 1 件も捕まえませんでした。**

⭐ **`R2.1` は MUST で、その理由にこう書いてあります**:

```
単位が固定の量は名前に単位を入れる。timeoutMs / voltageMv / capacityAh。
単位の取り違えは型検査を通り抜ける。
```

⚠️ **規約が予告したとおりのことが、そのまま起きました。**

## 2. 課題 —— **直したが、同じ形が残っている**

`CR-208` の回で換算を入れ、`tests/unit/uf-8-9-history-depth.test.ts`（21 件）で固定しました。
⛔ **しかし、名前は 1 つも変わっていません。**

比べている行を見ると、**単位を名乗らない量が 2 つ**あります:

```
while (done.length > 1 && totalSize(done) > limits.maxTotalSize) done = done.slice(1)
                          ↑ HeldStep.size の総和        ↑ 上限
                          どちらも「バイト」と名乗っていない
```

⭐ **`R2.1` の文言は「単位が固定の**量**は」です。** ⛔ **`HeldStep.size` も、`stepSize()` の戻り値も、同じ違反です。**
⚠️ **上限だけ直すと、指摘の文面は閉じますが、欠陥の型は開いたままです。**

### ⛔ 見つかった追加の事実（**反論が出し、私も確認した**）

```
tsconfig.json    "include": ["src", "vite.config.ts", "vitest.config.ts", "playwright.config.ts"]
tsconfig.entity.json  "include": ["src/entity", "src/use-case"]
```

⛔ **`tsc` は `tests/` を 1 行も型検査していません。**
⚠️ **つまり「改名すれば型検査が全部の呼び出し元を見つける」は、`src/` にしか当てはまりません。**
⭐ **試験側の綴りは、走らせて初めて落ちます。**（vitest は型検査せずに変換するため、**実行時まで気づきません**）

## 3. 対応案

| # | 形 | ⭐ 利点 | ⛔ 代償 |
|---|---|---|---|
| **1** | **上限だけ改名**（`maxTotalSize` → `maxTotalSizeBytes`）| ⭐ 3 行で済む | ⛔ **比べている相手（`size`）が単位を名乗らないまま残る。** 欠陥の型が閉じない |
| **2** ⭐ | **比べる両側を改名**（`maxTotalSizeBytes` ＋ `sizeBytes` ＋ `stepSizeBytes`）| ⭐ **`R2.1` の文言どおり「量」を全部直す。** ⭐ 読んだ人が単位を取り違えようがない | ⚠️ `src/` 6 行 ＋ 試験 16 行。⛔ **試験側は `tsc` が見ないので、走らせて確かめる必要がある** |
| **3** | **名前は変えず、型に単位を持たせる**（`type Bytes = number & {…}`）| ⭐ 取り違えを型検査が捕まえる | ⛔ **この repo に前例が無い。** ⚠️ 生成器が刷る `NOT_STORED_LIMITS` は素の `number` なので、境界で必ず 1 度剥がすことになる |
| **4** ⭐ | **名前は変えず、境界を試験で押さえる** | ⭐ **いちばん安い。** ⭐ **いま本当に守られていない線を直接塞ぐ**（§4）| ⛔ **`R2.1` は MUST であり、これは満たさない。** 指摘は開いたまま |
| **5** | **単位を名乗らない固定単位のメンバを全部掃く**（設定値 34 個ほか）| ⭐ 一度で片が付く | ⛔ **生成器・原稿・型・試験に広く当たる。** ⚠️ 本件の 100 倍の面積。**別の回にすべき** |

## 4. 推奨 —— **2 ＋ 4 を一緒に。⛔ 5 は別の回**

⭐ **推奨**:

```
2  比べる両側を改名する（maxTotalSizeBytes / sizeBytes / stepSizeBytes）
4  シェルの換算そのものを押さえる試験を足す
```

**根拠**:

1. ⭐ **`R2.1` は「量」に掛かる。上限だけ直すのは文面を閉じて型を開けたままにする**（規則 06 の 2. が「1 ファイルで完結するかでは線を引けない」と警告する形）
2. ⭐ **4 が要る理由が独立に強い** —— ⛔ **シェルの換算は、いまどの試験からも観測できません。** `HISTORY_LIMITS` は module 私有で、`FrameLoop` は履歴も深さも公開しません。**つまり「`64` に戻す」改変を、いまの試験は 1 件も捕まえられません。**
   ⚠️ **`uf-8-9-history-depth.test.ts` が押さえているのは「経路と上限の意味」であり、「シェルがその上限を作る 1 行」ではありません**
3. ⭐ **5 を退ける理由**: 面積が 2 桁違い、生成器と原稿に当たるので、**本件と混ぜると本件が終わりません**

⛔ **代償を正直に**: **試験側 16 行は `tsc` が見ないので、改名したら必ず `npm test` を走らせて確かめる必要があります。**

## 5. ⚠️ 分類について —— **E だが、E の理由は当てはまらない**

規則 06 の `E` は「公開署名・継ぎ目（表 T-064 / T-065）を決めるもの」であり、その代償は
「**他ユニットがそれに対して書かれ、その試験ごと無効になる**」です。

⛔ **本件では、無効になるものが 1 つもありません**:

```
`src/` 6 行と試験 16 行の 綴り が変わるだけ
tsc が src/ 側を全部捕まえる
試験の 意味 は 1 つも変わらない
保存される文書も MSPDI の要素も 1 つも動かない
docs/spec は 0 文字動く
```

⭐ **形式上は `E`（`HistoryLimits` は `PI-4` と `PI-8` の署名に載っている）ですが、覆すコストは `A` 並みです。**
⚠️ **規則 06 の 6. が「分類の根拠を 1 行書く」ことを求めているのは、まさにこの食い違いのためです。**
⭐ **したがって、これは「待つべき裁定」というより「即断できる裁定」です。**
