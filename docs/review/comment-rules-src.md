# src/ のコメント規則（裁定 17、利用者の裁定 2026-09-13）

⛔ **`src/` のコメントは、本書の第 3 節の形だけを書く。** 第 6-3 節（[`cleanup-2026-09-11-prompt.md`](cleanup-2026-09-11-prompt.md)）と裁定 16 が本書と食い違うときは、本書に従う。
⭐ 根拠: 命名と SSOT を徹底したので、仕様書とコードを見れば分かることが大半になった。多いコメントは腐り、この巡の実測でも事実でない文が 100 件以上見つかった。

## 1. 文字

**ASCII の印字可能文字（0x20〜0x7E）だけ。** 日本語も、⭐ ⛔ ⚠️ などの記号も書かない。

## 2. 密度

| 項目 | 定め |
|---|---|
| 密度 | コメント行 ÷（コード行 ＋ コメント行） |
| コメント行 | コメントの文字を含む行。**行末コメント（`code // see GR-21`）も 1 行と数える**。`/**`・` *`・` */` だけの行も数える |
| 数えない行 | コメントが `@purity` のタグだけの行 |
| 生成領域 | `<generated -- do not edit by hand>` から `</generated>` までは、コードにもコメントにも数えない |
| 上限 | **木全体で 10% 以下。** 加えて、**コード 100 行以上のファイルはファイルごとにも 10% 以下** |

## 3. 書いてよい形（これ以外は書かない）

| 形 | 書く場所 | 上限 | 書いてよい条件 |
|---|---|---|---|
| `// see FR-013` ／ `// see FR-013, T-021` | **関数・クラス・型の定義の直上** | 1 行 | その定義が実装している仕様の行。関係する行を並べた目録にしない |
| `// TRAP: <何をすると何が壊れるか>` | 壊れる行の直上 | 2 行 | 型・試験・機械検査のどれも止めない壊れ方がある |
| `// WHY: <採らなかった道と理由>` | 該当する行の直上 | 2 行 | 理由が仕様書にもコードにも無い |
| `// STOP: spec does not decide <何を>. Looked in <ID, ...>` ＋ `@provisional PND-n` | 該当する行の直上 | 3 行 | 仕様の穴を仮に埋めている |
| `// DEVIATION: spec says <...>; here <...> (DFC-n)` | 該当する行の直上 | 2 行 | 仕様からわざと外れていて、台帳に行がある |
| `/** @purity pure */` | 関数の直上 | 1 行 | 裁定 4 |
| ファイル頭: 役割 1 行 ＋ `@unit` ／ `@component` ／ `@publishes` | ファイルの先頭 | 5 行 | 各ファイル 1 か所 |
| 生成領域の出どころの見出し | ファイルの先頭 | 検査 21 が求める最小 | 生成領域を持つファイル |

⭐ `see` の行と `@purity` の行が並ぶときは、`// see ...` を上に、`/** @purity ... */` を定義の直前に置く。

## 4. 書かないもの

| # | 書かないもの | 分かる場所 |
|---|---|---|
| 1 | 第 3 節の形以外で仕様の行 ID を書くこと | 定義の `see` の行、生成物、試験の名前 |
| 2 | 仕様の文の言い換え（MUST・値・順序・語） | 仕様書 |
| 3 | 次の宣言や式が言っていること | 名前と型 |
| 4 | 機械が保証していること（層の規則、純粋性、値の範囲） | 検査・`tsc`・生成物の検査 |
| 5 | 他のファイルや関数についての記述。⭐ 例外: TRAP の中で「同時に変える相手」を名指すこと | `grep` |
| 6 | 数・日付・人・経緯・測定値 | Git と台帳 |
| 7 | 見出し・強調・区切り線 | ― |

## 5. 予算に収まらない罠は、コードで守る

⛔ **密度の上限に収まらない TRAP は、コメントで残さない。** 必須のメンバーにする、型を狭める、表明を置くなどで**コードが止める形**に直す。
⭐ **直すのは後でまとめて行う。** 掃除の巡ではコードを変えず、その罠を [`defects.md`](../development-records/defects.md) に行として起こし、コメントは消す。

## 6. 数値リテラル

⛔ マジックナンバーは禁止である。見つけたら [`magic-numbers.md`](../development-records/magic-numbers.md) の作業表で扱い、コメントで説明しない。
