# 先に足すべき機械検査

**今日 3 度踏んだ型を止められる。**

| 検査 | 内容 | 今日踏んだ実例 |
| --- | --- | --- |
| **行 ID 参照の実在** | 本文が書いた `S-10` / `X-4` のような行 ID が、実在する行か | `XO-5` の中に旧 `S-10` が残り、設定値表の `S-10`（`actualGap`）を指す形になった（`F-11`） |
| **行 ID の重複**（実装済み） | 同じ行 ID が 2 つの表に現れないか | `GL-` を `GOAL` と衝突、`SC-` をスクロール表と衝突 |
| 指し先の行の実在 | 「表 X が持つ」の先に、その**行**があるか | 合言葉・暦・自動保存の間隔・資源上限 |
| 散文の数と表の行数 | 「N 件 / N 項目」を抽出して照合 | 8 か所すべてが腐っていた |

行 ID の重複検査は次のとおり（実行済み・731 個で 0 件）。

```python
import io,re,collections
seen=collections.defaultdict(set)
for f in ['docs/spec/01-04-requirements.md','docs/spec/_assets/tbl-glossary.md','docs/spec/_assets/tbl-settings.md']:
    cur=None
    for line in io.open(f,encoding='utf-8'):
        m=re.match(r'\*\*表 (T-[0-9]+[a-z]?) ', line)
        if m: cur=m.group(1); continue
        m2=re.match(r'\| ([A-Z]{1,3}-[0-9]+[a-z]?) ', line)
        if m2 and cur: seen[m2.group(1)].add(cur)
print([k for k,v in seen.items() if len(v)>1] or 'none')
```

# 指摘 17 件

## Critical

### `F-01` `FR-013` の追記と `PM-1a` が正面から衝突する

- **箇所**: `FR-013` STATEMENT ／ 表 T-021 `PM-1a` ／ `FR-011` の括弧内
- **問題**: `FR-013` は「**実績バーが無いとき（未着手）**、および予定だけを表示しているときは、予定バーの右端の外側に出すこと（MUST）」と定め、`PM-1a` は「未着手 ＝ マーカーを出さない」と定める。**どちらも同じバッチで入れた。** さらに `FR-011` の理由づけ「未着手では進捗マーカーが出ていない（`PM-1` は選択時のみ表示）」は、`PM-1` から未着手を外した後は根拠として成立しない。
- **提案**: `FR-013` の追記から「実績バーが無いとき（未着手）」を落とし、**予定だけを表示しているとき**に限る。`FR-011` の括弧内を `PM-1a` 参照へ差し替える。

### `F-02` `HR-1a` が `ST-7` の 256 段安全弁と `FR-055` を同時に破る

- **箇所**: 表 T-015 `HR-1a` ／ 表 T-014 `ST-7` ／ `FR-055` ／ `tbl-settings.md` の `S-89`
- **問題**: 集約後の姿で段割当を行うなら、全畳みや縦ズームの縮小で 1 行に文書中のほぼ全 `Task` が集まる。目標規模（50 行 / 1000 `Task`）でも 256 を容易に超え、**`ST-7` によりエラーで処理が止まる。** 一方 `FR-055` は最も縮めたときに収まることを MUST で求めており、**その状態こそ最も集約が進む。** `S-89` の「256 段は実務では起きない。届いたら異常」という前提も、通常のズーム操作で到達する時点で崩れる。
- **提案**: `HR-1a` に「集約して描くときは段割当を行わず、代表の 1 段（またはグループ LOD の縮約表現）で描く」と書き、`ST-7` の安全弁の対象を「**人が置いた `Task` が同時に重なる段数**」に限定する。

### `F-03` `start`/`finish` 欠落の拒否が `EX-5` を実行不能にする

- **箇所**: `FR-012` の注記 ／ 表 T-033 `EX-5`
- **問題**: `EX-5` は「取り込んだ文書に**中身のない行**が含まれるとき、タスクとして画面に出さず、書き出しでは元の位置と形のまま戻すこと」と定める。中身のない行は日付を持たない。`FR-023` は「超えた入力は取り込まずに知らせること（MUST）。**部分的に適用してはならない（MUST NOT）**」なので、**中身のない行が 1 つでもあるとファイルごと拒否される。** `FR-021` の往復無損失も同時に落ちる。
- **提案**: `FR-012` の禁止を「**画面に出す `Task`**」に限定し、`EX-5` の対象を明示的に除外する。

### `F-08` `FR-049` の代替経路をプロパティパネルに限ったため、依存線の操作が全滅する

### `F-09` `AR-5`（コメントを構えて当たったとき）が `PD-3` により到達できない

### `F-10` `OP-2` と `FR-022` が同じ入口を奪い合う
