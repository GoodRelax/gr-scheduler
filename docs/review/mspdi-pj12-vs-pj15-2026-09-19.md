# MSPDI スキーマ pj12 と pj15 の比較 —— GRS が両方を扱うために（2026-09-19）

> **目的**: GRS を MSPDI の pj12（Project 2007）と pj15（Project 2013）の両方に対応させる前に、2 つのスキーマの差と、
> いまの GRS がその差にどう振る舞うかを実測で押さえる。仕様書はまだ変えない（変えるのは第 6 節の問いに答えが出てから）。
>
> **読んだ木**: `5a2d67d9`（ブランチ `mspdi-pj15`）。⭐ 数にはすべて測り方を添えた（第 7 節）。

## 1. 結論

| # | 結論 | 根拠 |
|---|---|---|
| 1 | **pj15 は pj12 に任意の要素を 17 個足しただけである。** 消えた要素・型や出現回数や列挙値が変わった要素・名前付きの型の変化は、どれも 0 | 第 3 節 |
| 2 | **既存の要素の並びは変わっていない**（足された要素が間に入っただけ）。⇒ **pj12 に妥当な文書は、そのまま pj15 にも妥当である** | 第 3.2 節。探針の `in-pj12b` が両方に妥当 |
| 3 | **ファイルは自分の版を名前空間で名乗らない。** 名前空間は両方とも `http://schemas.microsoft.com/project/2007`。⚠️ **pj15 自身の説明では、Project 2013 が書くのは `SaveVersion` 14**（15 ではない） | 第 3.3 節 |
| 4 | **GRS がゼロから書いた文書は、pj12 にも pj15 にも妥当である**（`OutlineCodes` を含まない限り —— 結論 6） | 探針 `out-pj12b` |
| 5 | **pj15 の文書を GRS で往復させると、17 要素は 1 つも落ちないが、親の末尾へ回されて pj15 に不妥当になる**（探針で lxml の誤り 5 件）。原因は、子の並び順が pj12 の並びで固定され、そこに無い名前を最後に置くこと（`mspdi-codec.ts:59`、`:580`〜`:584`） | 第 4 節 |
| 6 | 既知の `DFC-563`（持ち回った要素の並びが変わる）は、**pj12 だけの文書でも `EX-1`（公式スキーマに妥当）を破る。** `OutlineCode` の `Values` が後ろへ回され、pj12 にも pj15 にも不妥当になった | 第 4.2 節 |
| 7 | **pj15 には公式 URL が無い**（HTTP 404）。⇒ 仕様書の「MSPDI の正は公式 URL を引く」（`A-appendix.md` A.1、`05-07-design.md:1260`）は pj15 には当てられない | 第 2 節 |
| 8 | **`learn-docs/` はどちらの版とも一致しない。** 両方の XSD に無い要素を 47 個説明し、pj15 で足された 17 要素はどれも説明していない | 第 5 節 |

### 3.2 変わらなかったもの

| 見たもの | 差 |
|---|---|
| 消えた要素（要素の道筋で数えた）| **0**（pj12 681 → pj15 698）|

### 3.3 説明文だけが変わった要素（1 個）

`Project/SaveVersion`（`mspdi_pj12.xsd:232`、`mspdi_pj15.xsd:231`）。型は両方とも `xsd:integer`。
pj12 は「12 = Project 2007」だけを挙げる。pj15 は「14 = Project 2010」を足し、**Project 2013 は Project 2010 と同じ XML の版を書く** と述べる。
⇒ **ファイルの中身は「SaveVersion 12 / 14」で呼び、「pj15 のファイル」「版 15 のファイル」とは呼ばない。**

## 4. いまの GRS の振る舞い（実測）

### 4.1 探針の結果

実際の `documentFromMspdi` → `mspdiFromDocument` で往復させ、出力を lxml で両方の XSD に照らした（測り方は第 7 節）。

| 入力 | 入力の妥当性 pj12 ／ pj15 | 出力の妥当性 pj12 ／ pj15 | 通知 |
|---|---|---|---|
| `in-pj12b` —— pj12 の要素だけ、`OutlineCodes` なし | 妥当 ／ 妥当 | **妥当 ／ 妥当** | 0 |
| `in-pj15b` —— 17 要素のうち 15 個（`OutlineCodes` ごと `ShowIndent` と `IsCollapsed` を除いた）、`SaveVersion` 14 | 不妥当 ／ 妥当 | 不妥当 ／ **不妥当（誤り 5 件）** | 0 |
| `in-pj12` —— pj12 の要素だけ、`OutlineCodes` あり | 妥当 ／ 妥当 | **不妥当 ／ 不妥当**（`DFC-563`）| 0 |
| `in-pj15` —— 17 要素すべて | 不妥当 ／ 妥当 | 不妥当 ／ 不妥当 | 0 |

`in-pj15b` の出力に lxml が挙げた誤り 5 件（⚠️ lxml は 1 つの親につき最初の 1 件しか挙げない）: `Calendar/IsBaselineCalendar`、`Task/DisplayAsSummary`（2 タスク）、`Assignment/RateScale`、`Project/BaslineCalendar`。
位置のずれた要素そのものは、`Project` 直下の 4 個（`Assignments` の後ろへ回された）、`PredecessorLink` と `TimephasedData` を持つタスクの 8 個（全部がその後ろ）、`Summary` と `FreeSlack` だけを持つタスクの `DisplayAsSummary`（`FreeSlack` の後ろ）、`IsBaselineCalendar`（`WeekDays` の後ろ）、`RateScale`（`Units` の後ろ）である。
⚠️ 末尾に回されても、後ろに既存の兄弟が無ければ偶然正しい位置になる（探針のタスク 3 の `Active` と `Manual`）。⇒ 妥当かどうかは文書ごとに変わり、試験の見本しだいで見逃す。
⭐ **17 要素はどれも落ちていない**（全部が出力に残った）。落とすのではなく位置がずれる。
⭐ `ExtendedAttribute/SecondaryGuid` は位置を保った —— `ExtendedAttribute` には並び順の表が無く、届いた順のまま書かれるため。

### 4.2 原因

| 所 | 中身 |
|---|---|
| `src/adapter/document-codec/mspdi-codec.ts:59` | `CHILD_ORDER` —— `Project` `Task` `Resource` `Assignment` `Calendar` `WeekDay` `Exception` `TimePeriod` `PredecessorLink` の子の並びを **pj12 の順で** 持つ |
| 同 `:580`〜`:584` | `declaredRank` —— 表に無い名前は **最後に置く**（「落とすより位置がずれるほうが失うものが少ない」）|
| 同 `:1302`、`:1513` | 取り込んでいない文書の `SaveVersion` は `'0'`（取り込んだ文書は届いた値を持ち回る）。`0` はどちらの XSD の説明にも無い値だが、型（integer）には合う |
| `tests/unit/uf-36.test.ts:90` | 並びの試験は pj12 の XSD だけを実行時に読む ⇒ pj15 の並びは試験されていない |
| `DFC-563`（`docs/development-records/defects.md`）| 持ち回った要素の中で、値（葉）を先に、子を後に書く。⚠️ 行は `FR-021`（往復の一致）だけを破ると書くが、**探針では `EX-1`（公式スキーマに妥当）も破った** |

⭐ **pj15 の並びは pj12 の並びを包む**（3.2 節の「並びの変化 0」）。⇒ 並びの表を pj15 の順に替えれば、pj12 の要素しか持たない文書の並びはそのまま（pj12 に妥当なまま）で、pj15 の要素は正しい位置に入る。

⚠️ **未検証**: Microsoft Project が、並びの崩れた XML を開くときに拒むか・読み飛ばすか。手元に製品が無いので測っていない。

## 7. 測り方（反証するための手順）

1. **XSD の差**: 2 つの XSD を ElementTree で読み、`Project` から下の名前付き `xsd:element` を親の道筋つきで集め（pj12 681、pj15 698）、
   道筋の集合の差、共通の道筋ごとの `type` `minOccurs` `maxOccurs` `nillable` と内側の `xsd:restriction` の制約、注釈の文を比べた。
   名前付きの型は最上位の `simpleType` / `complexType` の直列化を比べた。
2. **並び**: 親ごとに合成子（`sequence` / `all`）の子の名前の列を取り、pj15 の列から pj12 に無い名前を除いた列が pj12 の列と一致するかを見た。
3. **learn-docs**: `*-element.md` のファイル名から `-element.md` を除き、XSD の `name="..."` を小文字にした集合と比べた。
4. **公式 URL**: `curl` で 2 つの URL の HTTP 状態とバイト数を取った（2026-09-19）。
5. **探針**: pj15 に妥当で 17 要素をすべて含む最小の文書（タスク 3、資源 1、割当 1、カレンダー 1、`OutlineCode` 1）を手で作り、lxml で pj15 に妥当・pj12 に不妥当を確かめてから、
   梱包された開始時の雛形（`src/framework/single-html-shell/startup-template.json`）を `current` にして往復させた。
   対照として、17 要素を除いて `SaveVersion` を 12 にした文書と、それぞれから `OutlineCodes` を除いた文書を作った（計 4 本）。
   探針のファイルは git 管理外の `scratch/mspdi-pj15-probe/` に置いた（結果の再現に要るのは本節の手順だけである）。
