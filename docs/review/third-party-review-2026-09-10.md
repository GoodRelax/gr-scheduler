### 4.5 で、依頼主の言う膨大な時間の正体は何か

**E1〜E4 が示したのは、ファイル数が原因ではないということである。**
生成の仕組みがある所は、素の TypeScript より**安い**。
高くつくのは、生成の外側、すなわち**判断あたりの読む量**である。数えるとこうなる。

| 測ったもの | 実測 |
| --- | --- |
| `docs/spec/01-04-requirements.md` の文字数 | **320,524 文字**（4,494 行） |
| そのうち日付を含む文が占める割合 | **14.7%**（436 文・47,270 文字） |
| 同ファイルの `（MUST）` | **900** |
| 同ファイルの `MUST NOT` | **693** |
| 要求 1 件（`FR-xxx`、99 件）が引く**他の ID の中央値** | **19 個** |
| 同・最大 | **164 個**（`FR-076`） |
| 仕様書 6 本に現れる**裁定** | **561 回** |
| 同・**実測** | **291 回** |
| 仕様書の md にある ID トークンの異なり数 | **2,457**（接頭辞 133 種） |
| `src/` の注釈行に埋まった ID 参照 | **23,749 件**（異なり 1,857） |

| `src/framework/single-html-shell/frame-loop.ts` 1 本が引く ID の異なり数 | **696 個** |

⇒ **1 つの要求を読み切るには、中央値で 19 か所へ跳ぶ。**
⇒ **1 つのファイルを読み切るには、最悪で 696 か所へ跳ぶ。**
⇒ **その跳び先の 14.7% は、いま何をすべきかではなく、いつ何を撤回したかである。**

**具体例**（`01-04-requirements.md` 945 行目、`FR-001` の STATEMENT 1 文）: 約 6,000 文字の 1 セルに、
いま有効な規則と、2026-09-02 の裁定と、それを 2026-09-07 が覆したことと、
2026-09-08 に依頼主自身が読み間違いを訂正したことと、その訂正がどの値の話だったかが、
**すべて同じ 1 セルに並んでいる。**

⭐⭐ **これが正体である。** 変更そのものは安い。**変更してよいと確信するまでが高い。**
規則と、規則の墓場が、同じ密度で同じ場所に置いてあるので、
**読む者は毎回、これは生きているか、を判定しながら進むことになる。**

## 付録 — 本書の数の出どころ

すべて本書を書いた者が 2026-09-10 に自分で測った。方法は次のとおり。

- **行数・注釈比**: 行頭の `//` と `/* */` を注釈、空白のみを空行、残りを実行文として分類する Python を書いて `src/` と `tests/` を走査した。
- **ID の異なり数と参照数**: 正規表現 `\b[A-Z]{1,5}-[0-9]+[a-z]?\b` を、仕様書の md と `src/` の注釈行に当てて数えた。
  `docs/spec/output/` は生成物なので除外した。
- **要求 1 件あたりの参照**: `**UID**:` 行から次の見出しまでを 1 ノードとして切り、その中の他の ID の異なり数を数えた。
  ⚠️ `GL-007` の 248 個という値は、UID を持たない散文の節を巻き込んでおり**過大である**。本書は中央値のみを使った。
- **変更の影響範囲**: `src` `tests` `docs/spec` と設定ファイルを scratchpad へ複写し、`node_modules` を junction で借りた
  独立の木で実際に変更し、346 ファイルの md5 を前後で比較した。**リポジトリ本体は書き換えていない。**
- **関数の長さ**: 注釈を除いた行に対する波括弧の深さで関数の範囲を取った。近似であり、厳密な構文解析ではない。
- **表の試験網羅**: 仕様書 md 中の `T-xxx` の異なり数と、`tests/` 中で `specTable('T-xxx')` として読まれる異なり数を比べた。
