# ToDo — 住所の無い規則を、表の行にする

⚠️ **別セッションの作業が終わってから着手する**（利用者の指示 2026-09-12）。

---

## 1. ⛔ 何が問題か —— 字数ではない

**1 つの段落に MUST が何本も入っていると、その MUST たちに住所が無い。**

| | |
|---|---|
| 表の行なら | `` 表 T-023d の `GR-5` `` と**名指せる** |
| 長い STATEMENT の中の MUST は | ⛔ **「`FR-001` の STATEMENT」としか言えない** |

⇒ ⛔⛔ **引きたい規則に住所が無いと、人は引用するしかない。**

```
健全:  `FR-011` が定める
実物:  `FR-011` は「両端を動かさないこと（MUST）」と定めている
```

**後者は参照ではない。指し先ラベルの付いた写しである。**⇒ **原本が動いても写しは動かない。**

### ⭐ これは推測ではない。2026-09-11 の巡が実測した

掃除フェーズ 2 が見つけた仕様書の嘘 **32 件**（`D-445` 〜 `D-476`）のうち、**18 件が「辺が嘘」**である ——
**引き先が違う席（9）／撤回済みを現在形で引く（4）／完全性の主張が偽（5）。**

⭐ **逆の証拠もある** —— **`GR-5` や `EP-9` のような行 ID を持つ規則には、引用の腐りがほとんど無い。指せるからである。**

⇒ ⭐⭐ **住所の粒度が粗いことが、引用の腐りの原因である。**

## 3. ⭐ 正しい形 —— 文書が既に答えを持っている

`docs/development-rules/08-spec-template/spec-writing-rules.md` の「1.9 の表と図の参照の規則」:

> **細目が表または図で表せるなら、要求は 1 文でそれを指すこと（MUST）。行ごとに要求ノードを作ってはならない（MUST NOT）。**

⇒ ⭐ **`FR-001` はその作法を守っていないだけである。**

```
いま:  FR-001 の STATEMENT に MUST が 26 本（住所は 1 つ）
正しい: 表 T-0xx に 1 行 1 規則（住所が 26 個）
        ＋ STATEMENT は「表 T-0xx に従うこと」の 1 文
```

### ⛔ やってはならない 2 つ

1. ⛔ **`FR-001a` / `FR-001b` … に割るな。**同じ規則の `WR-2` が**細目を要求ノードで並べることを禁じている**（要求ノードは 1 つずつが UID・理由・関係・試験を連れてくるので、文書も追跡も重くなるだけである）。
2. ⛔ **改行を入れるだけにするな。**段落を 6 つに割っても、**住所は 1 つのままである。**⇒ **意味が無い。**

## 4. ⚠️ 着手する前に決めること

- **どの段落を表にするか。**⛔ **6 つ全部とは限らない** —— 表にできるのは「**細目**」であって、論証や撤回記録は表にならない。⇒ **1 つずつ中身を見て決める。**
- **表の席番号。**⛔ **通し番号を詰め直してはならない（MUST NOT）** —— 同規則の「番号は席番号とする」。
- **指し先の付け替え。**⚠️ **いま「`FR-001` の STATEMENT」を引いている席が他に在れば、新しい行 ID へ向け直す。**⛔ **引き先を変えると、原稿を読む試験が赤くなる**（下の門）。

## 5. ⛔ 門 —— 仕様書を触る手ごとに 4 本

```bash
bash .claude/skills/spec-graph-check/check.sh > /dev/null 2>&1; echo "check=$?"
npx vitest run 2>&1 | grep -E "Tests "
npx tsc --noEmit; echo "tsc=$?"
npm run gen:check > /dev/null 2>&1; echo "gen=$?"
```

⛔⛔ **`vitest` を必ず走らせろ。**⚠️ **原稿を実行時に読み「その文がいまも一字一句在るか」を見る試験が在る。**⇒ **本作業は文を動かすので、確実に赤くなる。**
⭐ **赤くなったら、錨を新しい席（行 ID）へ打ち直せ。⛔ 期待値を消すな。**
⛔ **`Tests` の件数は守りにならない**（`it()` の数である）⇒ **`expect(` を数えよ。**

⚠️ **検査 42 の基準線は 469 で余裕ゼロ**である。⛔ **引用を指し先へ変える作業なので、下がることはあっても上がってはならない。**
