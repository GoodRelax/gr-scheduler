# エージェントと並行して協業する —— 開発する人向けの手引き

AI のセッションを 2 つ以上同時に動かして、gr-scheduler の作業を進めるときの決まりです。
AI 側の詳しい規則は `docs/development-rules/05-working-method.md`（3 節・6 節）と `docs/development-records/handoff.md`（§2.5〜§2.7）が持ちます。本書はその写しではなく、開発する人がすることだけを書きます。

## 並行には 2 種類ある

| 種類 | 誰が始めるか | 開発する人がすること |
|---|---|---|
| セッションの中の体（サブエージェント） | 前に立つセッションが自分で出す | 何もしない。報告を読んで裁定に答える |
| セッションを 2 つ以上開く | 開発する人 | 下の 5 つの決まりを守らせる |

## 5 つの決まり

1. **台帳を持つのは 1 つのセッションだけ（「主」と呼ぶ）。**
   `rulings.md`・`defects.md`・`fixed-defects.md`・`handoff.md`・検査の基準線は、主だけが書く。他のセッションは、書いてほしい文を開発する人経由で主に渡す。
2. **ファイルを分ける。** 2 つのセッションに同じファイルを触らせない。始めるときに「触ってよいファイル（フォルダ）」を渡す。
3. **commit は自分のファイルだけ。** `git add` にはパスを並べる。個人情報の点検の数を報告してから commit・push する。タグは開発する人が打つ。
   ⭐ 他のセッションの変更を巻き込むコマンドは、フック `.claude/hooks/block-sweeping-git.py` が機械で止める —— `git add -A`・`git add .`・`git add -u`・`git commit -a`・`git stash`（`list` と `show` は通す）。
4. **重い走行は 1 つずつ。** e2e と性能の測定は、同時に 1 つのセッションだけが回す。性能の測定の前は開発する人が許す。
5. **試すのは根の `dist/index.html`。** 主が `refactor` を進めて作り直し、「試せる」とブランチ・commit を添えて言ったときだけ試す。

## 2 つ目のセッションに貼る最初の文

````text
refactor ブランチの根で、別のセッション（主）が同時に作業している。次を守れ。
- 触ってよいのは ［フォルダやファイル］ だけ。それ以外は読むだけにせよ。
- rulings.md・defects.md・fixed-defects.md・handoff.md・検査の基準線は書くな。記録が要るときは、主に貼る文を私に渡せ。
- git add はパスを並べよ。git add -A と git stash は使うな。commit は自分のファイルだけ、個人情報の点検の数を報告してから。
- e2e・性能の測定・check.sh の全体は、走らせる前に私に問え。
- 報告の頭にブランチ名を書け。
やること: ［作業の中身］
````

## 困ったとき

- **どちらのセッションの変更か分からない**: どちらかのセッションで `git status --porcelain` と `git log --oneline -5` を打たせ、自分のファイルだけを commit させる。
- **主に記録を渡したい**: 相手のセッションに「主に貼る文」を作らせ、そのまま主に貼る。
- **いまのブランチを確かめたい**: gr-scheduler のフォルダで `git branch --show-current` と `git log --oneline -1` を打つ。
- **セッションがフックに止められた**: 止まるのが正しい。パスを並べた `git add <パス>` で打ち直させる。フックの確かめは `python .claude/hooks/block-sweeping-git.py --self-test`。

## 実績（2026-09-16）

主のセッションが裁定と台帳を持ち、もう 1 つのセッションが `docs/guides/` だけを書いた。後者はパスを並べて commit し、主の未 commit の変更に触れなかった。両者の commit は交互に `refactor` に積まれ、衝突は 0 だった。
