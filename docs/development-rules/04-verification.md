# 04 確かめ方 —— 試験・実物・機械検査

⛔ **「通った」は「正しい」ではない。** 本書は、何をもって確かめたと言えるかを定める。

---

## 1. ⛔ 書いた者に、その試験を書かせない

⛔ **ユニットを書いた者が、そのユニットの試験を書いてはならない。**
**実装を読んで書いた試験は、実装の読み違いごと緑になる。**

```
A  製品コードだけを書く。「別の者が仕様から試験する」と伝えられている
   ⭐ だから公開する形を、それだけで意味が通るように作る
B  docs/spec だけを読んで試験を書く。A の本体ロジックは読まない
   （読んでよいのは冒頭の宣言・公開する型・署名まで）
```

- ⭐ **落ちた試験は「手間」ではなく「発見」である**
- ⛔ **期待値をコードに合わせて書き換えてはならない。** 仕様が明確ならコードを直す（その文を引用する）。
  仕様が曖昧ならその件を落とし、**食い違いとして報告する**
- ⭐ **表を指す要求の試験は、表を写した固定データで駆動する**（`docs/development-rules/08-spec-template/spec-writing-rules.md`）

⚠️ **実測**: 415 件が緑のまま、ある関数が仕様の下限を落としていた（見つけたのは監査で、試験ではない）。
⭐ **仕様から書かせた 2 回の走りは、実装者自身の試験には出せない欠陥を 2 件捕まえた** ——
既に否定されていた古いコメントと、`@purity pure` を名乗りながら引数を書き換えていた関数。

---

## 2. ⛔ 通るだけの試験は何も証明しない

⭐ **検査・契約・免除は、わざと壊して落ちることを確かめるまで、確かめたことにならない。**

```
1. 期待どおり通ることを見る
2. ⛔ 壊す。落ちることを見る          ← ここまでやって初めて「効いている」
3. 戻す。ファイルが元に戻ったことを確かめる
```

⚠️ **控えを取ったら `ls -la` で存在と大きさを見る。** ⛔ **失敗した `cp` を信じて復元したつもりになり、原稿を壊した実例がある。**

⭐ **原稿から値が届く仕組みの受け入れ試験は「原稿の値を 1 つ変えると試験が落ちるか」とする。**
⚠️ **落ちなければ、その値はどこにも届いていない。**

## 3. ⛔ 緑の試験は「動くアプリ」を意味しない

⚠️ **描画・入出力を触ったときは、開発サーバの実 DOM を見る。** 過去に何度も刺さった:

- **rAF だけの初回描画** → 入力が来るまで白い画面
- ⛔ **文字列の鍵に制御文字が 1 つ混じる** → ブラウザが書き換える → 成果物のハッシュが合わなくなり
  **アプリ全体が止まる。** ⭐ **鍵は ASCII だけ**
- **収める表示のはみ出し**（印とラベルを数えていない）／ヘッダーが日程表の高さを奪う

⭐ **見るもの**: 要素数・色・`data-role` の節点・コンソールとセキュリティ方針の誤り。
⚠️ **プレビュー枠は幅も高さも 0 で冷間起動することがある** —— **そのときの崩れは退行ではない。**
1280×800 にして読み直してから結論を出す。

### ⛔ 新しい単体試験を書いてよいのは 2 つの場合だけ

```
① 実物で測って直したものを固定するとき（戻り止め）

```

⛔ **これ以外の増産を禁じる。** ⭐ **浮いた労力は `npm run parity` の手と `tests/system` の件へ回す。**
⛔ **単体試験の件数を目標にしてはならない**（利用者の裁定 2026-09-01）。

### ⭐ 「押しに行く」を 1 件ずつやらない

⚠️ **実測 2026-09-03: 台帳の `実測待ち`（自動試験は緑、出荷ビルドを押していない）が 16 件溜まっていた。**
⛔ **1 件ずつ手で押すと、それだけで 1 巡が終わる。**
⭐ **1 回のブラウザ起動でまとめて判定する掃引を書く**（`tests/system/` の件として）。
**閉じるだけでなく、そのまま戻り止めになる。**

## 3.7 ⛔ 原因は 1 つとは限らない。原因ごとに戻して確かめろ（**実測 2026-09-03**）

⚠️ **書き出した絵が畳みに追随しない件は、原因が 2 つあり、それぞれ別の状態を割っていた。**

```
①の 1 行を戻す  → 触らない状態と全開きが割れる（全畳みは正しいまま）
②の 2 行を戻す  → 全畳みだけが割れる（ほかは正しいまま）
```

⛔ **「症状が消えた」で止めるな。**⭐ **直した所を 1 つずつ戻し、どれがどの症状を割っていたかを数で出す。**
⚠️ **1 つ戻して症状が全部戻るなら原因は 1 つである。戻らない症状が在れば、原因はもう 1 つ在る。**

