### ③ SW アーキの基本方針（まず問う。短く済むはず）

**論点は 1 つ** — 通常 UI は Clean Architecture の外側だが、**本件は Entity に入れてよいのではないか。**

- マルチバーのレイアウト・上下左右整列・LOD・依存線の配線・時間↔座標変換は、
  **「画面の都合」ではなく GRS の価値そのもの**（`CLAUDE.md`「ドメイン境界（コアロジック）」）
- ⚠️ **これは ② と同じ問いである。** Entity に置くなら**その上に生える操作層も Entity 側**になり、
  **UI も AI も等しく外側**から呼ぶ形に落ちる。UI を外側に置いたまま操作層を UI 側に作ると、
  **AI の口が UI に生える。そこが破綻点。**
- ステップ 3 の 3-1〜3-5（`NEXT-STEPS-ja.md`）と `09-architecture/handover-architecture-entry-ja.md` を見る。
  **3-3 モジュール構成 / 3-4 技術スタックは「意図的な空白」**なので、埋めるかどうかも判断が要る

### ① 引継ぎ資産の整理・整頓 — **量が多すぎる。減らす**

**最初に「目的は何か」を答える。** 目的が決まらないと ② で何を入れて何を捨てるかも決まらない。

前セッションの見立て（採否は次期が判断する）:

> **次の開発者（人でも AI でも）が、決め直しをせず、推測を断定に変えずに、実装を始められること。**

この物差しなら判断が機械的になる:

| 残す | 落とす |
|---|---|
| **決定と、その根拠**（なぜそう決めたか） | 決定に至る**経緯・途中の検討** |
| **踏むと分かっている罠** | 一般的な設計論 |
| **一次資料の所在と検証手順** | 一次資料の要約（原文を見ればよい） |
| **数と全数**（何件あるか・全部そろっているか） | 前プロジェクトの**実装の記録**（コピペ禁止なのに残っている） |

⚠️ **最後の行は実際に効く。** 例えば `05-security-a11y/a11y-wcag21-aa-checklist.md` の
「根拠・満たし方」欄には `a11y-tokens.ts` 等の**凍結リポジトリのファイル名**が残っている。
考え方は使えるが、探しても `handover/` に無い。同種のものが他にもある。

### ② AI 連携の取り込み

**材料**: `ai-cowork-trial/draft-for-handover/`（**`.md` 7 本 ＋ `samples/*.json` 2 本・計 164KB**）

**ドラフト側は完成度が高い。** 入口・組込み手順・名前の衝突・格上げ判断まで書いてある。

- ⚠️ **名前の衝突が既知**: ドラフトの `OPEN-ITEMS-ja.md` は `handover/OPEN-ITEMS-ja.md` と衝突する。
  → `agent-interface-open-items-ja.md` へ改名する提案あり
- ⚠️ **格上げ判断が先**: 要求 18 件を `status: draft` / `Working Note` のまま入れてはならない。
  採用 / 一部採用 / 不採用（＝ `findings` 1 本だけ `06-background/` へ）の 3 択が用意されている
- ⚠️ **`authority` は絶対に付けない**（5 つ目の正を作らない）

**設計への組込みについての前セッションの意見**（採否は次期が判断する）:

> **「実装は後、設計は最初から」で正しい。ただし組み込むべきは機能ではなく性質 1 つ。**
> ドラフトの中心 ＝「**口は 2 つあるが、文書は 1 つ**。UI からの変更も API からの変更も、
> 同じ `revision` を進め、同じ Undo 履歴に積まれ、同じ検証を通る。AI 専用の裏口を作らない」
>
> **その操作層は既に別の理由で必須である** — Undo は不変更新スナップショット（07 §8）で
> 「すべての変更が定義された操作を通る」ことを要求し、項 62 は「すべての変更が同じ検証を通る」ことを
> 要求している。**AI 連携が追加で要求するものは実質ゼロ。**
>
> 実装順（UI モック → データモデル → 統合 → AI 連携）は妥当。
> ⚠️ ただし**「統合」の中に操作層が入ることを明示**しないと、
> 「UI が直接ストアを書き換える」形で作ってしまう。**そこが唯一の取り返しのつかない分岐。**
> 骨格段階で**操作を 1 つだけ実装し、UI と API の両方から呼んで同じ Undo に積まれることを見る**とよい。

⚠️ **① と ② は引っ張り合う。** ①「減らす」に対し ② は 164KB を足す。①の目的が先。
