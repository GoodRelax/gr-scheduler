# 08-poc — 動く PoC 一式（2026-08-01 再統合）

このフォルダは **ブラウザで開いて動かせる PoC** である。文書ではなく実行物なので、
読むより先に**開いて触ること**。

> ⚠️ **PoC は 2026-08-02 の 2 つの決定より前の姿である。** `Frozen Record` なので追随させない。
> **次の 2 点は PoC の絵で検算しないこと。**
>
> | PoC が描くもの | 確定した仕様 |
> |---|---|
> | 段割当で **`milestone` を優先**し、マイルストーンが `stack 0`（PoC では行の上端）に集まる | **マイルストーンを特別扱いしない**（`../03-ui-naming/handover-ui-detail-spec-ja.md` §6-1 末尾の注記 / `../02-data-model/grs-native-erd-ja.md` §5.6）。なお PoC は `stackDirection` 自体を実装していない |
> | 依存線は **FS の 5 パターン**のみ | **8 パターン**（SF / FF / SS を含む ＝ 同 §4-9）。SF / FF / SS の標本は無い |

## 開き方

**`poc-integrated.html` をダブルクリックする。以上。**

**サーバーは要らない。** どの `.html` も外部ファイルを 1 つも参照しない
（`POC-SPEC-ja.md` §0-1）。`file://` でそのまま動くことを 2026-08-01 に実機で確認した。

> ⚠️ **2026-08-01 訂正**: 本書はかつて「`file://` で開くとファイル間を移動できない
> （静的スナップショットとして描画されるため）。必ずローカルサーバー経由で開く」と書いていた。
> **これは誤りである。** 「静的スナップショットとして描画される」は
> 開発ツールのプレビューペイン固有の挙動であって、ブラウザの制約ではない。
> ペインの制約をブラウザの制約として書いてしまっていた。

**入口は `poc-integrated.html` の「記録」タブ。** そこに全ファイルの一覧と読み方がある。

## 何のための PoC か

2 種類が混在している。**目的が違うので混同しないこと。**

### (a) 案を比べる PoC — レイアウト 3 案 / ズーム 2 案（**現物は残していない**）

同じ入力・同じ計測項目で複数案を走らせ、**どれを採るかを決める**ためのものだった。
結論は `POC-RESULTS-ja.md` の前半にある。**下表は記録であって、ファイルは存在しない。**

| 案（旧ファイル名） | 案 | 結論 |
|---|---|---|
| `poc-layout-A-orthogonal-channel.html` | 直交チャネル配線 | 横切り 1 だが線どうしの交差 50。トレードオフ |
| `poc-layout-B-anchor-search.html` | 9 点アンカーの候補探索 | **推奨**。横切り 0 / 交差 9。1 回の再レイアウトが 13.3ms（60fps の予算 16.7ms にほぼ余裕が無い）のが弱点 |
| `poc-layout-C-reserved-lane.html` | 予約が先・配線 1 パス | 最速（再レイアウト 2.1ms）だが横切り 8（うち行跨ぎ 7）。**縦の通り道も予約が要る**と判明 |
| `poc-zoom-A-depth-threshold.html` | 深さしきい値 LOD | **推奨**。Fit で 21 行 PASS / 再レイアウト 0.5ms / 横切り 0 |
| `poc-zoom-B-fit-first.html` | 画面予算が深さを決める | L1 が入ることが構造上保証される。縦スクロールが原理的に無いので基本には採らない |

### (b) 確定した規則を検算する PoC — `poc-integrated.html` の 5 タブ

案を比べない。**すでに確定した規則が狙いどおりに効くかを測る**ためのもの。
画面上に PASS / FAIL が出る。結論は `POC-RESULTS-ja.md` 後半の「追試」節。

かつては 5 ファイルに分かれていたが、2026-07-31 と 08-01 の 2 回で 1 ファイルへ畳んだ。

| タブ | 検算する規則 | 元のファイル |

## 色と寸法の正（2026-08-01 の再統合）

**`poc-integrated.html` の中にインラインで入っている。** 共有ファイル `poc-ui.css` / `poc-ui.js`
は廃止した。値を変えたいときはこのファイルの `SPEC`（**64 項目**）と `:root`（色）を直す。

### なぜ共有ファイルをやめたか

2026-07-31 に 9 ページの値を 2 本へ統合したのは正しかった。統合前は予定バーが 16〜28px、
実績バーが 7〜15.4px、フォント下限が 10px と 12px に割れており、
`poc-zoom-lod-transitions.html` に至っては **`--dep` が未定義で依存線が 1 本も描かれていなかった**。

しかし共有にしたことで**別の 2 つの問題**が生まれた。

| 問題 | 2026-08-01 の解き方 |
|---|---|
| **「凍結」と書いた計測記録が凍結されていなかった。** 案比較の 5 本は `rowTitleWidth` / `rulerHeight` / `planHeight` / `actualHeight` / `actualGap` / `rowGap` / `markerSize` / `markerGap` を**実行時に**共有ストアから読んでいた。共有ファイルを直すと過去の計測結果が黙って変わる | 当時の値を各ページへ**焼き込んだ**。絵は 1px も変わらず、以後どこを直しても動かない |
| `POC-SPEC-ja.md` §0-1「**単一 `.html`。外部 CSS / JS を参照しない**」に全ページが違反していた | 焼き込みで解消。ローカルサーバーも不要になった |

**値が散る問題は再発しない。** 編集対象のページが 1 本しかないためである。

- 各案固有のアルゴリズム定数（レイアウト A の `V_PITCH` / `STUB`、B の `STUB` / `SAFETY_CAP`、
  C の `stubOut` / `stubIn` / `lanePitch` / `depthWeight`）は**各案に残してあった**
  （揃えると 3 案が同じものになり比較の意味が消えるため）。**その 5 本は 2026-08-02 に外した。**
- **ダークモードが動く。** `poc-integrated.html` にテーマ切替ボタンがある。

## 読むときの注意

### PoC の識別子は**確定名である**（2026-08-02 に揃えた）

**設定値のキー・CSS 変数・DOM の id は、すべて `../03-ui-naming/handover-ui-parts-ja.md` の確定名で書いてある。**
読み替え表は要らない。**文書とコードが同じ語で書かれている。**

揃えたのは次のとおり。改名の全数と理由は同書の改名表（2026-08-02）が正。

| 種別 | 内容 |
|---|---|
| 設定値 9 キー | `taskLevelOfDetailReadablePx` / `groupLevelOfDetailBase` / `groupLevelOfDetailRatio` / `basePlanHeight` / `rulerHeight` / `chevronNotchOfHeight` / `chevronNotchOfWidth` / `resumeArmOfMarker` / `resumeHeadOfMarker` |
| CSS 変数・marker id | `--dep` → **`--dependency`**、`depArrow` → **`dependencyArrow`** |
| トグルの DOM id | `tgAssignee` 等 → **`assigneeVisible`** など `documentSettings` の確定キー名 7 つ |
| ヘルパ関数 | `item()` → **`propertyRow()`**（`item` は廃止語） |

> ⚠️ **`markerTextOfFont` / `markerOfText` / `markerTextBaseline` の 3 キーは廃止し、
> `markerOfFont = 1.5` の 1 キーに畳んだ**（`../02-data-model/grs-document-settings-ja.md` §3）。
> **これは絵が変わる変更である。** 旧式は内側で「中の数字」を `fontMin` でクランプしてから 2 倍しており、
> **`fontSize < 16` の領域でマーカー径が 24px に張り付いていた**（実測: `fontSize = 12` で径 24px → 18px）。
> `../07-plan-actual/handover-plan-actual-decisions-ja.md` §2-4-1 の
> 「マーカーは**実績バーに追随する**。**注釈が本体より大きくならない**」を旧式は低ズームで破っていたので、
> **新式が正しい。** `POC-RESULTS-ja.md` §6-3 が報告した「固定 px のマーカーが低ズームで段数を決める」の実体がこれである。

> ⚠️ **担当ラベルと完了率ラベルのトグルは既定 OFF にした**
> （`../02-data-model/grs-document-settings-ja.md` §4-1 の確定。測るときは手で入れる）。

### PoC は実装ではない

**コピペ禁止**（`../README.md` 0-1）はここにも適用される。PoC のコードは測るために書いてあり、
Clean Architecture の層分けも型もテストも無い。**残したのは数字と、数字が示した事実である。**

### 数字は「基準の環境」に紐づく

```
画面 1920 x 1080 / ブラウザ全画面 / 拡大率 100% / ヘッダー領域の縦 50px
```

`../07-plan-actual/handover-plan-actual-decisions-ja.md` §2-4-1 と同じ基準。
別の環境で測れば別の数字が出る。**比率は生きるが絶対値は生きない。**

### 未確定のものが混じっている

`POC-RESULTS-ja.md` の追試 §B-6（フォント下限によるレベル減の**量の式**）は
**PoC の提案であって確定事項ではない**。確定しているのは「さらに縮めるのではなく
レベルを減らす」という方針だけ。画面上にもその旨を書いてある。

### handover への書き戻し状況

**`POC-RESULTS-ja.md` の §6（6 件）と末尾の表（7 件）に従う。ここには複製しない。**
全 13 件は **2026-08-02 に全数を棚卸し済み**で、各行に反映先か「未反映の理由」が入っている。

**2026-08-02 に 3 件とも決着した。** §6-2（縦の通り道）は**不採用**（横切りは重ね順で解く）、
末尾 #5（Fit と LOD 閾値）は**罠 T-14 として反映**、#7（レベル減）は**深さ 5〜1 を試す方式に確定**。
**書き戻し待ちのものは無い。**

## PoC ページ自身のフォント

読み物系（`poc-integrated.html`）は **本文 16px / 行送り 1.7**。
2026-07-30 に主要サイトを実測して合わせた。

| サイト | 本文 | 行送り |
|---|--:|--:|
| ja.wikipedia.org（Vector 2022） | 16px | 26px（1.63） |
| google.com | 14px | — |
| yahoo.co.jp | 13〜14px | — |

計器盤型の 5 ページ（レイアウト 3 案・ズーム 2 案）は密な操作面なので 16px にはせず、
**12px 下限だけ**を適用した。SVG の中の文字サイズは**測っている対象そのもの**なので触っていない。

**12px は製品側で決めた和文の可読下限**（同 §2-4-1）。PoC 文書自身がそれを割っていたので揃えた。
