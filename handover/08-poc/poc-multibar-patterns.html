PoC: マルチバー行のパターン集 — 1 行に複数のタスクが入るとき、段はどう積まれるか

20 パターン。overlap が 1 つでもあれば不合格。 担当・完了率・タスク名・進捗マーカー・Resume・依存線をすべて描いたうえで段を割り当てる。 ズームを動かすと同じデータで段数が変わる — それが確認したいことである。

この PoC で確かめること
  1. overlap = 0 — 段割当が全パターンで重なりを出さないこと（最終段の再利用を廃止した以上、絶対条件）。
  2. 決定的であること — 入力の並び順を変えても段割当が同じになること。ならないと再描画のたびに段が入れ替わる。
  3. 手動指定が自動に勝つこと — stackOrder を人が指定した段は自動配置に奪われない。
  4. 左右どちらの張り出しも占有幅に入っていること — 担当＋完了率はバーの外側左、タスク名と進捗マーカーと Resume は外側右に出る （handover-ui-detail-spec-ja.md §4-2 の ⚠️）。片側だけ数えると隣と重なる。
  5. 低ズームで段数がどれだけ増えるか — フォント下限 12px によりラベルが相対的に大きくなる。 §6-4 の ⚠️ が「PoC で実測すること」と言っている当の項目。
形状の描き分け（handover-plan-actual-decisions-ja.md §2-2）
  • 上下に幅がある形状（bar === / chevron >===>） → 実績を予定の内側に重ねる。
  • 上下に幅がない形状（arrow ---> / endpointSpan *----* / milestone） → 細線で描き、実績を予定の下にずらす。
  • 両端が縦棒の細線 |----| は廃止（handover-ui-detail-spec-ja.md §表）。 端点は点で描く。
  • 実績は予定と同じ形状で、少し小さく描く。

1. 全パターンの一覧

ズームを動かすとこの表がそのまま追随する。段数の列が動くパターンが、ズームに敏感なパターンである。

2. パターンごとの絵

予定実績 依存線（橙で固定）占有幅（左右の張り出しを含む）

書式は {担当} : {完了率 %} [タスク名]。 担当と完了率は予定タスクの左端を基準に外側左へ右揃えで連結する。

3. ズーム掃引 — 段数はズームに対して単調か

横ズームを 0.05 から 6 まで 240 段階で掃引し、全パターンの合計段数を記録する。 拡大したのに段が増える逆転があれば、そこが設計の穴である。

4. 左右どちらの張り出しがどれだけ効いているか

占有幅の構成要素を 1 つずつ外して、合計段数がどう変わるかを測る。
