## 何を作りたい？

1つの `.html` でブラウザだけで動作する**日程表作成ツール**。
パワポで日程表を書く作業とほとんど同じ操作感でありながら、成果物は画像ではなく **JSON / MSPDI XML** の構造化データを持つ。

## それはどうして？

- パワポや Excel で日程表を書くのは非効率。
- 既存の日程管理ツールは使いにくい。
- 調査した既存ツールはいずれも **1 行に複数のマイルストーンやタスクを入れられない**ため、**1 対象＝1 行＝全フェーズを 1 枚で俯瞰**する日程表を表現できない。（ツール比較の調査記録は前プロジェクトのリポジトリにある。特定製品の評価を含むため本フォルダには入れていない）

## プロパティ

19. `Task` にプロパティを設定できること。
20. プロパティは以下を含むこと。**編集画面の項目名は英語固定**（項 22）。

    | 項目名（英語・確定） | 日本語 | 備考 | MSPDI |
    |---|---|---|---|
    | `name` | 正式名称 | | `Task/Name` |
    | `notes` | 説明・備考 | **説明と備考は 1 つに統合**する（下記） | `Task/Notes` |
    | `start` / `finish` | 開始日 / 終了日 | **予定**の日付 | `Task/Start` `Task/Finish` |
    | `actualStart` / `actualFinish` | 実績開始日 / 実績終了日 | **同じ `Task` が持つ**（別アイテムにしない） | `Task/ActualStart` `Task/ActualFinish` |
    | `progressRatio` | 進捗率 | 0〜1 | `Task/PercentComplete`（÷100） |
    | `deadline` | 期限 | 「この日までに終える」独立マーカー。終了日とは別 | `Task/Deadline` |
    | `stop` / `resume` | 中断 / 再開 | 1 本のバーが割れる表現 | `Task/Stop` `Task/Resume` ※**意味がずれる**（別紙） |
    | `iconShapeKind` | アイコン字形 | | **無い** → 拡張領域 |
    | `strokeColor` / `fillColor` / `lineWeight` | 枠色 / 塗り色 / 線の太さ | | **無い** → 拡張領域 |
    | `nameAnchor` / `nameAlign` | 名称ラベルの位置 | 9 点アンカー ＋ 整列 | **無い** → 拡張領域 |
    | `importance` | 重要度 | 縮小時に何を残すかの判断に使う | **無い** → 拡張領域 |
    | `progressStatus` | 進捗ステータス | 自由文字列。数値の `progressRatio` とは別 | **無い** → 拡張領域 |
    | `fadeInDays` / `fadeOutDays` | フェードイン日数 / フェードアウト日数 | バー端をぼかして日付の曖昧さを表す | **無い** → 拡張領域 |
    | （表示のみ） | 担当者 | **`Assignment` → `Resource.name` から導出して表示**（自由入力欄は持たない） | `Resource/Name` |

    > **`fullName` / `description` / `remarks` の 3 語をやめる**。MSPDI 側は `Name` と `Notes` の 2 つしかないため、
    > **`name` ＋ `notes` に寄せる**。テキスト列を 5 つ持つと往復で必ず溢れる。
    >
    > **MSPDI に無い項目をどこへ置くか**は複数案を比較して結論を出した。
    > → 別紙 `02-data-model/handover-property-mspdi-mapping-ja.md`（全項目の対応表・3 案の比較・推奨案）

21. プロパティは**多国語対応**すること。
    - 対象言語は **en / ja の 2 言語**とする（それ以上は広げない）。
    - 表示言語の項目名は **`language`**（値 `ja` / `en`）。※「ロケール」は位置を連想させるので使わない（項 66）。
      **どの言語で開くかは読む人の環境**であり、文書には保存しない（別紙 `02-data-model/grs-native-erd-ja.md` §5.7-1）。
    - 文字コードは **UTF-8・BOM なし**。JSON は RFC 8259 が BOM の付加を禁じている。MSPDI XML も UTF-8・BOM なしで `<?xml version="1.0" encoding="UTF-8"?>` を出す。
    - ※ブラウザの File API は既定で BOM を付けない。**何もしなければ正しい**。「Excel 互換のため BOM を付ける」実装を入れてはならない（MSPDI が壊れる）。
22. プロパティ編集時の**項目名は英語表記**とすること。

## 行と階層

26. `Task` を分類する**水平線**（Group Grid Lines）を引けること。
27. **`TaskGroup` は階層を持てること**（大分類 > 中分類 > 対象 のように入れ子にする）。
    - **推奨 3 段、最大 5 段**。「大/中/小」という専用語は持たず、**深さで表す**。
    - 階層の単位で**畳み・並べ替え・表示/非表示**ができること。
    - ※前プロジェクトにあった「セクション」という別概念は**廃止**した。`TaskGroup` の階層がその役割を兼ねる。
    - **画面左（Row Title Panel）で階層を移動したら、元データ（MSPDI）の階層にも反映されること。**
      階層も親も移動する。**ただし `UID` は保持**する（相手ツールで新規タスクにならないため）。
    - 一方、**バーを別の行へ移す操作（マルチバー化）は元データを変えない**こと。**この非対称が要**。
    - 器（行）の既定名・生成規則は別紙 `02-data-model/grs-data-model-ja.md` §7.1-1、
      移動時の追随規則は同 §7.1-2 が正。
28. 非表示にした `TaskGroup` は、**親の**小タブ（Hidden Group Tab）で再表示できること。
    - 畳み/展開は**エディタのツリーと同じ操作体系**とする: **全展開 / 全畳み / 子を全展開 / 子を全畳み / 自分を畳む**。
    - 非表示が増えても**水平線の幅を太くしない**。
29. **Row Title Panel**（`TaskGroup` の見出し）を Schedule Canvas の**左側**に表示できること。
30. **1 行（1 `TaskGroup`）の中で時間が重なる `Task` は自動で縦に積む**こと。規則は次のとおり。
    1. **重なり判定は描画上の占有幅**で行う（日付だけでなく、**はみ出すラベルの幅も占有に含める**）。
    2. **積む順序は決定的**とする: `milestone` を優先 → `start` 昇順 → `finish` 降順 → `uid` 昇順。
       ※決定的でないと再描画のたびに段が入れ替わる。
    3. 各 `Task` を、**その段の既存 `Task` と重ならない最も浅い段**へ置く（貪欲割当）。
    4. **最上段にマイルストーン**を置く（下のタスク群から上のマイルストーンへ依存線が立ち上る構図）。
    5. 積む向き（上/下）は**文書全体**で選べること。既定は上。
    6. **人が `stackOrder` を指定したらそれを優先**する（`null` = 自動）。
    7. 段数には**上限**を設け、超えたら最終段を再利用する（帯高を無限に伸ばさない）。
    8. **行の帯高は段数で決まる**（段が増えた行は下の行を押し下げる）。行高固定を前提にしてはならない。
31. `Task` の位置を**揃えられる**こと。**縦と横で仕組みが違う**。
    - **縦（同じ高さに揃える）は自動**。項 30 の段割当の結果として、同時に始まるタスク・同種のマイルストーンが同じ段に来る。
    - **横（同じ日付に揃える）は Command Palette の整列コマンド**で人が実行する。

## 時間軸・ズーム

32. **Time Ruler**（Schedule Canvas 上端の目盛り）に、**表示中の期間の**年 / 月 / 日 / 曜日を表示できること。
    - ※`App Header` とは**別物**。`Time Ruler` は横スクロール・横ズームに追従し、縦スクロールでは動かない。
33. 拡大縮小で `Time Ruler` の粒度が**自動で切り替わる**こと。**閾値は 1 日あたりの表示幅（px/day）で決める**。
    | px/day | 粒度 | 段数 |
    |---|---|---|
    | 1 未満 | 年のみ | 1 |
    | 1 以上 8 未満 | 年 ＋ 月 | 2 |
    | 8 以上 | 年月 ＋ 日 ＋ 曜日 | 3 |
    - **単調であること**（拡大すると細かくなる一方。粗くなる逆転を起こさない）。
    - 日・曜日の段はラベルが重なるため、**N 日ごとに間引く**（N は幅から決める）。
34. 拡大縮小で**年単位から日単位まで**表示できること。
35. **縦方向のみ / 横方向のみ**の拡大ができること（異方性ズーム）。
36. 拡大縮小によって**表示する `Task` が自動的に増減**すること。
    - 判定は `importance`（重要度）。**縮小すると閾値が上がり、重要なものだけが残る**。
    - **縮小したのに表示が増える逆転を起こさない**（閾値はズームに対し単調）。
    - `TaskGroup` の階層も縦ズームで畳まれる（深い段から順に親へ集約）。
37. **マウスとキーボードの割当**は次のとおり。※**素のホイールはスクロール**。前プロジェクトで「素のホイール＝ズームは違和感がある」と判断して変更した結果を採る。
    | 操作 | 動作 |
    |---|---|
    | ホイール（修飾なし） | 縦スクロール |
    | **Ctrl**（Cmd）＋ ホイール | **両軸ズーム**（ポインタ中心） |
    | **Shift** ＋ ホイール | 時間軸（横）のみズーム |
    | **Alt** ＋ ホイール | 行軸（縦）のみズーム |
    | **Ctrl+Shift** ＋ ホイール | 横スクロール |
    | **Ctrl** ＋ ドラッグ / 中ボタンドラッグ | パン |
    - ズームは**ポインタ位置を中心**とし、カーソル下の日付・行が動かないこと。
    - 素の左ドラッグでパンしてはならない（ドラッグ中に日程表が滑って逃げる）。
38. 拡大したら上下左右にスクロールできること。**マウス操作だけでも**スクロールできること。
39. **稼働日/非稼働日**（土日・祝日）を区別して表示できること。

> **全機能のキーボードショートカットとマウス操作の一覧**は別紙
> `03-ui-naming/handover-ui-detail-spec-ja.md` §5 にある（前プロジェクトの Help に実在したものだけを採録）。

## カーソル

**まず種類。3 つあり、役割が違う。**

| # | 名前 | 何をするもの | 操作の入口 |
|:--:|---|---|---|
| A | **Today Line**（本日線） | 今日の日付に縦線を 1 本引く（固定） | Command Palette のトグル |
| B | **Dual Cursor**（デュアルカーソル） | 任意の縦線を **2 本**立て、その間の**日数を測る** | Command Palette |
| C | **Cursor Guide**（ガイドカーソル） | **ポインタに追従**する補助線。視線誘導用 | Command Palette に **4 モード排他**のアイコン |

**C の 4 モード**（排他・アイコンは線画で形が違う）: ガイドなし / 十字 / 縦 1 本 / 縦 2 本。

**次に機能。**

40. **Today Line** を表示できること。
41. **Dual Cursor**: 任意の縦線を 2 本立てて、その間の**日数を測れる**こと。
42. **Cursor Guide**: ポインタに追従する補助線。上記 4 モードから選べること。
    - ※ **41 と 42 は別機能**。前者は**計測**、後者は**視線誘導**。同じ「縦 2 本」の見た目でも役割が違う。
43. Today Line・各カーソルは表示/非表示を切り替えできること。
    - ※ 描画コストのため、**ガイドが無効なときはポインタ移動で再描画しない**こと（別紙 §1 E-12）。

    - 位置は**日付 ＋ 行**で持つ。**行は順番ではなく行の識別子で参照**すること（並べ替えで別の行を指す事故を防ぐ）。
    - 吹き出しのズレだけは**画面上の距離**で持つ（ズームしてもアンカーからの見た目の距離が変わらないこと）。
    - **指している行が畳まれた/非表示になったら、コメントも一緒に隠す**こと。
45. 任意の場所を任意の色の**角丸四角**（Highlight Boxes）で囲えること（一部を強調）。
    - 角丸の R は日程を拡大縮小しても**同じ大きさで見える**こと。
    - 範囲は**日付の範囲 ＋ 行の範囲**で持つ。行は同じく**識別子で参照**する。
    - **範囲内の行が非表示になったら、見えている行だけを囲う**こと（枠が縮む）。
    - ※ コメントと囲み枠は**別のもの**として持つこと。前者は「点を指す」、後者は「範囲を囲む」で必要な情報が違う。
    - データ構造は別紙 `02-data-model/grs-native-erd-ja.md` §5.8 が正。

## 予定と実績

50. 予定と実績を表示/管理できること。
    - **同じ `Task` が実績日を持つ**方式とする。予定と実績を別アイテム・別行にはしない。
    - **入力するのは 3 つだけ**（`actualStart` / `actualFinish` / `progressRatio`）。3 状態から外れる入力はできないようにする。

      | 状態 | 実績開始 | 実績終了 | 進捗率 | 入力するもの |
      |---|---|---|---|---|
      | 未着手 | 空 | 空 | 0 | 何も入れない |
      | **進行中** | **着手日（必須）** | 空 | 0 〜 1 の間 | **着手日 ＋ 進捗率** |
      | 完了 | 着手日 | **完了日（必須）** | 1 | **完了日**（率は自動で 1） |

    - **実績終了は完了したときにだけ入れる。** 途中では入れない。着手時に実績開始、以後は**進捗率だけ更新**、完了時に実績終了。
    - 詳細は別紙 `02-data-model/handover-property-mspdi-mapping-ja.md` §3-2（データ）と
      `03-ui-naming/handover-ui-detail-spec-ja.md` §4-0（UI）。
51. **予定のみ / 実績のみ / 両方**の表示を切り替えられること。
    - `[予定]` `[実績]` の**独立した 2 トグル**で表す。**両方 OFF は作らせない**（バーが 1 本も出ない画面は故障に見える）。
52. 予実の描き方を**重ね表示 / 上下分離表示**で切り替えられること。
    - `[分離]` トグルで表す。**両方表示のときだけ有効**（片側のみなら分ける対象がない）。
    - **重ね表示の重ね順は、背面から前面へ「予定 → 実績 → 名称ラベル」**とする。名称ラベルが最前面。実績バーがラベルを覆ってはならない。
53. 実績表示のとき**イナズマ線**（Progress Line）を引けること（どこがボトルネックか可視化）。
    **頂点（front）の求め方**は次のとおり。行に複数の `Task` があるときは、**その行で最も進んだ頂点が勝つ**。
    | 状態 | 頂点の日付 |
    |---|---|
    | マイルストーン | `actualStart ?? start`（**点**。内挿しない） |
    | 完了（`actualFinish` あり） | `actualStart + progressRatio × (actualFinish − actualStart)` ＝実質 `actualFinish` |
    | 進行中（`actualStart` あり・`actualFinish` なし） | `actualStart + progressRatio × (finish − actualStart)` ※予定終了を暫定の実績終了とみなす |
    | 未着手だが `progressRatio` > 0 | `start + progressRatio × (finish − start)` |
    | `progressRatio` = 0 かつ実績なし | **頂点を作らない**（線を引かない） |
    - **MSPDI では進捗率は独立データではなく期間実績の言い換え**である（`PercentComplete = ActualDuration / Duration`）。
      GRS は `ActualDuration` を持たないので `PercentComplete` を**読んで保持する**。読まないと export で相手の進捗を消す。
      詳細と 3 種類の進捗率（`PercentComplete` / `PercentWorkComplete` / `PhysicalPercentComplete`）の違いは別紙
      `02-data-model/handover-property-mspdi-mapping-ja.md` §3。
54. **変更前の予定をグレーで表示**し、計画の変更を可視化できること。
    - 変更前の予定は**別ファイル**として読み込んで重ねる。

## 透かし

55. 日程表に**透かし**（Watermark）を入れられること（Web 会議で秘密の日程を撮影されたときの証跡）。
    0. **透かしの設定は文書に保存しない。開いた人の名前と日時で描く。**
       証跡として意味があるのは「**誰がいつ画面に出していたか**」なので、作者の名前が他人の画面に出るのは誤り。
       ユーザー名は読む人の環境設定、日時は実行時に生成、パスワードのハッシュは `.html` 埋め込み。
    1. 透かしにはユーザー名と日時を入れること。
       - 日時は **RFC 3339 / ISO 8601 の UTC 形式 `YYYY-MM-DDThh:mm:ssZ`**（末尾 `Z` = UTC）で書くこと。
       - ※ MSPDI 内部の日付は**タイムゾーンを持たないローカル時刻** `YYYY-MM-DDThh:mm:ss` なので**別扱い**。混同しないこと。
    2. ギリギリ見えるくらいの薄さで、画面全体に斜め方向へ複数入れること。
    3. 表示/非表示を切り替えできること。**非表示にするにはパスワードの入力を求める**こと。
       - 照合は **SHA-256 のハッシュ比較**で行い、**生パスワードはコード・モデル・出力（HTML / JSON）に一切保存しない**。
       - **既定パスワードは `GoodRelax`**。その SHA-256（16 進）を定数として `.html` に埋め込む。
       - ⚠️ **クライアント単体の単一 HTML なので、これは弱い抑止（soft deterrent）にとどまる。** DOM / HTML を直接編集すれば透かしは除去できる。暗号的な強制はできない。サーバー配備時は必ず変更する。

## 次期の開始前に決めること

前プロジェクトで**答えが出ないまま終わった**もの。**下記の仕様で決着とする**（ユーザー確定）。
実装の詳細は `03-ui-naming/handover-ui-detail-spec-ja.md` §4 が正。

### 決着した仕様

1. **掴み点（選択点）の定義**
   - **名称ラベル / 担当ラベル**: 掴み点は**そのラベルの中心**。編集と移動のみでサイズ変更はしないため、これで足りる。
   - **予実のバー**: **左右端の中央高さ**＝開始・終了の変更。**左上**＝フェードイン、**右下**＝フェードアウトの掴み点。
2. **担当・進捗の表示**
   - 書式は **`{担当} : {進捗 %} [タスク名]`**。
   - **担当と進捗は「予定タスクの左端」を基準に、バーの外側左へ右揃えで連結**する。**タスク名はバーの上に左揃えで重ねる**。
   - 担当・進捗は**個別に表示/非表示**を切り替えられること。
   - フォントサイズは**タスク高の 80%**。ただし**下限でクランプする**（縦ズームを縮めたときに読めなくなるため）。
3. **予実が重なって編集できない場合の解決**
   - **モードで解く**。「予定のみ / 実績のみ」に切り替えるか、**上下分離表示**にして編集する。
   - 予実の表示状態は**遷移モードとして定義**し、Command Palette と App Header のアイコンで識別可能にすること。
     **色だけで区別してはならない**（WCAG 1.4.1）。**色 ＋ アイコン形状**の二重符号にする。
   - 掴めない端点は**薄く描き、理由をツールチップで示す**こと。無反応だと故障に見える。
4. **PoC を先に回す**
   - 上記のようにポイントとなる UI は、**実装前に PoC を回してユーザーと認識合わせを行う**こと。
   - PoC では **UI と性能を同時に測る**こと。予実 2 系統＋担当＋進捗ラベルは **1 アイテムあたりの DOM ノード数が最も増える構成**で、ぬるサクの最大のリスクである。
