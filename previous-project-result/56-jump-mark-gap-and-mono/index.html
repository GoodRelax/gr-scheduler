問の見本: 飛んだ先の印（Jump Landing Ring + Ripple）の「隙間」と「モノクロの色」

場面: 検索パネル（Search Panel）や遅延診断レポート（Delay Diagnostics Report）の名前を押してタスクへ飛ぶと、飛んだ先のタスクバーやマイルストーンのグリフに囲みが付き、波紋が 2 回広がる（表 T-332 の SJ-10）。 ここでは決まっていない 2 つを並べて比べる —— 問 1 囲みと形のあいだの隙間と、問 2 モノクロ表示（K-61）のときの囲みの色。

決まっていること（ここでは動かさない）
  • 囲みと波紋の色はローズ（色相 335）: 明るいテーマ #b31959 ／ 暗いテーマ #f17eae（JDG-2152）
  • 角は丸い。囲むのはタスクバー（タスクの線）とマイルストーンのグリフだけ。進捗マーカー（完了の ✓ など）は囲みの外（JDG-2153）
  • 選択の破線の枠（1px、刻み 2 × 1 —— S-174・S-175）は今の色（強調の色 S-151）のまま
  • 囲みの太さ 3px（S-556）、波紋は囲みから各辺 16px 外へ（S-559）、600ms（S-558）を 2 回（S-557）

問 1 囲みと形のあいだの隙間（S-555）

どの候補も、選んでいるタスクの破線の枠（形の縁の上、外へ 0.5px まで）と、フェードの掴み点（5 × 5px の四角を形の角に中央合わせ、縁 1px —— 外へ 3px まで、S-109・S-110）と、完了の ✓（径 14px、形の右に隙間 0 で接する —— 表 T-273 の LP-2、マイルストーンは labelLayoutOf で同じ）を描いた。 上段は等倍、下段は右端を 4 倍に拡げた。表は、囲みの線（太さ 3px）が何 px 重なるかを候補の値から求めたもの。

問 2 モノクロ表示のときの囲みと波紋の色

モノクロ（K-61 の themeMonochrome、S-74）は、表 T-236 のすべての行を、HSL の明度を保ったまま彩度 0 の灰にして描く —— 強調の色 S-151 も含め、例外を置かない（FR-041。人が指定した色は表 T-017b の CV-7）。 FR-041 は「カーソル S-195 と強調 S-151 はモノクロでは明度と形でしか分からない」と認めている。 下の候補はどれもモノクロで描いた（表示を「暗い」系にすると暗いモノクロになる）。下の段に、遅延診断の修正案から飛んだときの「関係するタスク」の囲み（S-573、波紋なし —— 表 T-346 の RW-13）を並べた。

問 3 進捗マーカー（✓ と右の名前）をどこに置くか

今の割付け（表 T-273 の LP-2、マイルストーンも同じ）では ✓ が形の右に隙間 0 で接するので、問 1 のどの隙間でも囲みの線が ✓ に重なる。JDG-2153 の「進捗マーカーは囲みの外」を守る置き方を 4 つ並べた。 どれも問 1 の C（隙間 1.5px —— 囲みの外縁は形の外 4.5px）で描いた。下の段は印の付いていない、ふつうのタスクである。 ⚠️ 名前が形の中に収まるタスク（LP-1）は ✓ も形の中の左端に在り、どの候補でも囲みの内側になる。

測り方

隙間は、等倍の SVG で getBBox() を読み、形の外接矩形の各辺と囲みの線の内縁（矩形の辺 ± 線の太さの半分）との差として測った（ページの下の「測った値」の行と、セッションの一時フォルダの Playwright の probe）。 灰は CF-6 と同じく 8 ビットの sRGB に丸めた値の (最大 + 最小) ÷ 2 を灰の値とした。描く色の値は表 T-236（色相 214）の値、形と寸法は出荷版の決まり（SL-8・FR-075・LP-2）に寄せた模型で、実物の割付けではない。
