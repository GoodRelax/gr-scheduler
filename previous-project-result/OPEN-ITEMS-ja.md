## 1. `Number` 枠が何番まで使えるか

| | |
|---|---|
| **確かめること** | MS Project のカスタムフィールドで `Number1`〜`Number?` が**何番まで**あるか |
| **なぜ要るか** | GRS が拡張領域（`ExtendedAttribute`）に載せる属性の割当先を決めるため |

## 2. `PercentComplete` に 100 を超える値を書いたらどうなるか

| | |
|---|---|
| **確かめること** | `<PercentComplete>150</PercentComplete>` を含む XML を開いたとき、MS Project が **100 に丸めるか / 拒否するか / そのまま受け入れるか** |
| **なぜ要るか** | GRS は「予定 10 日の仕事に 15 日かかった」を 150% として素直に出す方針にしたため |
| **やり方** | 予定 10 日・実績 15 日のタスクを 1 つ書いた XML を開き、`% 完了` 列を見る。保存して書き出し、値を比べる |
| **影響先** | `07-plan-actual/plan-actual-decisions-ja.md` §1-4 |
| **優先度** | **中** |

**背景**: XSD は `xsd:integer` で**制約ファセットを持たない**ので、150 は妥当な XML になる。
ただし意味論は「期間のうち完了した割合」なので 100 超は MS Project の考え方と食い違う。

**丸められると分かったら**: §1-4 を「MSPDI export では 100 で頭打ち」に変える。
超過は `ActualDuration` と日付から復元できるので、情報は失われない。

## 3. 完了したタスクの `Stop` / `Resume` をどう書き出すか

| | |
|---|---|
| **確かめること** | MS Project でタスクを 100% 完了にして書き出したとき、`Stop` と `Resume` に**値が入るか空か** |
| **なぜ要るか** | GRS は「完了したら `Stop` / `Resume` を書かない」方針にしたため、相手の書き方と揃うか見ておく |
| **やり方** | タスクを 1 つ作り、100% 完了にして XML で書き出す。`<Stop>` `<Resume>` を検索する |
| **影響先** | `07-plan-actual/plan-actual-decisions-ja.md` §10-1 |
| **優先度** | **低** |

**答えが出なくても困らない理由**: GRS 側は完了時に書かないと決めており、
未編集タスクは受け取った値をそのまま返す（Carry）ので、**相手がどう書いても往復は壊れない**。

## 4. GRS が新規に書き出した `Resource` / `Assignment` を MS Project がどう扱うか

| | |
|---|---|
| **確かめること** | `UID` / `Name` / `Type` だけの `Resource` と、`UID` / `TaskUID` / `ResourceUID` だけの `Assignment` を含む XML を開いたとき、① **担当者として表示されるか** ② **`Units` / `Work` を勝手に埋めるか** ③ 埋めた場合 **`Task` の `Duration` / `Work` が変わるか** |
| **なぜ要るか** | GRS で担当者を追加・編集できるようにした（`user-order.md` 項 69）。**③ が起きると `Task` の Carry（工数・コスト）と食い違い、往復無損失が壊れる** |
| **やり方** | タスク 1 本 ＋ 資源 1 人 ＋ 割当 1 件だけの XML を上記の最小の形で作って開き、`リソース名` 列と `作業時間` 列を見る。保存して書き出し、`<Units>` `<Work>` `<Duration>` を検索する |
| **影響先** | `02-data-model/grs-native-erd-ja.md` §5.5a-2 |
| **優先度** | **中** |

**背景**: 正本 XSD で確かめたとおり、**`Resource`（子要素 71）も `Assignment`（子要素 265）も必須は `UID` だけ**なので、
上の最小の形は**妥当な XML である**。**妥当性と、相手が期待どおりに読むかは別**である。

**埋めると分かったら**: §5.5a-2 に「export 時に `Units` を明示して書く」を足す。
GRS は割当率を持たないので、**書くとしたら固定値**になる。その値は実機の既定に合わせる。
