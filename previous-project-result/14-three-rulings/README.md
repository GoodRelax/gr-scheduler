## 2. 案 ①′ —— 掴み代の最終形

```
1  掴み代は、描かれたインクそのものとする。インクの中央で左右に割る（＝ 案 ①、R-36）
2  ⭐ 着手済の実績の長さの下限を 1 稼働日（S-129）とする。0 日には縮められない
3  S-93（30px の箱）は廃する。S-180（描く幅の上限）は残す
```

| 効くところ | なぜ |
|---|---|
| **裁定 ①** | 未着手のダミーと着手済の実績が**どの倍率でも同一の形**になる |
| **不具合 2** | インクが 0 にならないので掴み代も 0 にならない。⭐ **見えない掴み代を作らずに済む** |
| **不具合 8** | 30px の箱が消えるので、短いタスクでも予定の端点（`GR-3` / `GR-4`）が塞がれない |

⛔ **代償**: 実績を「0 日」として持つ道が、掴んで縮める側からは無くなる。
⚠️ **プロパティパネル（`PR-4` / `PR-5`）から空にできることを、直す前に確かめる。**

## 3. ⭐ 不具合 1 —— なぜ「2 つ目」だけが成り立つのか

**1 つ目（実績を書かずに印だけ変える）は成り立たない。**
この造りは**状態を保存していない**。**列の組み合わせから毎回導いている**（表 T-019a）。

| | 条件 | 導かれる状態 |
|---|---|---|
| `PS-1` | `actualStart` が空 | **未着手** |
| `PS-2` | `actualFinish` がある | **完了** |

⇒ 実績を 1 つも書かなければ `PS-1` で「未着手」に導かれ続け、**印だけ変えても次に描いた瞬間に戻る。**
⛔ 状態を別に保存すると、列と印が食い違ったまま保存できる文書ができる（`FR-041` が禁じる導出値の保存）。

**2 つ目（ダミーを実績にして幅を変更せず）は成り立つ。**
表 T-021a の `PV-1`（未着手 → 完了）が置く値のうち、**1 語だけを変える。**

| | `actualDuration` |
|---|---|
| いま | 予定の期間 |
| 直したあと | ⭐ **`S-129`（1 稼働日）** |

⭐⭐ **同じ数が 3 つの道で使われることになる** —— `S-129` は
① ダミーを掴んだときに置く実績期間（`FR-043`）、
② 案 ①′ が置く実績の長さの下限、
③ ステータスマークの 1 押しが置く実績期間。
⇒ **どの道から入っても、最初に立つ実績は同じ 1 日である。**

⭐ **`FR-013` の理由の側とも合う** —— 同要求は「**1 日で終わる作業は日程表で頻出する**ので、2 手を要求すると道具として重い」と書いている。
⛔ **いまの `PV-1` は、自分の要求の理由と食い違っていた。**

⛔ **代償**: 「10 日の予定が、予定どおり 10 日かかって終わった」を 1 押しで言う道は無くなる。
実績の右端（`GR-6`）を掴んで引くか、`PR-5` に日数を入れる。
