## 2. ⛔ なぜ 案 ① のままでは通らなかったか

案 ① は「**掴み代 ＝ 描いたインクそのもの**」である。
⇒ **インクが 0 なら掴み代も 0 になる。**
⇒ いただいた**不具合 2**（実績を 0 日にしたら実績の変更ができなくなる）が、まさにその状態である。

⭐ **仰せは「実績が 0 でもつかみシロは仕様通りに確保しろ」であった。**

---

## 3. ⭐ 案 ①′ —— 出した最適案

```
1  掴み代は、描かれたインクそのものとする。インクの中央で左右に割る（＝ 案 ①、R-36）
2  ⭐ 着手済の実績の長さの下限を 1 稼働日（S-129）とする。0 日には縮められない
3  S-93（30px の箱）は廃する。S-180（描く幅の上限）は残す
```

| 効くところ | なぜ |
|---|---|
| **裁定 ①** | 未着手のダミーと着手済の実績が**どの倍率でも同一の形**になる。案 ① 単体より強く `R-36` を満たす |
| **不具合 2** | インクが 0 にならないので掴み代も 0 にならない。⭐ **見えない掴み代を作らずに済む** |
| **不具合 8** | 30px の箱が消えるので、短いタスクでも予定の端点（`GR-3` / `GR-4`）が塞がれない |

⛔ **代償**: 実績を「0 日」として持つ道が、掴んで縮める側からは無くなる。
⚠️ **プロパティパネル（`PR-4` / `PR-5`）から空にできることを、直す前に確かめる。**

---

## 4. ⛔⛔ 1 件だけ、なお裁定が要る —— 不具合 1

**仰せ**: 「ステータスマークを押下しても、実績を変更するな」

⛔ **記録と原典を突き合わせた結果、これは造りの誤りではなかった。**

| 原典 | 逐語 |
|---|---|
| `FR-013` | **未着手のタスクを 1 押しで完了にできること（MUST）** |
| 表 T-021a の `PV-1` | 未着手 → 完了：`actualStart` ＝ `start`、`actualFinish` ＝ `finish`、**`actualDuration` ＝ 予定の期間** |

⇒ 「完了」は実績を持つ状態である（表 T-019）。**実績を書かずに完了にすることはできない。**
⇒ 仰せを字義どおり通すと、**`FR-013` の MUST が 1 つ消える。**

⭐ **案は 3 つ。見本の最後の節に図と表で並べた。**

## 6. ⭐ この巡で値打ちのあった 1 手

⚠️ **前に立つ者は最初、不具合 1 を「造りの誤り」として直しにかかろうとした。**
⛔ **原典を読んだら、`FR-013` の MUST と 表 T-021a の `PV-1` が、まさにその挙動を求めていた。**
⇒ **直していたら、MUST を黙って 1 つ消していた。**

⭐ **もう 1 つは前の版から引き継いだもの** —— 案 ① の代償「低倍率での掴みにくさ」を、
**述べる前に出荷ビルドで 6 段階測った**（`S-49` の床は予定にだけ掛かり、実績には掛かっていなかった）。
