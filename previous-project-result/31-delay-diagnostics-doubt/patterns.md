## 見えたこと

1. **`!!` は WBS の祖先にだけ付く。** 親が子と同じ行（W01）でも 1 段上（W02）でも、導いた親（W03）でも同じ。孫の炎は親と祖父の両方に `!!`（W06）。同じ行でも親子が無ければ何も付かない（W13）。
2. **`JDG-1057` の ④ は、依存の種類で読み分けないと誤る。** 後続が FS ・ SS の先行の許す日より早く着手した（先行が未完了のまま着手した）ときは、いまは先行に炎（D05）、当てた後は後続自身に炎（D05・D02・D14）。一方、後続が先行の遅れを待ってから着手した（D11・D12）ときに文字どおり「先行で縛らない」と、先行 P の押し出しが消える。FF ・ SF は先行が縛るのが後続の終了なので、早く着手しても先行は外せない（D29・D36）。本書の「当てた後」はこの読みで測った（`DFC-1631` に追記）。
3. **予定の開始を過ぎても未着手のタスクは、どの依存でも炎にならない**（D01・D13・D25・D37・A02）。遅れは後続へ持ち込まれるだけで、元として名指されない（`DFC-1632` ・ `PND-629`）。
4. **`VC-13` と `VS-3` は依存の種類を見ない**（仕様の文も、コード `delay-diagnostics.ts:544` ・ `:586` も）。SS で P が着手済みのまま S が完了（D18）、SF で P が着手済みのまま S が完了（D42）は依存の向きどおりなのに、S が `?` になり下流が壁（`DW-1`）で止まる。FF ・ SF で P が未着手のまま S が着手（D26・D38）も向きどおりなのに `VS-3`（`DFC-1660` ・ `PND-635`）。
5. **FS の同じ日**（O02・O04〜O06・M01・M02・M04・M06）は、いまは `?`（`VC-15`）か `VS-4`、当てた後は消える（`CR-618` ・ `DFC-1490` のとおり）。SS ・ FF ・ SF の同じ日は、いまも指摘にならない（予定 O13・O22・O31、実績 O11・O20・O29）。
6. **遅れ（lag）は、いまも当てた後も読まない**（O37〜O40: lag 2 を破っても指摘なし）—— `PND-606` ・ `JDG-822` のとおり、変更要求を待つ。
7. **完了率 100 以上で未完了**（A08・A09）は正常として扱われ、予定の終了を過ぎたので炎になる（仕様どおり、`JDG-1057` の ③）。
8. **再開の予定が基準日より後**（A15）でも、見込み終了は基準日で止まる —— 表 T-313 の `BD-1` は `resume` を読まない（`DFC-1661`）。
9. **先行が全部完了した節目**（M01）は、手の完了が無いと当てた後に `!`（遅れ）が付く。節目は `MP-4` で 05-07 に達成しているのに、遅れの印が出る（`DFC-1662`）。
10. **親子の矛盾**（`VC-9` 〜 `VC-12`、W07〜W10）は親を `?` にし、親から下流を壁で止める。子の炎はそのまま（W07）。親が決まらない子（W04・W05）は、子と候補の親が `?`。
11. **未着手の先行 P と着手済みの後続 S**（D02・D14・D26・D38）は、いまは誰にも炎が出ない（どちらも `!`）。当てた後は、FS ・ SS では S 自身の遅れで S に炎（④）。

## 作り方（反証できるように）

- 組み合わせは scratch の Python が作り（稼働日は月〜金で数えた）、scratch の TypeScript が `documentFromJson` で起動の見本を読み、その暦と列の既定値のまま `schedule` の中身だけを差し替えて `diagnoseDelay` を呼んだ（`frame-loop.ts` と同じ呼び方）。rolldown で束ねて node で走らせた。
- 「当てた後」は `delay-diagnostics.ts` の写しの 3 か所を差し替えた: `linkHolds` の FS と SF の `least` を 0、前向きの流しの FS の境を `nextWorkingDay` を取らない同じ日、`flowOf` で着手済みの最早開始が実績の開始より遅くなったら実績の開始（`start` は下回らない）に戻す。
- 完了率は `FR-012` の式（実績の長さ ÷ 予定の長さ）で置いた。診断は完了率を読まない。
