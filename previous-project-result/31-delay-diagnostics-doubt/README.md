## 何を調べたか

利用者の問い（`JDG-1055`・`JDG-1056`）: 起動の見本で uid 996「Web Service workstream」に `!!` が付くのは、同じ行の uid 287「Book the training reviews」（炎）のせいか。同じ行の中は同僚どうしで、階層ではないはず。

| 分かったこと | 台帳 |
|---|---|
| `!!` の元は行ではなく WBS の親子（287 の `wbsParentUid` が 996）。仕様（`FR-133`・表 T-315 の `DG-3`）もコードも同じ。`CR-618` を当てても変わらない | `DFC-1630` |
| 親と子が同じ行に並ぶのは、取り込みの規則（`CR-567` の決定 3、`JDG-560` の A1）どおり。利用者のいまの意図（親と子で行を分ける）は、そのとき退けた A2 に当たる | `DFC-1630`・`JDG-1058` |
| 前向きの流しが、着手済みのタスクの最早開始も先行で縛る。⇒ 利用者の裁定（`JDG-1057` の ④）: 実績の開始で置く | `DFC-1631` |
| 予定の開始を過ぎても着手していないタスクは、炎にならない | `DFC-1632`・`PND-629` |
| 記載漏れ（`VO-3`）を持つタスクにも炎が付く | `DFC-1633`・`PND-630` |
| 起動の見本の完了率が `FR-012` の式と合わない | `DFC-1634` |

測り方: `src/adapter/document-codec/json-codec.ts` の `documentFromJson` と `src/entity/document-model/schedule/delay-diagnostics.ts` の `diagnoseDelay` を scratch のスクリプトから rolldown で束ねて呼んだ（`frame-loop.ts` と同じ呼び方）。直した形の数は、`delay-diagnostics.ts` の写しを scratch で差し替えて測った。
