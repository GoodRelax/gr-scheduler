# 将棋トライアル

○×（`../`）で「人間と AI が 1 つの文書をライブ編集できる」ことは確認済み。
こちらはその上に、**GRS で本当に必要になる 3 つ**を足して確かめる版。

1. **アプリ内チャット** — 別のチャット窓に切り替えずに、編集対象を見ながら AI と話す
2. **Undo（待った）** — AI の着手を人間が取り消せる。両者の手が 1 本の履歴スタックを通る
3. **ドメインの一元化** — 合法手判定はサーバのルールエンジンだけが持ち、
   クライアントは文書に載った `legalMoves` を描画するだけ

## 起動

Claude Code で `/shogi` と打つ。あるいは手動で:

```bash
node ai-cowork-trial/shogi/server.mjs
```

<http://localhost:8789> を開く。人間が先手（▲・下）、AI が後手（△・上）。

## 操作

駒をクリックで選択 → 移動先をクリックで着手。同じ駒をもう一度クリックで取消。
持ち駒はクリックしてから打つ場所を選ぶ。成れる手は成/不成を確認する。

## ファイル

| ファイル | 役割 |
|---|---|
| `rules.mjs` | ルールエンジン。純粋関数のみ（I/O なし・DOM なし） |
| `server.mjs` | 共有状態 + API + SSE。ポート 8789 |
| `public/index.html` | 盤・持駒・チャット・棋譜の UI。自己完結 |
| `wait.mjs` | 人間が何かするまでブロックし、終了して AI を起こす |
| `turn.mjs` | 着手と発言を 1 往復で送る（AI の応答時間を縮めるため） |
| `say.mjs` | 発言だけ送る最小版 |

## API

○×版と同じ形。`/api/chat` だけ追加。

| エンドポイント | 次期 GRS `window.grs` | 将来の MCP ツール |
|---|---|---|
| `GET /api/state` | `getDocument()` + `getRevision()` | `grs_get_document` |
| `POST /api/apply` | `applyCommands()` | `grs_apply` |
| `POST /api/chat` | （新規）会話チャネル | `grs_chat` |
| `GET /api/events` | `on('change')` | `grs_watch` |

コマンド: `move` / `drop` / `undo` / `reset` / `resign`。

## 実装した将棋ルール

成り（強制成り含む）・持ち駒と打ち込み・二歩・行き所のない駒・王手放置禁止・
打ち歩詰め・詰み判定・手詰まり判定。千日手と持将棋は未実装。

検証済み（`rules.mjs` に対する実測）:

- 初期局面の合法手が 30（既知の正解値）
- 全筋に歩があるとき歩打ちが 0（二歩）
- 桂打ちの最小段が 3 段目、香打ちが 2 段目（行き所のない駒）
- 頭金の詰み判定、金が無防備なら詰まない
- 最終段へ行く歩は不成の選択肢が消える（強制成り）
- 打ち歩詰めは拒否され、同じマスへの香打ちは通る

## ここで踏んだ問題

**日本語をシェル引数で渡すと文字化けする**（Windows のコードページが curl に渡る前に
バイト列を壊す）。盤の漢字は無事なのでページ側の問題ではない。
対策として、AI が**発言する内容は必ず UTF-8 ファイルに書いてから** `say.mjs` で送る。
ASCII だけの JSON コマンドは curl に直接渡してよい。

GRS でも同じ話が出る: **AI が製品へ渡す日本語データはシェル引数に載せない。**
ファイルか stdin か HTTP ボディで渡す。
