# 25 色の入力の並べ方の見本（2026-10-01）

⭐ **`CR-606` の並べ方の参照にする、触れる見本である。** 指示は `JDG-863`、推奨の受け入れは `JDG-922`（`docs/development-records/rulings.md`）、台帳の行は `DFC-1333`（`docs/development-records/defects.md`）。
本見本は並べ方を見せるだけで、仕様を決めない —— 決まっていないことは末尾に挙げた。

## 絵

- タスク: 予定バー（縦 28px ＝ `S-4`、zoomY 1）と、その左 55% に実績バー（縦 × 0.5715 ＝ `S-5`）。予定の塗りは塗りの値、実績の塗りは実績の塗りの値、縁は両方とも縁の値（`CV-6`）。テーマ追随の縁は予定 `S-156`・実績 `S-158`。ラベルは `S-168` の字に地の色の縁取り（字 × 0.10 ＝ `S-34`）。
- カスタムカラーの実績の塗りは `CV-10` で導く（彩度と明度に `S-157` − `S-155` の差を足し、明度を `S-415` 15%〜`S-416` 85% に収め、比が `CT-3` の 3 : 1 に届かなければ逆向き、それでも届かなければ比の大きい端）。
- ハイライトボックス: テーマ色のタスクを 1 本置き、その上に箱（角の丸み 4px ＝ `S-132`、塗りの透過率 50% ＝ `S-371`）。枠の線の太さは選んだ px。

## 見本で分かったこと

測り方: 見本の倍率 1.25 で開き、各欄の要素の幅（`getBoundingClientRect().width`）を 1.25 で割ってアプリの寸法へ戻した（2026-10-01、Windows の system-ui 字体）。

- 入力の側の幅は 146.6px しかない（280 − 余白 16 − 枠 2 の 42% を名が取る）。
- `ライト: ■ 値 / ダーク: ■ 値` は、日本語・英語とも 4 欄すべてで 1 行に収まらず 2 行に折れた（`JDG-863` の絵は 1 行）。
- [塗潰しなし][その他の色] は 74.1 ＋ 62.5 ＋ 間 6 ＝ 142.6px で 1 行に収まった。ボックスの枠の空き枠を「線なし」の大きさにすれば、そこも収まる。

## 決まっていないこと

1. **ハイライトボックスの枠線色の「線なし」。** `JDG-863` の並びは [noline][custom] を置くが、仕様は枠の透明を禁じる（`FR-019`「ハイライトボックスの枠の線に透明を選ばせてはならない」、`PR-22`、`CV-9`「その欄では透明の場所は空けたまま」）。見本は今の `CV-9` どおり場所を破線で空けた。空けるか・詰めるか・「線なし」を許すかは仕様が決めていない —— 見本では決めない。
2. **ハイライトボックスの「塗潰しなし」が何をするか。** 保存する値は `transparent` で、箱の内側を塗らない（`FR-019`: 塗りの色が透明の箱は塗らない）。ただし「プロジェクトテーマ色」（`null`）も `S-370` の既定 `transparent` で描くので、既定では 2 つのボタンが同じ絵になる。違いは保存する値だけで、`S-370` を変えたときにだけ絵が分かれる。2 つを並べる意味を仕様は述べていない。塗りの透過率（`PR-24`、`S-371`）は透明の箱では効かない。本見本は透過率の欄を置いていない（`JDG-863` の並びに無い）。
3. **ボックスの「プロジェクトテーマ色」の語。** 枠の `null` は注記の色 `S-312`（色相に追随しない）で描くので、「プロジェクトテーマ色」と呼んでよいかは未定。
4. **枠線幅にテーマ（既定）へ戻す入口を置くか。** 今の列はどちらも `null` を取る（`AT-104`・`AT-145`）。`JDG-863` の並びは数だけなので、見本も数だけにした。`null` を残すなら、タスクの既定の px（`S-39` の 1px か）も決める。
5. **枠線幅が実績バーの縁にも掛かるか。** `CV-6` は色については予定と実績の両方の縁を名指すが、太さについては述べていない。見本は両方に掛けた（10px では実績バーが縁に埋もれる）。
6. **側の行が折れること**（上の測り方）。1 行に収めるなら、字・名の欄の割合・パネルの幅のどれかを動かすことになる。
