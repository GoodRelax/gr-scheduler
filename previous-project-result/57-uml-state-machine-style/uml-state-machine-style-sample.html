UML の状態遷移の見本 —— CR-767

ガードの書き方:

0. この見本は何か

利用者の裁定 JDG-2161 は、状態機械の原稿 docs/spec/_source/state-machines.json を唯一の正とし、状態遷移表と状態遷移図をどちらもそこから刷り、図は UML に準拠させると決めた。 ガードの条件を「言葉」で書くか「式」で書くかは答えに無い —— CR-767 の 11 節の Q1 が問う。上の 3 つのボタンで、同じ機械の図と表がどう変わるかを見比べられる。 図は drawio-uml の技能（Graphviz の dot で配置し draw.io で書き出す）で、原稿の値から刷った。表はこのページの中で原稿の値から組む。

名今と同じ —— ガードの名だけを書き、条件は下の一覧（6 節）で引く。 言葉ガードの条件を日本語の 1 文で書く（CR-767 の Q1 の択 A）。 式ガードの条件を小さな式で書く（Q1 の択 B）。式の語（ancestors()・children() など）は仕様が別に定める。

2. UML の図 —— タスクグループの木（treeStateMachine）

5 つの状態、11 の出来事、43 の遷移を 19 本の矢印に描いた。同じ 2 つの状態を結ぶ遷移は 1 本の矢印にまとめ、1 行に 1 つの遷移「出来事 [ガード] / 副作用」を並べた（CR-767 の ③ の X-c）。 「言葉」と「式」では矢印のラベルが長くなり、配置の道具がラベルを重ねる所がある —— 図のガードを名で書く案（③ の X-d）の根拠である。

3. 状態遷移表 —— タスクグループの木（treeStateMachine）

列 ＝ 今の状態（遷移元）、行 ＝ 出来事、升 ＝ 遷移先とガード条件（と副作用）。升の無い組は変化なし「—」。どのガードにも当たらないときは「それ以外 → —」。 JDG-2161 は、升にガードの名ではなく条件を見せると決めた —— 「言葉」か「式」を選ぶと升が条件になる。

4. Entry ／ Exit —— 二重カーソル（dualCursorModeStateMachine）

状態 on（中に placingDate1 と placingDate2 を持つ複合状態）から出る 3 つの遷移は、どれも同じ副作用 storeClearedDualCursor を起こす。 UML ではこれを on の exit 動作として 1 度だけ書ける。原稿を測って、同じ形の候補は 31 の機械のうち 4 つの状態だけだった（CR-767 の ③ の X-f）。

5. 兄弟の囲みの代わり —— 構え（armModeStateMachine）を UML で描くと

今の図の「notArmed 以外」の箱を、原稿の本物の複合状態 armed（新しい状態の案）にし、行き先が運ぶ値 armKind で決まる升を選択の擬似状態（◇）で分けた。 6 つの構えの状態のどの 2 つの間も結ぶ遷移（36 本）は、armed から ◇ への 1 本になる。⚠️ armed は今の原稿に無い状態であり、足すかは CR-767 の 11 節の Q3 が問う。 この図だけはガードを名で描いた。

6. ガードの定義（この見本に出る 9 つ）

CR-767 は、65 のガードのすべてに、この形の定義を原稿に持たせる。言葉と式の下書きは今のコードと契約試験から起こした（CR-767 の付録）。
