# 65 — AI 連携の調べ：取次の中身・API の仕様の在りか・人 / API / AI の機能の表

調べた版: `ec9803f1`（公開中の Pages と同じ）。調べた日: 2026-10-17。調べるだけで、直していない。

## 1. `grs-relay.mcpb` の中身と、GRS JSON の説明が AI へ届く道

### 1.1 束の中身（実測）

公開中の `https://goodrelax.github.io/gr-scheduler/download/grs-relay.mcpb` を落として zip を開いた（2026-10-17、Python の `zipfile`）。

| 入っているもの | 大きさ（展開後） | 圧縮後 | 中身 |
| --- | --- | --- | --- |
| `manifest.json` | 5,889 B | 2,402 B | 名・版（`0.0.0`）・22 の道具の名と説明・Node 18 以上 |
| `server/grs-relay.mjs` | 2,806,969 B | 620,097 B | 取次そのもの。**GRS の単一 `.html` を base64 で中に持つ**（`vite.relay.config.ts` の `relayEntry`） |
| `index.html` | 2,016,544 B | 402,694 B | GRS の単一 `.html`（`dist/index.html` とバイト一致） |

- 3 つの `.html` は同じ: zip の `index.html`・`.mjs` の中の base64 を戻したもの・`ec9803f1` の `dist/index.html` の SHA-256 の頭 16 桁がどれも `d621a138f308d32f`。
- ⚠️ **zip の `index.html` は使われていない** —— `.mjs` の中に `readFile` も `index.html` も 0 回（正規表現で数えた）。取次は中に持つ base64 を配る（`vite.relay.config.ts` の「the relay reads nothing from disk」）。束 1,025,529 B のうち 402,694 B（39 %）がこの使われない複製である。設計（`docs/spec/_assets/design-mcp-relay.md` 6 節）が「同じ版の単一 `.html` を入れた zip」と定めているとおりなので、コードの誤りではない。
- 版が `0.0.0` —— `package.json` の `version` をそのまま写す（`tools/build_relay_bundle.mjs` の `manifestOf`）。AI のアプリの拡張の画面では、どの版の束を入れたか見分けられない。

### 1.2 GRS JSON の説明は誰がどう Claude へ伝えるか

**専用の道は無い。** 取次が MCP の初期化で名乗る能力は道具だけである（`src/framework/mcp-relay-server/mcp-relay-server.ts:547-553` の `capabilities: { tools: {} }`、`:560-569` が答えるのは `initialize`・`ping`・`tools/list`・`tools/call` の 4 つだけ）。`instructions`・`resources`・`prompts` は無い。

Claude が手にするのは次の 3 つだけである。

| 道 | 何が届くか | 正 |
| --- | --- | --- |
| ① 道具の説明 | 22 の道具ごとの説明。表 T-107 の「何を担うか」の欄をそのまま刷ったもの | `docs/spec/_source/agent-api-members.json` → `tools/generate_mcp_tool_descriptions.py` → `src/adapter/mcp-tool-translator/mcp-tool-descriptions.json` |
| ② `applyCommands` の入力の形 | 90 の命令の 1 つずつの JSON Schema（鍵・型・範囲・正規表現と、列ごとの短い説明）。この道具だけで 52,374 字 | 同上 ＋ `docs/spec/_source/document-commands.json`（表 T-108） |
| ③ 読んだ値そのもの | `readDocument` は文書の値（`$schema` は持たない —— `src/entity/document-model/document/document.ts:67`）。`exportJson` の文字列だけが先頭に `"$schema": "https://goodrelax.github.io/gr-scheduler/spec/_source/grs-document.schema.json"` を持つ（`src/adapter/document-codec/json-codec.ts:460-466`） | 表 T-052 の `DR-4`、`S-540` |

⚠️ 届かないもの・届いても読めないもの（実測）:

- **GRS JSON のスキーマ本体（`grs-document.schema.json`、英語の説明つき）は MCP では届かない。** `readDocument` と `importDocument` の形は `"type": "object"` だけで中身の型が無い。スキーマの URL は Pages で `200` を返す（2026-10-17 に `curl` で確かめた）が、AI がそれを読むのは、AI のアプリがウェブを読めて、AI が自分で `exportJson` を呼んで URL に気づいたときだけである。
- **道具の説明はすべて日本語である** —— `mcp-tool-descriptions.json` の `description` 348 個のうち日本語を含むものが 348、ASCII だけのものが 0（Python で走査）。原稿 `agent-api-members.json` の `kinds` が `ja` しか持たない。
- **説明が仕様の行 ID を指すが、AI はその先を読めない** —— 同じ 348 個の中に `AT-3`・`AG-2`・`FR-134`・`T-317` のような行 ID が 315 回（異なり 192 種）現れる（正規表現 `[A-Z]{1,4}-\d+[a-z]?` と `T-\d+` で数えた）。仕様は束に入っていない。
- 人の道では届く: 「日程の画像をデータ化するプロンプトをコピー」（`IC-115`、`FR-068`）は、スキーマを連ねたプロンプトをクリップボードへ置く。人がそれを AI に貼れば、AI はスキーマを読む。MCP の道にはこれに当たるものが無い。
- 利用者の指示 2026-10-15（`DFC-2494` の行に記録）「初見AIがGRSのJSONのスキーマを読むだけでスケジュールの読み書き方法を理解できることが要求だ」は、スキーマが AI に届くことを前提にしている。MCP の道はその前提を満たしていない。

## 3. 人が使える機能・API として公開している機能・AI に制限している機能

### 3.1 読み方

- **人操作可否** —— 画面で操作できるか。入口は表 T-109 の `IC-n`（`docs/spec/_assets/tbl-glossary.md`、138 行）。
- **API 公開有無** —— `Agent API` のメンバ（`AM-n`）か、`applyCommands` が運ぶ命令（`CM-n`）があるか。○ ある ／ △ 一部 ／ × 無い。
- **AI 操作可否** —— MCP の取次を通して AI ができるか。取次は表 T-107 のメンバと 1 対 1 で、足しも省きもしない（`AG-12` の ④）ので、AI の道は `Agent API` だけである。
- ⭐ **「公開しているが AI には制限」** は ⛔ を付けた行。
- ID の `AF-n` はこの表だけの**仮の番号**であり、行 ID の接頭辞として登録していない（`row-id-prefixes.json` に `AF` は無い —— 確かめた）。
- 対応は手で引いた。表 T-109 の 138 行と表 T-108 の 91 行を、どれかの行の「備考」に載せた。
