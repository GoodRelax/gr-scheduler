## 1. 結論

1. GRS は β（11-28 の予定）の前に、新しい規則を当てない。β の前には、これから作る物の形を新しい基準に合わせるだけにする（段 1: CR-857 の用語集の JSON のキーと、CR-855 の改名の手順）。
2. 規則 07 は、11-08 の原本（`0db4e95`・`51958f0`）にも追いついていない。今回の版へ一度で追いつかせる。11-08 の計画の段 4〜7（計画の 391〜396）は本書の段 2〜5 に畳む。
3. 一番大きい仕事は 2 つある。コメントの移し（src と tests の約 700 ファイル）と、仕様を ANMS v0.36 の形へ組み替えること（要求の本体 1.4 MB）。どちらも β の後に置く。
4. 新しい基準書で初めてレビューすると、High の FAIL が多く出る（Gherkin 0 本、テストの記録 0、ユースケースの形）。基準書は High の受容に人の承認を求めるので、持ち主の承認の受け方を先に決める（問 6）。
5. 基準書と ANMS には、GRS が守り方を決められない所が 8 つある。チーム T へ返した（6 節）。
