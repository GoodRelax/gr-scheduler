# 追記: 短い質問「JSON のキーの名 —— self と own のどちらが自然か」（2026-11-22）

指摘 F-8（`selfShowMode`）で、持ち主が英語の self と own の違いを確かめるため、短い質問状（場面・`taskGroups[]` の JSON の断片・候補 `selfShowMode`・`ownShowMode`・`showMode`）を 2 つの外の AI に出した。答えを持ち主が貼った写しのまま置く。照らした裁定は `JDG-3736`。

## AI-A

```
問 1: self = ノードそのもの（子孫ではなく「この帯自体」を指す。CSS の `align-self` 等に近いツリー文脈の技術的な表現だが、「自己表示（自動動作）」のようにも読める硬さがある） / own = 自身固有の（親からの継承や子の集約ではなく「このノードに直接設定された値」を指す。`[its] own showMode` と文法的に自然だが、継承値と対比する場面以外ではやや冗長） / 違い: `self` は「対象範囲（子孫ではなく本体のみ）」、`own` は「所有・由来（他からの継承ではなく固有の設定）」を強調する点。
問 2: 1 位 `showMode` （理由: JSON ではオブジェクト直下のキーはその要素自身の属性を表すのが標準であり、対になる `childrenShowMode` 等がない限り修飾語は不要で、最も誤解なく「この帯の表示モード」と伝わるため）、2 位 `ownShowMode` （理由: 「この帯固有の設定意図」という意味が英語の語順として自然で、`self` のような「自動表示」の誤読がないため。なお別案としては、より一般的な `visibilityMode` も自然です）。
問 3: 「代表タスク自身」と誤読される心配はほぼありません（JSON の階層上、`self`/`own` は親であるタスクグループ自身を指し、兄弟キーの `representativeTaskUid` には結びつかないため）。また「子孫を含む」と誤読される心配もありません（どちらも範囲を自身に狭める語のため）。ただし逆方向の誤読として、「`hidden` にしても自分だけが隠れ、子孫は隠れない（子孫に波及しない）」と誤解されるリスクは、`self` や `own` を付けることでむしろ高まります。
```

## AI-B

```
問 1: self = 「そのオブジェクト自身」を強く指す。プログラマには馴染みがあり、親・子・代表タスクなど他要素との区別を連想しやすい / own = 「自分の」「所有する」の意味が強い。オブジェクト自身というより、そのオブジェクトが持つ何か（own properties など）を連想しやすい / 違い: self は対象そのもの、own は所有関係のニュアンス。今回は self のほうが自然。

問 2: 1 位 showMode（理由: taskGroup のプロパティなのだから通常は「その taskGroup の表示モード」と読む。最も自然で冗長さがない）、2 位 selfShowMode（理由: 「代表タスクではなく帯自身」を強調したいなら有効）、3 位 ownShowMode（理由: 英語として不自然ではないが、この用途では所有のニュアンスが混ざる）

問 3: self は「代表タスク自身」と誤読される可能性は低いが、読む人によっては「子孫を含まない taskGroup 本体」という強調だと解釈する。own は「その taskGroup が持つ表示設定」という意味には読めるが、「帯自身」を指すとは限らず、かえって曖昧。どちらも「子孫を含む」とは通常読まれないが、誤解の少なさでは self > own。なお、文脈が十分なら showMode が最も誤解されにくい。
```
