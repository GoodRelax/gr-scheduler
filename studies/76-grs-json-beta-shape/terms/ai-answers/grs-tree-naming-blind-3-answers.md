## 問 5. 第一印象
- 読みにくかった名（3 つ、理由つき）:
  1. `retracted`（英語札の `Retract`）: 一般的なツリーUIの「折りたたみ（`collapsed`）」と別に「引っ込める（`retracted`）」が存在する意図が英語名だけからは掴みにくい。「取り消す・撤回する」という意味も強い単語なので、日本語の「親へしまう」を見るまで「子ではなく自分自身を親へ格納する操作」だと気づきにくかった。
  2. `visibleDepth`（および数値 `2`）: プログラムの木構造ではルートを `0` と数える流儀と `1` と数える流儀の両方があるため、`2` が「B, C まで」なのか「B1, B2 まで」なのかを名前だけから一意に読めず、JSON内の `B1: revealed` との整合性から逆算する必要があった。
  3. `revealed`: `expanded` や `visible` ではなく「明かされた・露わになった」という少し受動的・文学的な語彙が使われているため、「ユーザーが手動で開いた状態」なのか「検索ヒットや条件一致で自動的に浮かび上がった状態」なのか、操作のニュアンスが読み取りにくかった。
- 読みが割れそうな名と割れ方:
  - `Retract` / 親へしまう（`retracted`）: 「押した帯**自身**が親の中に隠れる（B を押すと B が消える）」と読む人と、「B の**配下**が B の中にしまわれる（通常の折りたたみと同じ）」と読む人に割れそう。
  - `visibleDepth` の数値（`2`）: 「ルートを 1 と数えて 2段目（B, C）まで見える」と読む人と、「ルートを 0 と数えて深さ 2（B1, B2）まで全部見える」と読む人で真っ二つに割れそう。
  - 見出しの `∧∧`（Collapse All / すべて折りたたむ）: 「最上位の帯（A, D）だけ残して配下をたたむ」と読む人と、「文字通り全行がたたまれ、画面からすべての帯が消える」と読む人に割れそう。

## 問 4. 構造

| (a) 帯自身の意図を 1 つ | 賛成 | 帯の移動・貼り付けや階層変更（3-3）を行った際、親側が子の状態を持っていると状態の移し替えや不整合が起きやすい。帯自身が自分の意図を持つ設計は、操作の独立性と undo/redo の整合性を保つうえで非常に優れている。 |

## 問 5. 最大の危険
- 危険: 見出しの `∧∧`（Collapse All / すべて折りたたむ）を押した瞬間に最上位を含むすべてのタスクグループが画面から消えて空白になり、利用者が「全データが消えた」とパニックになること（および見出しの `∨` でそれをどう戻すか気づけないこと）。
- 起きる場面: 多数のタスクグループを開いて作業していた利用者が、一般的なアウトライナーや MS Project の「すべて折りたたむ」と同じ感覚（最上位行だけ残して配下を畳むつもり）で見出しの `∧∧` をクリックした場面。左欄の帯が 1 本残らず消えたうえ、隣の見出し `∨` が `Expand One Level`（1 階層だけ展開する）という名前のため「0 行の状態から最上位を取り出すボタン」だと結びつかず、復旧手段を見失う。
- 防ぎ方: ① 見出しの `∧∧` を `Retract All`（すべて見出しへしまう）、見出しの `∨` を `Restore Top Level`（最上位の帯を戻す）に改名し、「折りたたんで見出し行を残す」のではなく「見出しの中へすべてしまい込む／取り出す」操作であることを名前で明示する。② すべての帯がしまわれて 0 行になった直後は、空白になった帯欄の中央に控えめな案内（例:「すべてのタスクグループが見出しにしまわれています（▾ N）。クリックして最上位を戻す」）を表示し、復旧導線を視覚的に保証する。
