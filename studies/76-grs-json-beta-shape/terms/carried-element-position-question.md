## 1. 背景

GRS は、ブラウザで動く日程表のアプリです。日程を 1 つの JSON ファイル（GRS JSON）に保存し、Microsoft Project の XML 形式（MSPDI）とも読み書きします。外の道具（AI のエージェントを含む）も、この JSON を読み書きします。

MSPDI のタスクの一覧（`<Tasks>`）には、GRS がタスクとして扱わない要素も並びます。たとえば、ファイル全体を束ねる UID 0 の「要約タスク」や、中身の無い空のタスクです。GRS はこれらを捨てずに預かり、MSPDI へ書き出すときに元の場所へ戻します。

## 2. 今の案

GRS がタスクとして扱う物は `tasks` の配列に入ります。預かる物は、別の配列に「GRS の包み ＋ MSPDI のままの中身」で入ります。

```json
"tasks": [
  { "uid": 12, "name": "設計" },
  { "uid": 14, "name": "実装" }
],
"passthroughEntities": [
  { "collection": "Tasks", "precedingUid": 12,
    "element": { "UID": "13", "IsNull": "1" } }
]
```

- `collection`: MSPDI の一覧の名（`Tasks`・`Resources`・`Assignments`・`Calendars`）。
- `precedingUid`: 同じ一覧の中で、この要素の直前にあった要素の uid。上の例では「uid 12 の後、uid 14 の前」に戻す。一覧の先頭にあった要素は、このキーを書かない。UID 0 の要約タスクは、いつも先頭に戻す。
- `element`: MSPDI の要素を、構造と要素の名のまま。

前の仮の名は `afterUid` でした。依頼主は「名が何を指すか分からない」と退けました。

決まっていること:
- 名は、指すものを言う。略さない。
- キーは camelCase。参照は「相手の名 ＋ `Uid`」。
- 「無い」はキーを書かないことで言い、`null` は使わない。
- 物を「行（row）」と呼ばず「実体（entity）」と呼ぶ。

## 3. 指す先が消えたとき（今の案）

| 場面 | 今の案 |
|:---|:---|
| GRS の操作で、指す先のタスクを消す | 同じ操作の中で、`precedingUid` を「消したタスクの直前の要素の uid」に書き換える。直前が無ければキーを消す（先頭へ） |
| 開いたファイルで、指す先が無い | 文書は開く。その要素を一覧の末尾に置き、そのことを知らせる |
