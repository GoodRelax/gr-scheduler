# 質問状（1 回目）: 木の 4 つのボタン ∨・∨∨・∧∧・∧ の名を、対称に名づける案をください

**答え方: 答えはすべて日本語で（名そのものは英語と日本語で）、1 つのコードブロック（```markdown で始めて ``` で閉じる）の中に、8 節の型で書いてください。コードブロックの外には何も書かないでください。**

## 1. 頼みたいこと（一言で）

日程表アプリの、木の形に並んだ「帯」に付く 4 つのボタン **∨・∨∨・∧∧・∧** の名（英語の札・日本語の札・プログラムの中の出来事の名）を、**見た目どおり対称に名づける案**をください。4 つのうち **∧ だけが「押した帯自身」に効き、ほかの 3 つは「押した帯の中身」に効きます**。この食い違いをどう扱うかの考えもください。

名が正しいかよりも、**初めて画面を見た人が札だけで動きを当てられるか**を重く見てください。褒め言葉は要りません。

## 2. GRS とは（前提）

GoodRelax Scheduler（GRS）は、ブラウザだけで動く日程表（ガントチャート）のアプリです。タスクのバーは横に日付の軸を持ち、縦には **タスクグループ** と呼ぶ横長の **帯** が積まれます。帯は親子の木（アウトライン）を作ります。画面の左の欄に帯の名が木の形で並び、各帯の名の横にボタンが並びます。

以下の例は、すべてこの木で書きます（字下げが親子）。

```text
A
├─ B
│   ├─ B1
│   │   └─ B1a
│   └─ B2
└─ C
```

## 3. 4 つのボタンが何をするか（帯 B で押した例）

帯の木の外に、もう 1 つの軸があります: **縦のズームが自動で深さを決める**。縦に縮めると深い帯から自動で描かれなくなり、広げると戻ります（最上位の帯は縮めても落ちません）。人がボタンで決めた帯は、ズームより優先します。

**状態の模型（今の検討の到達点）:** 各帯は、**自分自身についての人の意図**を 3 つのうち 1 つだけ保存します。

| 保存する意図（今の候補の名。決定ではない） | 意味 |
|:---|:---|
| `show` | 画面に出せ（ズームで縮めても出す） |
| `hide` | 画面から消せ（ズームで広げても出さない） |
| `automatic` | ズームの深さ（とピン止めなど）に任せる |

画面に実際に出ているか（`visible`／`invisible`）は、この意図とズームと木から **導く結果** で、保存しません。決まり（不変条件）が 1 つあります: **`hide` の帯の子孫は、みな `hide`**（消えた帯の下に、見える帯は作れない）。

**各ボタンが書くもの:**

| ボタン | 動き | 書く意図 | 押した帯 B 自身 |
|:---|:---|:---|:---|
| ∨ | 直下の子だけを出す。孫より下は出さない | B の子に `show` | 変えない |
| ∨∨ | 配下をすべて出す | B の子孫すべてに `show` | 変えない |
| ∧∧ | 配下をすべて消す。B は残る | B の子孫すべてに `hide` | 変えない |
| ∧ | **B 自身と配下を消す**（親 A の中へしまう） | B と子孫すべてに `hide` | **`hide` にする** |

**前後の絵**（「…」は、その帯の配下が描かれていないこと）:

```text
[∨ を B で押す]            前                  後
                           A                   A
                           ├─ B …              ├─ B
                           └─ C                │   ├─ B1 …
                                               │   └─ B2
                                               └─ C

[∨∨ を B で押す]           前                  後
                           A                   A
                           ├─ B …              ├─ B
                           └─ C                │   ├─ B1
                                               │   │   └─ B1a
                                               │   └─ B2
                                               └─ C

[∧∧ を B で押す]           前                  後
                           A                   A
                           ├─ B                ├─ B …
                           │   ├─ B1           └─ C
                           │   │   └─ B1a
                           │   └─ B2
                           └─ C

[∧ を B で押す]            前                  後
                           A                   A
                           ├─ B                └─ C
                           │   ├─ B1
                           │   │   └─ B1a
                           │   └─ B2
                           └─ C
```

- ∧ で消えた B を戻す専用の場所はありません。**親 A の ∨ で戻ります**（戻るのは B だけ。B の子は消えたまま）。A の ∨∨ でも戻ります（配下ごと）。仕様はこれを「1 本の上向きで親へ折りたたみ込み、親の 1 本の下向きで戻る」と言い、∧ と親の ∨ を対として設計しています。
- **∧ の「1 段だけ畳む」版が無い理由:** 上の不変条件があるので、「B の直下の子だけを消す」は「B の配下をすべて消す」（∧∧）と同じ絵になります。下向きは「1 段」と「全部」で別の絵になるのに、上向きで中身に効く操作は 1 つしか区別できません。4 つ目の場所を「自分を消す」が埋めている、という形です。
- 「全体を収める」（Zoom to Fit）は、`show` を `automatic` へ戻し、`hide` は残します。
- 帯には、ほかにピン止め・配下に足す・消すのボタンもありますが、今回の問いの外です。

**パネルの頭（帯の欄の見出し）のボタン:** 頭は「最上位の帯のさらに上にある、深さ 0 の仮の根」として扱われます。頭の ∨ は最上位の帯に `show`、∨∨ はすべての帯に `show`、∧∧ はすべての帯に `hide` を書きます（頭の ∧∧ の後は、帯が 1 つも描かれないことがあり、頭の ∨ で最上位が戻ります）。**頭に ∧ はありません**（しまい込む先の親が無い）。

## 4. 今の札（出荷中）と、今ある候補

**出荷中の札**（英 ／ 日。かっこの中は説明の文）:

| ボタン | 英語の札（説明） | 日本語の札（説明） |
|:---|:---|:---|
| 帯の ∨ | Expand One Level（Expand only this task group's own children, leaving deeper task groups collapsed） | 1 階層だけ展開する（このタスクグループの直下の子だけを展開する。孫より下は折りたたんだままにする） |
| 帯の ∨∨ | Expand Below（Expand every task group below this one） | 配下をすべて展開する（このタスクグループの配下をすべて展開する） |
| 帯の ∧∧ | Collapse Below（Collapse every task group below this one） | 配下をすべて折りたたむ（このタスクグループの配下をすべて折りたたむ） |
| 帯の ∧ | Collapse（Collapse this task group itself） | 折りたたむ（このタスクグループ自身を折りたたむ） |
| 頭の ∨ | Show Top Level Only（Bring back only the shallowest task groups, leaving what is under them collapsed） | 最も浅い段を 1 階層展開する（最も浅い段のタスクグループだけを戻す。その配下は折りたたんだままにする） |
| 頭の ∨∨ | Expand All（Expand every task group that was collapsed） | すべて展開する（折りたたんだタスクグループをすべて展開する） |
| 頭の ∧∧ | Collapse All（Collapse every task group） | すべて折りたたむ（すべてのタスクグループを折りたたむ） |

今の出来事の名（プログラムの中。camelCase で、末尾は `Pressed`）: 帯は `oneLevelOpenPressed`・`allBelowOpenPressed`・`allBelowFoldPressed`・`hidePressed`、頭は `topLevelOpenPressed`・`everyTaskGroupOpenPressed`・`everyTaskGroupFoldPressed`。動詞が Open・Fold・hide に割れていて、札の Expand・Collapse と合っていません。

**今ある候補（どれも決定ではありません。採らなくて構いません）:**

| 候補 | ∨ | ∨∨ | ∧∧ | ∧ |
|:---|:---|:---|:---|:---|
| 甲（札は ∧ だけ直す） | Expand One Level ／ `expandOneLevelPressed` | Expand Below ／ `expandBelowPressed` | Collapse Below ／ `collapseBelowPressed` | Collapse Into Parent・親へ折りたたむ ／ `collapseIntoParentPressed` |
| 乙（慣わしに寄せる） | Expand | Expand All Levels | Collapse | Collapse Into Parent |
| 丙（全部を show／hide の語に） | Show Children | Show All Below | Hide All Below | Hide |

- 甲の ∧ は、仕様の言い方「隠すことは、親へ 1 歩折りたたみ込むこと」から来ました。**持ち主は「Collapse Into Parent も悪くないが、なんかこうダサい」と感じています。**
- 乙は札「Collapse」が今の ∧ から ∧∧ へ移るので、今の札を覚えた人とヘルプが取り違える、という反対があります。
- 丙は、保存する意図の名（`show`／`hide`）と動詞が同じ語になる一方、製品の別の所（表の列の Show／Hide）とも同じ語になります。

## 5. 持ち主の望み

持ち主の言葉（そのまま）: 「v・vv・^^・^ のボタンの名称が重要だな。…見た目が対称なので対称的な命名にしたい。^だけが自分自身への操作になるので、鬼っ子だな。collapseIntoParent も悪くない... がなんかこうダサいのよ。」

## 6. 名づけの決まり（守ってほしいこと）

| 決まり | 中身 |
|:---|:---|
| 名は体を表す（NEIM） | 名だけで意味が分かること。説明の文を読まないと分からない名は弱い |
| 1 つの名に 1 種類（OKPN） | 1 つの名が、2 種類の物を指さない |
| 1 つの値に 1 つの意味（OMPV） | 同じ語が 2 つの意味を持たない（例: collapse が「自分が消える」と「中身が消える」の両方を指すのは避けたい。今の札はまさにそうなっている） |
| 略さない | 許す略は `uid`・`id`・`Px`・`Utc`・`dx`・`dy`・`min`・`max`・`hex` だけ（`auto`・`btn`・`expd` などは使えない） |
| 世の慣わし | collapse／expand（fold／open）は、木の UI の慣わしでは「押した節の中身（子）」に効く動詞で、節自身は残る（WAI-ARIA の `aria-expanded`、エディタやファイルの木、表計算のアウトラインなど）。自分自身が見えるかは hidden／visible など別の語で言うのが普通 |
| 3 つの形 | 英語の札（Title Case）・日本語の札・出来事の名（camelCase、末尾 `Pressed`。例: `expandOneLevelPressed`） |
| 記号は今のまま | ∨・∨∨・∧∧・∧ の絵は変えない（札と説明の文と名だけを変える） |
| 保存する意図とぶつからない | 保存する意図の名（今の候補 `show`・`hide`・`automatic`）と、画面の結果の名（`visible`・`invisible`）は別に決めている。ボタンの名は、これらと読み違えないこと |

## 7. 問い

**問 1.** 4 つの帯のボタン（∨・∨∨・∧∧・∧）に、**対称な名の組を 2〜3 組**ください。1 組ごとに、英語の札・日本語の札・出来事の名・説明の文（英語 1 文）を 4 つ全部と、その組を選ぶ理由（対称をどう作ったか、6 節の決まりのどれに強く、どれに弱いか）を書いてください。4 節の候補を直した案でも、まったく新しい案でも構いません。

**問 2.** ∧ だけが自分自身に効く食い違い（「鬼っ子」）を、どう扱うのがよいですか。名だけで済ませる道と、考え方を変える道の両方について、**良い所と悪い所**をください。少なくとも次の 3 つを比べてください（ほかの道があれば足してください）。
- (a) 動きはそのままで、∧ を「自分を消す」と言い切る名にする（例: Hide 系）。ほかの 3 つの名と対称に見せられるか。
- (b) 動きはそのままで、∧ を「親の中へしまう」と、親から見た言い方にする（今の Collapse Into Parent の系）。ダサくない言い方はあるか。
- (c) ボタンの組そのものを見直す。たとえば ∧ も中身に効く操作にして対称を作り、「自分を消す」は別の場所（右クリックの一覧など）へ移す。3 節のとおり「1 段だけ畳む」は ∧∧ と同じ絵になるので、別の動き（例: 見えている最も深い段を 1 段だけ消す）が要ります。その動きに意味があるか、∧ と親の ∨ の対（しまう・戻す）が崩れてよいか。

**問 3.（別の問い）** 持ち主は「Top レベルとそれ以外を分ける必要があるのか？」とも問うています。頭のボタン（深さ 0 の仮の根の ∨・∨∨・∧∧）と帯のボタンは、動きは同じで範囲だけが違います。今の札は別の名です（帯 Expand One Level ／ 頭 Show Top Level Only、帯 Expand Below ／ 頭 Expand All、帯 Collapse Below ／ 頭 Collapse All）。なお頭の ∨ は、英語の札（Show Top Level Only）と日本語の札（最も浅い段を 1 階層展開する）の言い方も違います。また今の設計案では、頭の ∨ は最上位の帯に `show` を書くだけで、深い帯を消しません（札の「Only」が当たるのは、深い帯がもともと消えているときだけです）。
- 頭と帯で **同じ名にする**（範囲は置き場所で分かるとする）のと、**別の名にする**のと、どちらがよいですか。それぞれで起きる困り事（ヘルプ・説明の文・外の AI が使う命令の名・読み違い）を挙げてください。
- 問 1 の組ごとに、頭の 3 つの名も添えてください。

**問 4.（短くて構いません）** 同じ 4 つの動き（1 段出す・全部出す・全部畳むが自分は残る・自分ごとしまう）を、よく知られた道具（エディタ、アウトライナ、表計算、ガントの道具など）はどう名づけていますか。記憶による物はそう書いてください。
