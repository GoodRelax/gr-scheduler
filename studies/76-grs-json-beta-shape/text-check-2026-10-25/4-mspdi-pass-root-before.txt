Terms used in these descriptions. MSPDI: The Microsoft Project XML Data Interchange format used by Microsoft Project. GRS: GoodRelax Scheduler, the tool that generates this file. "Same as MSPDI X": The property has the same meaning and values as MSPDI element X. Any GRS-specific differences follow in the same description. Properties without this mark are defined by GRS. A GRS schedule document. `$schema` is where the latest version of this schema lives (the same as this schema's $id). It is the first property, so that a person who has only the document can find the schema; a reader never refuses a document because of its value. `schedule` is the data; `documentSettings` is how it is drawn when opened; `documentStamp` and `changeLogEntries` record when, by whom and why it changed. A property with no value is omitted: null is never written, and an empty array [] is never written. So "the source had no value" (the property is absent) and "the value is 0" are never confused. What comes from MSPDI keeps its names and codes, so that nothing is lost when the file goes to MSPDI and back. Times come in two kinds, for two reasons. Schedule date-times (start, finish, deadline, statusDate, calendar exceptions, comment boxes) are wall-clock times without a zone, exactly as MSPDI writes them, so that they come back unchanged; project.scheduleDataTimeZone says whose wall clock they are. They are read as instants to the minute (seconds are cut) and never shifted by an offset. Write each one with its time: a date without a time is read as the start of that day's first working span on a start-side property and the end of its last span on a finish-side property, which is seldom what was meant. A finish-side value is the instant the work ends; a milestone's start and finish are the same instant. A calendar exception runs from 00:00:00 to 23:59:00. A range of whole days (a highlight box, the fit span) is written as firstDay and lastDay (YYYY-MM-DD), both included. Record times (schemaVersion, buildVersion, documentStamp, changeLogEntries) are UTC (YYYY-MM-DDTHH:MM:SSZ), so that every reader sees them in their own local time. A color is one of three kinds: {"kind":"theme"} follows the theme, {"kind":"palette","name":...} is a named color of the palette, and {"kind":"custom","light":...,"dark":...} gives a value for each theme. In a custom color, each side is {"value":"#rrggbb","source":...}: "chosen" when a person picked it, "derived" when GRS made it from the other side. You may omit one side; GRS derives it when it opens the file. Where a color property may be omitted, an absent color means that part is not drawn.
