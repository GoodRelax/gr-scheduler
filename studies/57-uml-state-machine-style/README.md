## 見て分かったこと

- **言葉と式は図のラベルを長くする。** 木の機械の図の 19 本のラベルは、どの書き方でも 1 本が最大 4 行で、1 行の最長は名 67 字・言葉 88 字・式 108 字（見本を作った変換の `model.json` を数えた）。長くなるほど、配置の道具（Graphviz の dot）がラベルどうしを重ねる所が増える。⇒ CR-767 は「表の升は条件、図のラベルはガードの名」とした（③ の X-d）。
- **表は向きが今と同じ。** 今の刷りは既に行 ＝ 出来事・列 ＝ 葉の状態であり、変わるのは升に条件が出ることと、Entry ／ Exit の行が足せること。
- **Entry ／ Exit の候補は少ない。** 31 の機械を測り、ある状態へ入る（出る）遷移が 2 本以上あって、どれも同じ副作用を持つのは 4 つの状態だけだった（`dualCursorModeStateMachine` の `on` の exit、`scaleMessageDisplayStateMachine` の `shown`、`fileOperationStateMachine` の `readingDocumentFile`・`importingDocument` の entry）。
- **兄弟の囲みを UML にすると、状態が 1 つ増える。** 構えの「notArmed 以外」は、原稿に本物の複合状態を足さないと UML で描けない（足さなければ 36 本の矢印になる）。足すかは CR-767 の Q3。
- **drawio-uml の手当てが 3 つ要った。** ① ラベルの改行は `.drawio` の値の改行を `&#xa;` に直さないと 1 行に潰れる ② 群の箱が点線（クラス図の群の形）で描かれるので、複合状態の実線の角丸に直した ③ クラス図の凡例が付くので消した。SVG は `--embed-svg-fonts false` で書き出した（字を絵にしないので 13〜45KB）—— `docs/spec/_source/build.py` の前例と同じ。

## 作り方（再現）

- 原稿 `docs/spec/_source/state-machines.json`（`4a907919`）の機械を、セッションの作業場の小さな変換（機械 → drawio-uml の `model.json`、遷移を (元, 先) の組でまとめ、ガードを名・言葉・式で書く）にかけ、drawio-uml の `draw.py`（`engine: "dot"`）で `.drawio` を作り、上の 3 つの手当てをして、draw.io の CLI で SVG に書き出した。変換は作業場に置き、リポジトリには入れていない —— CR-767 が当てる刷り手が同じことを正式に行う。
- ガードの言葉と式は、今のコード（`task-group-folding.ts` の `TASK_GROUP_GUARDS`、`screen-values.ts`）と契約試験の `guardHolds` から起こした下書きであり、決まった文ではない。
- 表はページの中で、埋め込んだ原稿の値から組む（図と同じ値）。
