# タスクグループ名のリンク（study 79）

- 作った日: 2026-10-25。基は `develop` の `4b4dae6fe`。
- 裁定: `JDG-3083`（リンクを持つタスクグループの名は青い字に下線）、`JDG-3084`（1 回の押下で開き 2 度の押下で名前の欄を開く。待つ長さと後ろのタブは見本で測ってから決める）。
- 見本: [`link-click-sample.html`](link-click-sample.html)（1 ファイル。ダブルクリックで開く。通信しない。リンクの先はこのファイル自身）
- 測り: [`probe-open-tab.mjs`](probe-open-tab.mjs)
- この調べは仕様書・台帳を 1 行も変えていない。

## 1. 測ったこと

| # | 開き方 | 待ち | Edge 156.0.4314.42 | Chrome 155.0.8059.85 |
|---|---|---|---|---|
| 1 | ページが `window.open(url, '_blank', 'noopener,noreferrer')` | 0 | 前に出る | 前に出る |
| 2 | 同じ | 500 ms | 前に出る（止められない） | 前に出る（止められない） |
| 3 | ページが隠したリンクへ Ctrl 付きの押下を送る（`dispatchEvent`） | 0 | 前に出る | 前に出る |
| 4 | 同じ | 500 ms | 前に出る | 前に出る |
| 5 | ページが隠したリンク（`target=_blank`）を押す | 0 | 前に出る | 前に出る |
| 6 | 同じ | 500 ms | 前に出る | 前に出る |
| 6b | ページが `window.open` の直後と 50 ms 後に `window.focus()` で元のタブを前に戻そうとする | 0 と 500 ms | 前に出たまま（元のタブは `hidden` のまま） | 前に出たまま（同じ） |
| 7 | 人が名前（本物の `<a href>`）を Ctrl を押しながら押す | —（ブラウザが開く） | 後ろに開く | 後ろに開く |
| 8 | 人が名前をホイールで押す | —（ブラウザが開く） | 後ろに開く | 後ろに開く |

「前に出る」は、新しいタブの `document.visibilityState` が開いた直後から `visible` で、元のタブが `hidden` になったこと。「後ろに開く」はその逆。

### 測り方

`node studies/79-task-group-link-click/probe-open-tab.mjs <ブラウザの exe> <名> <結果の json>`。ブラウザを使い捨ての利用者データ（`--user-data-dir` を一時フォルダ）で起こし、窓を画面の外に置き、窓の隠れの計算を切る（`--disable-features=CalculateNativeWinOcclusion` —— 画面の外でも前のタブが `visible` のまま測れる）。押下は CDP の `Input.dispatchMouseEvent`（ブラウザが人の押下として受ける）。1 つの場合ごとに、増えたタブの見え方と元のタブの見え方を読み、増えたタブを閉じる。Edge は 3 回、Chrome は 2 回走らせ、新しいタブの見え方はどの回も上の表と同じ（Chrome の 1 回目は元のタブの見え方を、増えたタブを閉じた後に読んでいたので、その列だけ使わない）。⚠️ Edge の 1 回目と 3 回目に、ブラウザが自分で開いたタブ（歓迎のページ、拡張機能のサインインのページ）が混じった —— 見本の URL で始まらないタブを数から除いた。

ダブルクリックの間隔は、この機械の Windows の設定（`HKCU\Control Panel\Mouse` の `DoubleClickSpeed`）で 500 ms（Windows の既定）。ブラウザはこの値で 2 度の押下を 1 つのダブルクリックとみなすが、ページからは読めない。CDP の押下は押した回数を呼ぶ側が渡すので、この間隔は CDP では測れない —— 人の間隔は見本の 4 節が測る。

## 2. 分かったこと

1. **ページが開くタブは、待ちがあっても無くても、Edge と Chrome のどちらでも前に出る。** ページから後ろのタブを選ぶ道は無い（Ctrl 付きの押下をスクリプトで作っても効かない。開いた後に `window.focus()` で元のタブを前へ戻すこともできない —— 6b、2026-10-25 に利用者の「ワンクリックでバックグラウンドで開かせる方法がないってこと？」を受けて足した測り）。
2. **500 ms 待ってから開いても止められない。** 人の押下から 500 ms 後の `window.open` は、どちらのブラウザもポップアップとして止めなかった。
3. **後ろに開けるのは、人が本物のリンクを Ctrl を押しながら押すか、ホイールで押したときだけ。** 名前を本物の `<a href>` で描けば、この 2 つはブラウザが待たずに後ろへ開く（ページの待ちは要らない）。
4. **待つ長さは、ダブルクリックの間隔より短いと、ゆっくりのダブルクリックでもタブが開く。** 間隔はページから読めないので、待ちは決まった値になる。Windows の既定の 500 ms に合わせれば、既定のままの人のダブルクリックでタブは開かない。間隔を長くしている人（例 900 ms）では、500〜900 ms のゆっくりのダブルクリックで、タブが開き、名前の欄も開く。

## 3. 決めること（利用者）

- 1 回の押下で開くまでの待ち —— 500 ms（Windows の既定に合わせる）か、もっと短くするか。
- 新しいタブ —— 1 回の押下では前に出る（ページから選べない）。後ろに開きたいときは Ctrl を押しながら押すかホイールで押す、と書くか。
