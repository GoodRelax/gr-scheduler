# 拡大縮小の戦略（study 78）

- 作った日: 2026-10-25。基は `develop` の `80927c91d`。
- 見本: [`scaling-sample.html`](scaling-sample.html)（1 ファイル。ダブルクリックで開く。サーバーも通信も要らない）

## 2. 測ったこと

### 2.1 ブラウザが見せる値（`sweep-browser-zoom.mjs` → `result-browser-zoom.json`）

本物のブラウザの倍率（Edge の利用者設定の既定の倍率）と、OS の倍率の代わり（`--force-device-scale-factor`）を掛け合わせ、ページが読める値を測った。窓は 1280 × 800（DIP）、headless と画面に出す窓の両方。

| OS | ブラウザ | `devicePixelRatio` | `innerWidth`（CSS px） | `outerWidth ÷ innerWidth` | 合う `resolution` |
| ---: | ---: | ---: | ---: | ---: | --- |
| 100% | 100% | 1 | 1256 | 1.0191 | 1dppx |
| 100% | 150% | 1.5 | 837 | 1.5293 | 1.5dppx |
| 150% | 100% | 1.5 | 1256 | 1.0191 | 1.5dppx |
| 125% | 80% | **1** | 1570 | 0.8159 | 1dppx |
| 150% | 150% | 2.25 | 837 | 1.5293 | （無い） |
| 200% | 200% | 4 | 628 | 2.0382 | 4dppx |

（全 54 行は `result-browser-zoom.json`。）

| # | 事実 | 根拠 |
| --- | --- | --- |
| F1 | `devicePixelRatio` は **OS の倍率 × ブラウザの倍率** の積に、浮動小数の誤差まで一致する | 54 行すべて |
| F2 | **積しか読めない** —— OS 150%・ブラウザ 100% と OS 100%・ブラウザ 150% は同じ 1.5、OS 125%・ブラウザ 80% は 1 で何もしていない機械と区別できない | 上の表 |
| F3 | ページの CSS の幅は、窓の幅（DIP）÷ ブラウザの倍率。最大化した窓ではモニターの物理の幅 ÷ `devicePixelRatio` になる | `innerWidth` の列 |
| F4 | `outerWidth ÷ innerWidth` はブラウザの倍率だけを近く表すが、窓の枠の分（約 2%）ずれ、横の帯や開発者ツールを開けば崩れる。OS の倍率は映らない | 同列 |
| F5 | `screen.width` はブラウザの倍率で変わらない。`visualViewport.scale` はいつも 1（指の拡大だけを表す） | `result-browser-zoom.json` |
| F6 | `matchMedia('(resolution: …dppx)')` の変化で「積が変わった」ことだけは知れる。どちらの層が動いたかは知れない | `res` の列 |
| F7 | ブラウザの倍率を、ページから読む・変える API は無い（拡張機能だけが変えられる） | 標準の API の一覧（利用者が貼った覚え書きと同じ） |

### 2.2 出荷の作りの書き出し（`sweep-app-export.mjs` → `result-app-export-free.json`・`result-app-export-fixed.json`）

`dist/index.html`（`develop` の `80927c91d` の作り）で `sample-small-website-renewal.en.xml` を開き、全体表示を押してから SVG と PNG を書き出した。窓はモニターを埋める大きさ。透かしの層（表 T-020 の `ZO-12`、開いた人と時刻が入る）を除いた SVG の指紋と、その SVG を 1920 幅に描いた画素の指紋を比べた。

**期間を固定していないとき（今の `FR-080`）:**

| モニター | OS | ブラウザ | CSS の幅 | 縮める比 | PNG の字（目盛の約 13px の字が） |
| --- | ---: | ---: | ---: | ---: | --- |
| 1920 | 100% | 50% | 3792 | 0.506 | 約 6.6px（[`export-free-zoom50.png`](export-free-zoom50.png)） |
| 1920 | 100% | 100% | 1896 | 1.013 | 約 13px |
| 1920 | 100% | 200% | 948 | 2.025 | 約 26px（[`export-free-zoom200.png`](export-free-zoom200.png)） |
| 3840 | 200% | 100% | 1896 | 1.013 | 1920 / 100% と **同じ絵**（SVG も画素も一致） |
| 3840 | 150% | 100% | 2536 | 0.757 | 約 10px |

| # | 事実 |
| --- | --- |
| F8 | 期間を固定していない絵は、**縮める比 ＝ 1920 ÷ CSS の幅** であり、ブラウザの倍率・OS の倍率・窓の幅のどれでも変わる。比は「物理の画面を 1920 幅へ写した倍率」に等しい —— 1920 の物理の画面では、画面の画素をそのまま写した絵になる |
| F9 | CSS の幅と `devicePixelRatio` が同じなら、SVG も PNG の画素も同じになる（1920 / 100% と 3840 / 200%）。**PNG に描く段は `devicePixelRatio` に依らない** —— 絵の幅はいつも 1920 画素 |
| F10 | ブラウザ 50% では PNG の中の字が 7px を切り、読めない。200% では見える範囲が狭まり、下の行が切れる |

**期間を固定したとき（`IX-12` 〜 `IX-16`）:**

| 比べたもの | 結果 |
| --- | --- |
| `devicePixelRatio` が 1 と 2 の 4 つ（1920/100%/100%、1920/100%/200%、3840/200%/100%、1280/100%/100%） | SVG・画素とも **すべて同じ**（[`export-fixed-zoom100.png`](export-fixed-zoom100.png)・[`export-fixed-zoom200.png`](export-fixed-zoom200.png)） |
| `devicePixelRatio` が 1.5（OS 100%・ブラウザ 150% と、OS 150%・ブラウザ 100%） | 2 つは互いに同じ。だが 1 のときと **違う** |
| `devicePixelRatio` が 0.5・0.67・0.8・0.9・1.1・1.25 | それぞれ違う |

| # | 事実 |
| --- | --- |
| F11 | 期間を固定した絵は、窓の大きさにもブラウザの倍率にも依らない **はず**（`IX-12`）だが、`devicePixelRatio` が整数でないと、すべての縦の位置が 0.33px ずれる（868 か所。例 高さ 656 → 655.67） |
| F12 | 原因は `App Header` の高さを DOM から測っていること —— `dom-screen-surface.ts` の `reportHeaderHeight()` が `getBoundingClientRect().height` を読み、その値が組み方の入力（`appHeaderHeight`）になる。測った高さは物理の画素の格子へ寄る: ブラウザ 100% と 200% で 29px、125% で 28.8px、150% で 28.67px、80% で 29.24px（OS 100%、同じ作り）。**`IX-12` の「同じ文書から毎回同じ絵」を破る不具合**（`DFC-3594` の候補） |

### 2.3 文書が持つ px の、今の意味

| 欄（GRS JSON） | 既定の行 | 描くときに掛けるもの（今） | CR-851 の後 |
| --- | --- | --- | --- |
| `documentSettings.taskGroupPanelWidthPx` | `S-79` | 表示の倍率 ÷ 100 × 0.625 | 表示の倍率 ÷ 100（値を畳む） |
| `documentSettings.rulerFontSizePx`・`rulerHeightPx` | `S-3`・`S-2` | 表示の倍率 ÷ 100 × 0.625 | 表示の倍率 ÷ 100（値を畳む） |
| `TaskVisual.strokeWidthPx` | `S-39` | 表示の倍率 ÷ 100 × 0.625 | 表示の倍率 ÷ 100（CR-851 の 15） |
| `TaskGroup.minHeightPx` | —— | 表示の倍率 ÷ 100（`DS-13`、`JDG-710`） | 同じ |
| `CommentBox.fontSizePx`・`strokeWidthPx`・`bodyOffsetPx` | `S-624`・`S-374` | **何も掛けない**（`JDG-464`・`JDG-2895`） | 決めていない |
| `HighlightBox.strokeWidthPx`・`cornerRadiusPx` | `S-369`・`S-132` | **何も掛けない**（`JDG-456`） | 決めていない |

名の末尾の `Px` が、CR-851 の後も 2 つの意味（表示の倍率に従う px ／ 従わない px）を言う。ズーム（L6）はどの欄にも掛けない —— これは揃っている。

## 3. 戦略の案

| # | 決まり | 理由 |
| --- | --- | --- |
| P1 | **GRS は L2・L3 を読まず、変えず、打ち消さない。** `devicePixelRatio`・`outerWidth`・`screen.*` を、組み方・文書・書き出しの入力にしない。自分の根に CSS の `zoom` や `transform` を掛けてブラウザの倍率を打ち消さない | F2・F4・F7 —— 読めるのは積だけで、近似は窓の作りで崩れる。ブラウザの倍率は読む人の道具であり（WCAG 1.4.4・1.4.10）、打ち消すと読む人の拡大を奪う |
| P2 | GRS の画面の単位は **CSS の px** だけとする。文書の `…Px` は「表示の倍率 100 のときの CSS の px」 | P1 から。物理の大きさはブラウザと OS が決める |
| P3 | 文書が持つ倍率は L4・L5・L6 だけ。L4 は「絵の大きさ」、L5 は「字の大きさ」、L6 は「日付と行の間隔」を言い、互いに掛け算で重ねる（表 T-252） | 3 つは目的が違う（`JDG-131`・`JDG-1562`）。L3 と違い文書と一緒に渡り、AI も読み書きできる |
| P4 | 書き出す絵は 2 つの組み方を持つ —— 期間を固定していなければ **画面のとおり**（L1〜L3 に従う）、固定していれば **文書だけで決まる**（L1〜L3 に従わない） | 5 節 Q1 |
| P5 | 2 つ目の組み方は、DOM から測った寸法（ヘッダーの高さなど）を入力にしない | F11・F12 |
| P6 | PNG の画素は 1920 幅に固定し、`devicePixelRatio` で増やさない | F9。倍率を持たない（`IX-1`・`IX-2`） |

## 4. 見本の開き方

| したいこと | すること |
| --- | --- |
| 層を動かす | 右の「読む人の環境」と「文書が持つ値」 |
| ブラウザの倍率で書き出しがどう変わるかを見る | 「ブラウザの倍率」を 50% と 200% に。2 の絵（案 A）は字と範囲が変わり、3 の絵（案 B）は変わらない |
| 本物の値を見る | 本当に `Ctrl` ＋ `+` を押す。4 の表の `devicePixelRatio` と CSS の幅が変わる |
| コメントボックスの扱いを比べる | 「コメントボックスも表示の倍率に従う」を入れて、表示の倍率を 50 にする |
| 値を伝える | 右下の灰色の塊をそのまま貼る |

⚠️ 見本の日程は既定値を写した模型であり、出荷のコードではない。書き出しの数（2.2 節）は出荷の作りで測った。

## 5. 決めたこと（2026-10-25、利用者に 1 問ずつ）

| # | 問い | 答え | 退けた案 |
| --- | --- | --- | --- |
| 1 | 書き出す PNG / SVG は何に従うか | **今の 2 本立て** —— 期間を固定していない文書は画面のとおり（ブラウザの倍率・OS の倍率・窓の幅で変わる）、固定した文書は文書の値だけで決まる。0.33px のずれ（F11）は直す | いつも基準の画面 1920 × 1080・100% で組み直す ／ いつも画面のとおり |
| 2 | 文書の `…Px` の意味 | **1 つに揃える** —— どれも「表示の倍率 100 のときの CSS の px」で、描くときに表示の倍率 ÷ 100 を掛け、ズームは掛けない。コメントボックスの字・線・ずれ、ハイライトボックスの線・角も従う（`JDG-456`・`JDG-464`・`JDG-2895` の「画面の px」を表示の倍率について覆す） | 名前で 2 つに分ける（`fontSizeScreenPx`）／ 今のまま |
| 3 | 横のズーム `zoomX` | **`dayWidthPx`** —— 1 日の幅を、表示の倍率 100 のときの CSS の px でそのまま持つ。隠れた基底（`S-1` × 0.625 ＝ 3.75px/日）が消える。表示の倍率は **`displayScalePercent`** | `horizontalZoomRatio`（基底が隠れる）／ `shownDayCount`（窓の幅で詰まり方が変わる） |
| 4 | 縦のズーム `zoomY` | **2 つに分ける**（1 つの値が 1 未満で「畳む深さ」、1 以上で「大きさ」を言うのは OMPV に反する）—— 大きさは **`verticalZoomRatio`**（1 以上、1 ＝ 既定。予定・実績・名前の字をまとめて伸ばす。特定の形を基準にしない）、深さは **`taskGroupAutoExpandDepth`**（開閉が `auto` のタスクグループを深さ N まで開く。根 ＝ 1、0 ＝ 根だけを閉じて描く、0〜4） | 1 つの `verticalZoomRatio` ／ `planBarHeightPx`（書いた高さと描いた高さが食い違う）／ `taskPlanBarHeightPx`（矩形のグリフが基準になる）／ `taskGroupAutoDepthLimit`（利用者が `…ExpandDepth` を選んだ） |
| 5 | 目盛の字 `rulerFontSizePx`・帯の高さ `rulerHeightPx` | **文書から外す** —— 文字サイズの段から道具が決める（字 ＝ 段の字 × 1.5、帯 ＝ 字 × 3 ＋ 余白 × 3）。設定の面の読むだけの 2 行（表 T-380 の `RN-5`）も除く（CR-851 の指摘 55「今のまま」を覆す）。⚠️ 問うたときの場面は「設定の面で作成者が数を入れられる」と述べたが誤りで、書けるのはファイルを手で直す人か AI だけである —— 外す理由は変わらない | 残して上書きしない（読む人が文字を大きくしても目盛が大きくならない）／ 今のまま（書き手が 2 人） |
| 6 | 文字サイズ `fontSizeStep` の値 | **`small` / `medium` / `large`** | `S` / `M` / `L` ／ 12 / 14 / 16 |
| 7 | 量の接尾辞 | **CR-851 の命名規則 2 に足す** —— `Px`（上の 2）・`Percent`（100 ＝ 等倍・全部）・`Ratio`（既定に掛ける比、1 ＝ 既定）・`Fraction`（1 つのものの中の位置、0 以上 1 未満）。`percentComplete` は MSPDI の名を守る鉄則で例外 | —— |

⭐ 横を px、縦を比で持つ理由: 横には「1 日」という自然な単位が 1 つあり、`zoomX` が動かすのは 1 日の幅だけである。縦には形（矩形・矢印は半分）と字が混ざって 1 つの単位が無いので、既定に対する比で持つ。

## 6. CR-853 で変わるもの

下書きは [`change-request/CR-853-scaling-layers-get-one-strategy.md`](../../change-request/CR-853-scaling-layers-get-one-strategy.md)。⭐ 調整役の裁定（2026-10-25）: 外部契約の行（GRS JSON の鍵・命令・`Agent API` の説明・スキーマの注記）は CR-851 の行の確かめへ渡し、利用者はそこで 1 度だけ見る。CR-853 は振る舞いの行（縦のズームを分けた後のホイール・全体表示・端・LOD、期間を固定した絵が DOM の寸法を読まないこと、箱が表示の倍率に従うこと、`FR-039` の P1）だけを持ち、CR-851 の後に着地する。
