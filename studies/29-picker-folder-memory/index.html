ファイル選択の面が開くフォルダの見本

CR-619 の材料。GRS と同じ File System Access API を、4 通りの渡し方で呼ぶ。 どのボタンも何も書かない（保存の面は「キャンセル」で閉じてよい）。このページは何も覚えない（localStorage・IndexedDB を使わない）。

試し方（file:// で開いて行う）

  1. このファイルをダブルクリックで開く（GRS と同じ file://）。
  2. ある行の「開く」を押し、既定とは違うフォルダのファイルを 1 つ選ぶ。
  3. 同じ行の「開く」をもう一度押す —— 前に選んだフォルダで開くか？（同じ起動の中）
  4. 同じ行の「保存」を押す —— 同じフォルダで開くか？（開くと保存でフォルダを共にするか）
  5. ページを再読み込み（F5）してから、同じ行の「開く」を押す —— まだそのフォルダか？（起動をまたぐ）
  6. ブラウザを閉じて開き直し、もう一度このファイルを開いて同じ行を押す。

4 通りの渡し方

行渡すものいまの GRS との関係押す
A何も渡さない（開く: { multiple: false }、保存: { suggestedName }） いまの GRS と同じ（file-system-access-file-store.ts）
Bid: "grs-document"（開くと保存で同じ id） ブラウザが id ごとにフォルダを覚える。GRS は何も覚えない
Cid: "grs-open" と id: "grs-save"（開くと保存で別の id） 目的ごとに別のフォルダ
DstartIn: 同じ起動で最後に選んだファイルの取っ手（メモリだけ） GRS が上書きのためにすでにメモリに持つ取っ手を使う。再読み込みで消える

記録

選んだファイルの名だけを出す（ブラウザはフォルダの場所を頁に渡さないので、フォルダは目で確かめる）。
