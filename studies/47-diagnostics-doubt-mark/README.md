## 推奨: A

1. 裁定（`JDG-1739`）の字のとおりである —— 「親の `Task` のマーカーに、疑義と分かる印を出す（表 T-315 に状態を足す）」。
2. 1 つの `Task` の印は 1 つのまま（`FR-133`）。レポートの絵（表 T-347 の `DT-1`）・ポインタを止めたときの説明（表 T-348）・当たり判定（表 T-023d の `GR-23`）がマーカーのものをそのまま使い、新しい置き場の規則も当たり判定も要らない（`EZ-6` は「別の当たり判定を起こさない」）。

4. 弱みは、拡大した画面で印と凹みが離れることである。利用者が離れすぎと感じたら、B を A に足す（`CR-716` の問 2）。

## 記号: `≠`（推奨）と `?`

`?` は 表 T-315 の `DG-1`（信用できない・要修正）と同じ形である。同じ形にすると、`DG-1` の条件（表 T-310 の矛盾など）に `VS-6` を足すのと同じになり、優先順 1 位として `DG-3` の `!!` を消す —— この見本の文書では、2 稼働日外れる 6 つの「連携」の親（uid 125・129・133・137・141・145）が `!!` を持つので、ボトルネックへの掘り下げ（`FR-133`）の入口が消える。`≠` は「親と配下が合わない」を形で言い、優先順を `DG-3` の下に置ける。地は `DG-1` と同じ紫（`S-389`）とし、「値を確かめよ」の仲間であることを色で、違いを形で言う（`FR-133` の「色だけに頼らない」）。
