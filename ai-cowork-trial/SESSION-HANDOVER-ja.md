## 5. 落とし穴（前セッションで実際に踏んだ）

| 罠 | 対処 |
|---|---|
| **bash の `node -e "..."` 内でバッククォートが command substitution される** | 置換スクリプトは `cat > /tmp/x.mjs <<'SCRIPT'` のヒアドキュメント（**クォート付き区切り**）で書いて `node /tmp/x.mjs` |
| **Write ツールで `<` と書くと実体化して `<` になる** | プレースホルダを書いてから node で置換する |
| 複数行の置換が謎に MISS する | 行番号レンジで `splice` するほうが確実 |
| **Mermaid は壊れても静かに表示されないだけ** | `@playwright/test`（devDependencies に既存）＋ `https://esm.sh/mermaid@11` で `mermaid.parse()` を通してから確定する |
| 日本語をシェル引数で渡すと Windows で文字化け | ファイル経由で渡す |

## 6. 実測済みの事実（**測り直さなくてよい**。全数は `OPEN-ITEMS-ja.md` §0）

- `file://` から**兄弟ファイルの `fetch`/`XHR` は両方とも拒否される**（2 エンジンで一致）
  → URL パラメータで文書を読ませる方式は成立しない。**起動時注入だけが投入経路**
- `file://` でも**ファイル保存の仕組みは使える**。同じハンドルへの 2 回目以降は**ダイアログが出ない**。
  ハンドルはリロードをまたいで残るが、**権限は `prompt` に戻り 1 クリックが要る**（「常に許可」が無い）
- **ダウンロードは上書きされず ` (1)` が増える** → 「編集中のファイル」をダウンロードで実現しない
- **`file://` のページは外から操作できる**（Playwright で実証）。AI は `file://` のまま GRS を起動し、
  API を呼び、画面を確認できる
- **注入時の `<` エスケープは必須**。対照実験で、省くと JSON が壊れるうえ**内容が本文へ漏れた**
  → **セキュリティ対策**である
- 将棋 1 セッション: `revision` 104・楽観ロックが **6 回発火**・AI の自己訂正 **7 回**・
  会話量の比 **人間 1 : AI 84**
